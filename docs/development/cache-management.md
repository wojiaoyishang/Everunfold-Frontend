# 节点状态

在「设置 → 节点状态」（`/admin/settings/nodes`）可查看所有节点的站点与主题发布回执。「节点缓存」默认显示当前前端节点，也可切换至其他节点。公开内容、站点设置和节点策略分别显示本机已验证版本、磁盘文件数和逻辑字节数。内容磁盘剩余空间来自文件系统。磁盘版本和后端确认版本可分别核对。

「部署配置」显示当前前端实例的节点标识、浏览器后端地址、公开站点地址、设置副本和快照配置。内容由服务器配置文件维护。切换「节点缓存」所选节点后，部署配置仍显示当前前端实例的信息。

- 在「节点策略」可调整动态数据刷新间隔、单次请求超时、失败后重试间隔和浏览量合并窗口。表单与磁盘状态共用节点选择。切换节点时保留各自草稿，保存只提交所选节点。发生版本冲突时，可撤销该节点的草稿并载入最新版本。
- **重新同步**：让后端重发所选节点的单项或全部副本。已排队与节点确认分别显示。同版本完整重发可恢复丢失文件；同版本不同内容仍受不可变写入保护，损坏文件需要运维修复。如果首次生成公开内容副本，或部署变化使派生设置确实变了，新的全站版本仍会发给所有启用节点。
- **清理旧版本**：每项每次最多删除 200 个旧文件。当前副本、内容版本意图、来源绑定、其他来源与节点、媒体及 `.next` 不受影响。当前副本缺失或损坏时跳过该项。文件大小是逻辑字节数，实际释放的文件系统空间可能不同。清理失败或超时后先刷新状态。

浏览器沿用站点会话。读取需要 `settings:read`。保存策略、重发和清理需要 `settings:write`，并检查浏览器 Origin/CSRF。操作有设置审计。后端内部访问使用接收器绑定、真实来源 IP 和凭据。清理还校验节点 ID 和来源。未升级的接收器会显示升级提示。

部署时先显式执行 `alembic -c migrations/alembic.ini upgrade head`，再更新 API、Worker、Scheduler、前端和接收器。接收器不对公网暴露。仅安装后台页面不会改变缓存大小；此功能没有定时清理，也不会刷新已打开的页面或清理外部 CDN。

文章发布、重新发布、撤回和定时开放，以及公开页面、翻译、分类标签、评论、站点设置和节点策略的版本变化，由后端登记事件供可信插件订阅。普通草稿保存不会发出发布事件。
