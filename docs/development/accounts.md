# 账号中心与用户管理

版本：accounts-runtime-10，2026-11-10。基础检查见[验收记录](../handoff/accounts-verification.md)，入口与头像动效见[最新验收](../handoff/header-account-entry-verification.md)；身份预设见[本轮验收](../handoff/user-presets-verification.md)，协议见[API Key接入指南](api-key-applications.md)。

## 使用入口

| 页面 | 使用者及功能 |
| --- | --- |
| `/account` | 所有登录用户：个人资料、独立头像库、密码、会话和自己的API Key |
| `/admin/users` | 有用户管理权限的账号：搜索、新建、编辑、启停、授权、重置密码与撤销Key；顶部可调整头像限制；管理员另有身份预设入口 |
| `/admin/users/presets` | 管理员新增、修改、删除成员身份预设；有用户管理权限的委托成员可只读查看自身授权范围内的预设 |
| `/admin/settings/api-keys` | 有应用管理权限的账号：接入应用、权限目录、签名凭据与回调记录 |

前台右上角“云端同步”面板及后台头像进入同一账号中心，侧栏不再单列账号入口。已登录且头像可用时，顶栏先打钩再显示头像，点击仍打开同一云端/账号面板；匿名用户从这里登录。后台接入菜单为“应用程序接入”，原路径保持。公开作者介绍和私有资料分开；邮箱、会话、授权、Key和应用凭据不进入公开快照。私有页面身份确认后从浏览器请求资料，SSR仅匿名壳，`private/no-store`、禁止索引，公开数据源故障不阻断登录和账号入口。

## 资料与账号安全

用户名创建后固定；显示名、邮箱、简介、网站和界面偏好可修改。邮箱明确未验证，不能用于登录或找回密码。语言选项来自站点目录，内容语言数量不限于中英文；当前程序包提供中文/英文，其他语言使用配置的界面回退。

资料按期待版本和稳定操作ID保存。409时保留输入，选择“读取最新资料”，核对后“保留输入并更新基线”：未改字段使用最新值，本地改过的字段保留；再次保存才写入。离开未保存表单需确认，取消离开保留输入。多个标签页不会以最后一次请求无条件覆盖资料。

管理员创建用户并交付临时密码；首次登录必须先在账号中心修改。新密码至少12个字符。用户改密需要当前密码，退出其他会话并续签本机；默认同时永久撤销已有Key，也可明确保留。管理员重置会退出目标账号全部会话、永久废止旧Key，并要求下次改密。账号停用后旧Key不会因重新启用而复活。会话页可退出其他设备，不泄漏会话token。

角色、授权、启停、重置、Key签发、应用设置/凭据轮换等敏感操作需操作人的当前密码，并记录审计。最后一个有效管理员不能停用或降级，服务端事务保护并发竞争。普通用户默认没有发文或完整媒体库权限。当前不提供公开注册、邀请、邮箱验证/找回或2FA。

## 受限个人头像库

个人头像不通过完整媒体库页面管理，不要求`media:read/upload`。只展示本账号通过头像入口上传的图片；管理员编辑目标用户时，也只能选择目标本人图库中的图片。自填URL不能冒充拥有关系；未改动的旧头像地址在编辑其他资料时保留。

用户确认以下初值，管理员在“用户管理 → 头像上传限制”调整，使用版本校验与用户管理权限，保存前展示影响范围提示，不再要求密码（ADR0075）；调小限制不删除已有图片。

| 项目 | 初值 |
| --- | --- |
| 类型 | 静态JPG、PNG、WebP |
| 单文件 | 2 MiB（2,097,152字节） |
| 输出最长边 | 512px，不放大小图 |
| 每人每日接纳次数 | 10次，UTC零点重置 |
| 每人保留数量 | 20张 |

后端按实际格式验证，拒绝动态图片、SVG及超过1600万像素的源图，纠正EXIF方向、剥离元数据并重编码为WebP。类型、大小和数量均由后端执行。上传复用统一多文件队列、真实进度/降级、稳定ID、停止/重试与失败隔离；相同请求ID重试不重复扣次数。跨API进程争抢最后一个名额只能成功一次。

被接纳的持久预留计入当日次数；存储失败可原ID重试或移除预留。移除不返还次数，当前头像须先更换或清除。图库移除仅解除该用户引用，同哈希原件可能被他人使用，底层回收由管理员统一媒体生命周期处理。个人图库限制管理可见范围，图片仍用现有公开媒体分发，不能当作私密相册。

## 身份预设

从“用户管理 → 身份预设”打开独立配置页，初始提供可修改、可删除的“编辑”和“审稿人”。左侧选择预设，右侧编辑名称、说明及各应用权限，保存/删除须填写“当前管理员密码”。切换或离开未保存表单会确认；其他页面更新后刷新目录保留本地输入，显式“读取最新预设”才替换。

| 初始预设 | 默认权限 |
| --- | --- |
| 编辑 | 读取/编辑全部内容，读取/上传媒体；不能直接发布或撤回 |
| 审稿人 | 读取/编辑/直接发布与撤回全部内容，读取媒体；编辑能力用于现有审核工作流 |

这些是权限模板，不替代受保护的`admin/user`基础角色。新建/编辑成员时选择“身份预设”，预览后保存；也可微调权限，此时自动转为“自定义权限”。服务端在同一用户保存事务中按ID和期待修订读取当前预设并复制权限，不信任客户端预览的grants。已过期或已删除的选择会拒绝且保留输入，刷新后重新选择；管理员角色不能套用成员预设。委托管理者只能读取/应用不超过自身当前授权的模板，不能维护全站预设。

列表和账号资料显示应用时的身份名称快照。**修改、重命名或删除预设不会自动更改既有用户及其Key**；用户仍使用自身role/grants鉴权。需要跟随新版时，在用户编辑页刷新并重新选择该预设后保存。仅修改个人资料保留来源快照；显式选择自定义或手动更改角色/权限则清除来源标记。实际权限改变沿用既有会话、Key及WS失效流程，不因显示名字改变就扩权。

预设名称和说明属于管理员配置内容，切换界面语言保持原文；功能文案、帮助和稳定错误码提供中英界面。

## 细分授权与Key

管理员可授予稳定能力代码及支持的资源范围：`own`为创建者本人，`all`为全部。内容读取、编辑、发布分别授权，没有发布权限不能通过草稿或协作接口变相发布。媒体库、设置和短代码等全局资源不伪造“仅本人”范围。翻译组包含其他创建者时，本人范围拒绝整组操作。

前端按授权收起菜单和写操作，后端对每条路径、查询结果与目标资源检查；直接输入编辑地址也不能越权。HTTP、协作票据、源码租约及已连接WS共用当前身份，持续复核撤销/降权。已打开的本机源文仍可按既有离线流程导出。

个人Key绑定一个接入应用与audience，明确选择权限、范围、到期时间并以当前密码生成。有效能力取“用户当前授权 ∩ Key显式授权 ∩ 应用权限目录”。管理员Key不会自动继承管理员角色，新增能力不扩大旧Key；用户/应用管理能力不能发给Key。账号无可用权限时须先由管理员授权。

Key只在生成成功当次显示，数据库仅存摘要。相同操作重试只返回无密钥回执，丢失时应撤销后重新生成。管理员可查看名称、范围、状态并撤销，不能读取已有明文。业务使用`Authorization: Bearer ...`；资料/用户/Key管理本身坚持Cookie Session+CSRF。无效Bearer不会降级借用Cookie。

## 接入其他项目

1. 管理员从“应用程序接入”新建应用。调用博客选`audience=everunfold`；保护独立子项目选该项目自身audience并登记能力目录。
2. 保存当次提供的查询和回调两份独立签名材料，交给子项目服务端。资料页为此应用创建用户Key；两类密钥不互换用途。
3. 子项目签名调用主项目校验接口并验证签名响应。读取短缓存默认最多30秒、不能滑动续期；写入每次在线校验。
4. 部署放行回调来源后保存回调URL。使用“测试回调”“重新同步”“重试失败投递”，区分已入队、已接收、已应用，不能把HTTP200视为缓存已更新。

签名主密钥由`auth.application_master_key_env`引用环境，API/Worker使用同一个稳定值；`auth.callback_allowed_origins`明确放行回调来源。查询/回调独立轮换，新代次立即生效，须更新子项目材料再同步。无需统一登录服务；后端`examples/api-key-client.mjs`为Node22参考，多实例子项目必须共享失效版本或关闭读缓存，详情见接入指南。

## 部署与契约

后端显式迁移至`0022_user_permission_presets`，启动不自动迁移。使用accounts1.4.0、auth0.2.0、content-admin1.9.0及api-key-protocol1.0.0；前端生成文件锁定后端已提交来源，不手改Schema或客户端。先迁移、部署API/Worker，再部署匹配前端。当前容器按原要求使用HTTP和`0.0.0.0`，设备地址和凭据只在忽略的运行配置中维护。

## API Key的验证码权限

面向博客的Key创建表单增加“阅读免验证码”“评论免验证码”，两项默认不选，只有已获对应权限的用户可签发。站点验证码设置还可禁止豁免及调整每Key阅读侧请求额度；授权并不跳过文章密码或直接公开评论。失效Key不回退匿名，签名查询/Callback仍沿原协议。完整使用与限制见[验证码指南](captcha.md)。


## 前台确认与退出

账号中心的站内离开、资料标签切换和退出均使用项目共享ConfirmDialog；取消保留当前标签与输入，确认后才丢弃并离开。账号中心不再注册浏览器beforeunload原生提示，后台原有保护保留；浏览器系统关闭/刷新不属于可用站内弹窗同步拦截的操作。

前台右上角同步展开面板为登录用户提供“退出登录”。CSRF logout回执成功才更新匿名状态，失败保留身份并提示结果未确认；重试不会手工删Cookie。已确认会话变化通过同页事件与BroadcastChannel发送无凭据失效提示，其他标签向后端重新确认；签出后断网也不再保留旧身份展示。消息不含用户/CSRF，不写浏览器持久存储。检查见[本轮验收](../handoff/comment-submit-verification.md)。

前台同步面板的“进入账号中心”和“退出登录”使用同一backend-account-entry样式：颜色、圆角、尺寸与悬停状态一致，放在8px间距的按钮组中；分隔线在整个账号组下方，面板内边距16px，避免通用弹层6px规则覆盖。
