# 内容运营与拖拽上传

版本：content-operations-2，2026-11-10。对应 [ADR0089](../decisions/0089-content-management-workflows.md)，实际检查见[验收](../handoff/content-operations-verification.md)。

## 列表筛选与快速编辑

文章、说说列表仍按原文聚合语言版本，一组一行。状态包含全部、草稿、已发布、待定时发布、定时失败及回收站；搜索可与作者、分类、标签、修改时间组合，按最近修改、创建、发布时间或标题升降序排列。筛选匹配任一译文，排序按原文行字段；草稿指尚未发布的工作稿，不等于已发布内容的后续编辑。

高级筛选可折叠，保留当前条件数量。查询条件和分页写入当前列表 URL，并按文章/说说分别保存在当前标签页的 sessionStorage；从编辑器返回时恢复。切换筛选或刷新版本后清空勾选，避免继续操作旧结果。这里不缓存正文、凭据或阅读验证。

每行完整编辑入口保留铅笔，旁边的快速编辑只调整标题、摘要（仅文章）、分类、标签、置顶及是否允许评论。只提交真正修改的字段，不提交正文，不自动发布。保存时同时核对草稿修订与协作持久水位；其他人修改后会保留输入并阻止旧版本覆盖。可选择「读取最新版本并保留修改」，核对后再保存，不自动强制覆盖。

## 批量操作与语言范围

勾选本页条目，使用批量编辑或移至回收站；回收站提供恢复。确认窗口列出实际内容名称、语言及修订号，并区分组选中数量与本次语言版本数量。

- 编辑默认仅原文，可选择全部语言或指定语言；支持分类/标签添加、移除指定项、替换全部，以及置顶和评论开关。不提供批量覆盖标题或正文。
- 回收/恢复默认全部语言版本。只回收译文时，原文仍作为回收站中的组入口，明确标记「有回收的译文」，不会把原文也恢复或回收。
- 回收原文必须明确包含该组全部未回收语言版本。已发布内容要求发布权限，并沿原可靠投递撤回；恢复只成为草稿，不自动重新发布。
- 每次最多 50 个具体内容 ID，不是 50 组。所有项先校验权限、修订、协作水位、合并锁和状态，再同事务应用。任一失败整批不写入；重试保持原操作 ID，改变输入则使用新操作 ID。
- 编辑仅修改当前工作稿，已发布内容及已冻结的定时发布快照保持；需要更新前台时仍到编辑器确认发布。

## 分类与标签

后台「分类与标签」提供查询、新建、改名、分类层级、合并与删除，显示已发布和工作稿引用数量。需要全部内容的读取/修改权限。草稿中新输入的分类/标签也进入目录，无须先发布。

修改前展示工作稿、已发布、定时版本、直接子分类的影响数量。确认时再次核对目录修订、实时草稿水位和影响摘要；范围变化时要求重新检查。合并/改名同步更新工作稿与当前公开关联，不改正文；公开变更继续通过 Outbox 投递。分类删除只移除关联，子分类上移一级，不删除内容。

ID 与 slug 保持稳定，旧名称是内部身份索引：改名/合并后，旧草稿或离线输入再次写入会解析为当前名称；删除后的旧名称保留墓碑，不会因重新保存旧稿而复活。历史版本和定时冻结快照不被覆写，未来发布时进行规范化。这里不建立页面 URL 别名或重定向。分类层级不允许循环；保留名称不可被另一分类重新占用。

## 后端接口与存储

| 接口 | 主要参数与行为 |
| --- | --- |
| POST /v1/admin/content/query | 原分页/分组参数，加 author_id/category/tag/updated_from/updated_to/order_by/direction；日期要求带时区 |
| POST /v1/admin/content/batch | operation_id、action、items[{id,expected_revision,expected_seq}]、可选 patch；最多50个唯一ID |
| POST /v1/admin/content/taxonomy/query | kind、search、page、page_size，附同类可选父级/合并目标目录 |
| POST /v1/admin/content/taxonomy/preview | action、kind、id、expected_revision、改名/层级或目标与目标修订，返回影响和 token |
| POST /v1/admin/content/taxonomy/save | 同一命令加确认时的 impact_token；创建无需影响确认 |

元数据差异写入已有 Y.Doc，保留正文、稳定块 ID、协作 epoch；即便仅删除文本，也会产生可传递的删除更新。持久更新、检查点、审计与幂等回执同事务，在线编辑器沿原协作水位恢复更新。合并锁期间拒绝修改，API Key 与会话仍按当前权限判定；浏览器写入要求 CSRF。

0030_taxonomy 增加目录修订、退休标志和名称索引；0031_draft_terms 索引已有草稿中的自由分类标签，不改正文或历史。迁移必须显式执行，服务不自动升级。content-admin 1.16.0、collaboration 2.5.0；前端锁定后端契约提交及 SHA，派生客户端只在忽略的 var/cache 生成。

## 验证码解锁后的评论

页面解锁响应使用独立 UnlockedManagedPage，附带已审核留言；公开 PublicManagedPage 不含这些私有字段。正文、评论和阅读回执只保留在解锁组件内存，接口 no-store。评论提交仍待审核，阅读验证不授予发布权。

评论点赞读写可附 X-Everunfold-Read-Target 与 X-Everunfold-Read-Receipt；二者成对发送，不放入 URL。后端复核目标、当前访问策略、真实来源、API Key 身份（如有）以及 Redis 中的30分钟回执；回执仅授权指定目标的已审核评论。无凭证不暴露受保护留言，错误目标或失效凭证拒绝操作；前端提示刷新并重新解锁。撤回、停用或策略变化仍即时执行原守卫。captcha 1.2.0、comment-likes 0.2.0；浏览器消费后端声明的头名称。

## 统一拖拽上传

媒体库、图标库、字体库、头像上传区域、Markdown/HTML 编辑区及共享上传按钮均支持拖入文件。鼠标进入有主题色提示，松手后交给原多文件上传队列，保留逐文件校验、进度、失败重试和现有授权。选择文件按钮仍可用；手机使用文件选择器。

编辑器拖入图片走原图片占位/上传/插入逻辑；不支持的格式单独失败，不阻止其他合法文件。媒体库仍支持其已允许的图片、视频及附件；头像只能使用本人受限图库的格式、体积和配额，拖放不绕过限制。一次只入队一次，拖到区域内的上传按钮不会同时触发父区域。文本、正文块拖动保持原行为。文件夹暂不递归上传，给出提示。

开发入口：`src/core/media/use-file-drop.ts` 统一事件识别，主题共享 `FileDropZone` 提供高亮和提示，`FilePicker` 提供点选及按钮拖放。新上传入口复用这些组件并把文件传给已有 queue.add，不另写传输。包含 CodeMirror/Tiptap 等有原生文件 drop 行为的区域使用 `capture`，阻止重复插入；只对文件拖动拦截，不接管文字拖动。

## 后台标签词云（2026-11-10）

后台 `/admin/taxonomies` 的标签页默认词云，可切换原分页列表。复用私有目录返回的完整parents集合，不只取当前20条；搜索同时过滤词云。字号按published_count，标题提示已发布/工作稿各自数量。点击词打开原编辑窗口；只读用户点击进入该标签的列表筛选，不因此获得写权限。分类页继续使用列表。

词云稳定选择已发布引用次数最多的前100个标签，自适应字号、水平/竖向/斜向旋转与剩余空间密排；词少时按画布放大，词多时缩小，仍放不下的显示实际数量并允许切列表。使用真实字体宽度和旋转包围盒，尺寸/字体变化重新计算，不将密排当成数据总数。公用layoutWords默认仍为公开词云的80词/无旋转，只有后台启用dense/fill。主题useWordCloud封装测量，公开与后台复用。

搜索沿用共享admin-search的图标、输入高度/内边距和焦点样式，手机合理换行。该功能无后端接口、迁移或数据写入变更；实际视觉/边界验收见[本轮记录](../handoff/admin-cloud-manual-verification.md)。
