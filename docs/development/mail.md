# 邮件配置与测试发送

版本：mail-4；2026-11-10。配置与主动测试发件已实现，业务通知、自动重试和邮件提供方插件尚未实现。真实服务商参数由管理员填写，开发验收不写主站 SMTP 配置，也不向外部邮箱发送。

## 使用入口

后台「设置 → 邮件配置」。桌面悬停设置显示浮层，点击父级固定展开；当前所属父级不再弹浮层。手机使用点击手风琴。主题设置独立显示。读取配置需要 `settings:read`；修改、测试与读取测试结果需要 `settings:write`，沿用会话、CSRF 和 API Key 权限约束。

| 配置 | 初值或规则 |
| --- | --- |
| 允许邮件发送 | 关闭；用于后续自动通知，关闭时仍可主动测试 |
| SMTP 服务器 | 空；主机名或 IP，不带协议、端口或账号 |
| 端口 | 587；允许 1–65535，以服务商为准 |
| 连接加密 | STARTTLS；也可选直接 SSL/TLS 或不加密 |
| 连接超时 | 15 秒；允许 3–120 秒 |
| 服务器需要认证 | 开启；关闭时可使用无需认证的中继 |
| 用户名、密码或授权码 | 空；密码只写，读取仅返回是否已配置 |
| 发件邮箱、发件人名称 | 空；邮箱填写单一地址 |
| 回复邮箱 | 可选；留空使用发件邮箱 |

启用发送时，服务器、发件邮箱及认证所需的用户名和新密码为必填；已有密码可以留空保留。表单依原生 required 显示红色星号，端口、超时与测试收件邮箱也有标记。关闭发送允许保存未完成配置，只有完整、已保存的配置才能测试。密码明确清除须保存才生效；关闭认证不会自动删除凭据。

保存只更新私有设置和审计，不连接 SMTP、不生成邮件任务、不触发前台同步。未保存离开使用项目弹窗，并发冲突保留输入；凭据不写入浏览器持久存储或公开快照。配置区和测试区是两个独立表单，保存栏位于页面底部，通过 form 关联配置表单。

## 接口与存储

settings 契约 `1.21.0`，前端锁定后端提交与摘要后生成客户端：

| 方法与路径 | 操作 | 参数 |
| --- | --- | --- |
| GET `/v1/admin/settings/mail` | readMailSettings | 无 |
| PATCH `/v1/admin/settings/mail` | saveMailSettings | expected_revision、value、可选只写 password、clear_password |
| POST `/v1/admin/settings/mail/test` | sendTestMail | request_id(UUID)、expected_revision、recipient |
| POST `/v1/admin/settings/mail/test/status` | readTestMail | id(UUID) |

读取配置只返回 revision、value、password_configured。保存锁定站点设置行，独立修订冲突为409，字段错误422；同一事务写 `_mail_private` 与脱敏审计，公开投影不包含该私有段。密码目前为后端私有数据库字段，**未新增字段加密**。

测试请求返回 id、recipient、status、error、created_at、finished_at。结果只允许发起者读取；已清理或其他用户记录返回404。服务端原始错误、密码及邮件内容不作为公开错误返回。SMTP 认证、TLS、拒收、网络失败分别映射安全错误码。

新增 `0033_mail_test` 迁移与 mail_test_deliveries 表，`0034_task_progress` 保存统一进度事件，显式部署：`uv run --locked alembic -c migrations/alembic.ini upgrade head`，不在 API 启动时自动建表。记录保存发起人、配置修订、目标邮箱、状态和租约，完成记录保留30天；数据库访问与备份按包含私人邮箱/凭据的数据管理。

## Scheduler 与 Worker

管理员明确提交才创建 queued 记录和审计。每位用户每分钟最多5次，超限429；同一 request_id、用户、收件人及配置修订重复提交返回原结果，不再排队。编号复用但参数不同返回409。

Scheduler 的内置 `core.mail-test` 每3秒向 Worker 指派一次扫描；任务不包含密码、正文或目标邮箱。Worker 使用行锁认领一条记录，先提交 sending/租约，再从私有配置获取参数并连接 SMTP。API 与 Scheduler 不执行网络发件。后台运行与任务可查看该计划及执行结果。

- 排队时配置变更：取消本次测试，要求用户基于新配置重新发起。
- 队列等待超过10分钟：failed/queue_timeout。
- SMTP 返回最终接受响应：sent；界面提示“邮件服务器已接收”，不保证收件箱送达。
- 明确拒收或连接失败：failed，显示对应原因。
- DATA 阶段失联、发送租约到期或整体等待超时：unknown，不自动重发。用户先检查邮箱，再主动决定是否新建测试请求。

SMTP 使用 Python 标准库；TLS 使用系统信任验证，不在 STARTTLS 失败后回退明文。网络调用在 Worker 线程中执行，按配置限制命令超时和总等待预算。SMTP 无法证明完全不重复，当前策略优先避免未知结果自动重发，也不宣称消除进程/网络故障的所有不确定性。

浏览器持续使用统一任务监控接口长轮询，不再限制60次；断线退避续读，隐藏暂停/恢复，卸载取消读取。测试任务ID按后端/账号保存在sessionStorage，刷新继续查看同一任务，不再次发信；只保存ID，不保存邮件参数或报文。创建响应丢失时保留原请求编号，“确认请求”复用同一编号。

测试区可直接查看分阶段日志、SMTP命令/响应及测试MIME报文，认证对话整体脱敏。运行与任务的执行记录也能展开同一监控组件；可复用接口、SDK及限制见[统一任务进度](task-progress.md)。原测试结果接口仍保留兼容读取，不再由各页面独立定次轮询。

## TLS主机身份修复（2026-11-10）

SMTP客户端必须在构造时传入保存的host/port，并在基类构造连接读取问候前初始化日志。Python3.12的SMTP.connect不更新构造时保存的主机名；先空主机构造再connect会让STARTTLS和直接SSL的SNI/证书hostname检查收到空值，引发ValueError。23755d9修正此初始化问题，保持系统信任验证和主机名验证。

TLS证书拒绝记录安全verify_code、握手异常只记录类型；超时使用timeout分类，通用transport附安全异常类名，不记录原始异常文本。前端5b30729补超时/本地传输错误说明。真实本地STARTTLS与直接SSL握手、SNI、认证/投递通过，错误hostname和未信任证书均在AUTH/DATA之前拒绝。真实供应商认证和送达仍由管理员主动测试。
