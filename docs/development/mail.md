# 邮件配置与发送路线

版本：mail-1；2026-11-09。本阶段已实现配置持久化，尚未接入发送器。依据用户要求，实际参数由管理员填写，不预填凭据或发送测试邮件。

## 使用入口

后台「系统管理 → 邮件配置」。桌面子菜单可展开/收起，移动端为手风琴；当前子页面自动展开。配置需要 `settings:read`，修改需要 `settings:write`，沿用会话、CSRF 和 API Key 权限约束。

| 配置 | 初值或规则 |
| --- | --- |
| 允许邮件发送 | 关闭；保留配置。本阶段即使开启也没有发送任务 |
| SMTP 服务器 | 空；填写主机名或 IP，不带协议、端口或账号 |
| 端口 | 587；允许 1–65535，以服务商为准 |
| 连接加密 | STARTTLS；也可选直接 SSL/TLS 或不加密 |
| 连接超时 | 15 秒；允许 3–120 秒 |
| 服务器需要认证 | 开启；关闭时可使用无需认证的中继 |
| 用户名、密码或授权码 | 空；密码只写，读取仅返回是否已配置 |
| 发件邮箱、发件人名称 | 空；邮箱填写单一地址，不带显示名称 |
| 回复邮箱 | 可选；发送阶段留空应使用发件邮箱 |

保存前允许保持未完成、未启用的配置；开启发送必须填写服务器、发件邮箱以及认证所需的用户名和密码。关闭认证不会自动删除已有凭据。密码留空表示保留，点击「清除已保存的密码」后仍须保存才生效，可在保存前撤销。关闭发送不清除任何参数。

保存只更新后端私有设置及审计，不访问 SMTP、不生成邮件任务、不触发前台同步。未保存离开使用项目确认窗口；并发冲突保留输入，重新读取前再次确认。表单凭据不写入 localStorage、IndexedDB 或公开设置快照。

## 接口与存储

settings 契约 `1.19.0` 增加 `readMailSettings` 和 `saveMailSettings`，前端按锁定后端提交生成类型/客户端。接口为 `GET/PATCH /v1/admin/settings/mail`，仍使用标准响应外壳及真实 HTTP 状态。

- 读取：`revision`、`value`、`password_configured`；绝不返回原密码。
- 修改：`expected_revision`、`value`、可选只写 `password`、`clear_password`。空密码保留；同时传非空新密码与清除标记拒绝。
- 保存锁定站点设置行、校验独立修订、写入私有 `_mail_private` 和审计，并在一个事务提交。修订冲突返回 409；字段/启用条件错误返回 422。
- 原站点设置保存保留该私有段；公开投影按既有字段模型输出，不包含 SMTP 参数。审计只记录操作、启用状态及密码是否改变。
- 复用已有 JSONB 设置与审计表，无新增迁移。密码目前保存在后端私有数据库字段，**没有额外的字段加密**；数据库备份必须按含凭据的数据管理。此实现不宣称客户端端到端加密。

## 下一阶段规划（尚未实现）

1. **发送基础与测试邮件**：增加后端邮件提供方接口，SMTP 为首个适配器，允许插件登记其他发送提供方。统一服务负责发件规则、模板、语言、限流和幂等；提供方只负责交付。后台测试按钮必须指定收件地址，由用户主动触发，展示真实结果，不能把保存配置当成测试成功。
2. **可靠队列与可观测性**：业务事务写邮件投递记录及 outbox，Worker 在事务外发送，Scheduler 指派到期/重试任务，沿用现有运行管理。队列只携带记录 ID，不带 SMTP 密码；区分待发、发送中、已交付服务商、失败和结果未知。使用退避、重试上限和人工重试，避免宣称 SMTP 能保证完全不重复；密码从后端私有配置获取。关闭开关阻止新增交付，已执行中的外部调用不可撤回。
3. **业务通知**：先做按收件人偏好发送的评论回复通知，再做邮箱验证、密码找回和运行故障告警。账号令牌由鉴权核心管理、短期有效且一次使用；模板按用户语言选择，不给插件接管核心授权。日志及错误信息必须去除凭据、令牌和邮件正文等私有数据。
4. **部署与恢复**：提供邮件积压/失败统计、保留策略及受控清理；随后开展备份恢复和迁移演练。实际供应商的 TLS、超时、拒收及网络中断验证留到发送阶段。

本路线是后续分批实现的安排，不代表当前已提供通知、密码找回、测试邮件、模板编辑、邮件提供方 SDK 或自动投递。
