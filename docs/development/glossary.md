# 术语表与文章按需 Tooltip

版本：glossary-runtime-12，2026-11-10。实现决定见 [ADR0099](../decisions/0099-article-scoped-glossary-tooltips.md)、[ADR0101](../decisions/0101-glossary-rules-and-reader-ui.md)、[ADR0103](../decisions/0103-dynamic-glossary-footnotes.md) 与 [ADR0104](../decisions/0104-localized-navigation-and-glossary-hooks.md)。当前功能属于后端插件 `everunfold.glossary`，文章和正文快照不做术语迁移。

## 管理入口

管理员在「内容 → 术语表」打开 `/admin/glossary`：

- 旧词条默认继续以标题和别名匹配；新词条可独立关闭标题匹配，并配置普通文本或受限正则、逐条启停、区分大小写、ASCII 单词边界和 0~100 优先级。同一语言内的活跃普通文字不能与其他非归档词条重复；正则交集在运行时按优先级处理。
- 别名是独立字段，始终参与正文命中、全局搜索和公开词条展示。`match_rules=null` 与空数组都只表示没有额外规则；普通/正则规则只补充标题和别名之外的特殊匹配方式，正则表达式不会公开。后台「匹配测试」通过后端 `POST /admin/preview` 仅验证不保存。
- 默认 Tooltip 来源为完整术语正文，正文使用与文章相同的安全 Markdown/HTML 区块列表；简短提示摘要可留空，仅在站点提示来源显式设为“简短提示”时使用。
- 新词条默认启用“术语标题本身”匹配规则；标题变更会同步更新该规则。标题和路径片段是必填项，摘要、正文、别名与补充匹配规则均可留空。
- 草稿不进入公开目录和文章匹配；发布后进入；归档后保留记录但不再公开。
- 保存使用 `operation_id` 幂等和 `expected_revision` 冲突保护。冲突时保留当前输入，刷新词条后再合并。
- 公开路径为 `/glossary/{slug}`。路径是稳定公开标识，修改已有词条的 slug 会改变旧链接。

后台采用与其他系统设置一致的布局：页面接入 `admin-settings-page`，编辑区用 `SettingsSection` / `SettingsText` / `admin-settings-field`，目录与状态使用共享的后台按钮、搜索、徽标和空状态。术语正文复用文章 `EditorBody`、`BlockComposer`、`DraftPreview`、格式/代码/公式/媒体工具和统一上传队列；正文预览按钮通过 `SettingsSection` 的头部操作位放在“术语正文”标题右侧。默认 Tooltip 直接渲染正文，简短摘要可选；必要字段由原生 `required` 和共享 CSS 显示单个星号，页面组件不再重复添加。术语页面不应重新用裸标签和浏览器默认控件拼装表单。

站点设置只保留正文关键词识别总开关、每页提示上限和提示来源。文章/说说的编辑设置新增独立的“术语提示”面板，分别保存 `show_glossary_tooltips` 与 `show_glossary_footnotes`；自定义/注册页面也在页面编辑设置中保存同名两项。开关随各自草稿、版本和发布投影保存，无数据库迁移。

术语别名在独立分组使用共享 `TokenField` 维护，不再由匹配规则自动生成。`/glossary` 目录只负责浏览公开词条，不提供独立搜索框；站内全局搜索按标题、摘要和别名检索公开术语，并在“全部内容”结果中展示术语分组。搜索语言列表来自站点已配置语言目录并带旗帜，另保留“所有语言”图标；默认选择当前语言，类型与语言控件保持紧凑间距。

## 后端匹配与缓存边界

文章级接口：

```text
GET /v1/plugins/everunfold.glossary/for-content/{content_id}
```

响应中的 `terms` 是文章实际命中的已发布词条；没有命中时必须是空数组。服务端会检查内容类型、公开状态、语言和正文可见区块。代码、链接和 HTML 标签不参与普通正文匹配。文章正文继续走原公开内容快照，不需要因术语表重新生成文章快照。

新增 `matched_patterns` 返回实际命中的文字、大小写、整词和优先级；兼容字段 `matched_texts` 仍保留。正则使用受限 Python 3.12 语法（最多 160 字符、有限的非嵌套重复、最多 6 处分支/重复、单次重复最多 32），不支持无限重复、断言、反向引用和空宽度匹配。一次仅截取有限数量命中文本。禁止将未验证的原始正则直接发送给浏览器执行。

前端 `loadGlossaryMatches` 的缓存键由 API 地址、内容 ID 和内容修订组成，寿命 5 分钟；命中、未命中以及多个组件同时请求都共享同一个 pending Promise。失败会移除缓存，页面继续可读。不要改成启动时下载整份术语目录再在浏览器匹配，也不要让术语请求阻塞文章首屏。

公开目录接口 `GET /index` 只用于 `/glossary`，不是文章 Tooltip 的批量索引。详情接口 `GET /terms/{slug}` 按当前语言读取。

## 前端交互

内容 HTML 渲染后，前端在普通文本节点中优先按后端返回的 `matched_patterns` 字面文字二次装饰，旧响应回退 `matched_texts`：

- 同一页面最多提示 `site.glossary.max_matches_per_page` 个，默认 20。
- 同起点先比较规则优先级、再比较文字长度，区间不重叠；完整英文单词匹配会检查 ASCII 边界。
- 链接、按钮、代码、公式、脚本、隐藏文本和已有提示节点不装饰。
- Tooltip 支持点击/触屏打开、Enter/空格、Escape 关闭并回到触发词；桌面悬停先停留180ms再打开，定位完成并绘制透明首帧后，以双帧触发320ms淡入、240ms淡出。减少动态偏好下保留160ms纯透明度淡入和120ms淡出，不移动位置。
- 首级 Tooltip 使用紧凑主题卡片：摘要非空时显示摘要；摘要为空时只渲染第一个非空正文区块。完整正文仍通过「查看详情」打开原生 dialog，「打开词条页面」继续进入独立详情页。
- 卡片按实际尺寸选择触发词上方或下方，并限制在视口边界内；内容在卡片内部滚动，操作栏固定在底部。超长标题使用省略号并保留原生 `title`；别名为正文顶部可换行标签，最多展示四个并用 `+N` 汇总其余别名。
- Tooltip、完整说明 dialog 和术语目录卡片均提供进入/退出或入场动画，并遵循减少动态偏好。
- 词条详情页将基础信息与正文收紧到12px间隔，并用主题渐变分隔线区分；“打开词条页面”在 Tooltip 与完整说明层中都使用新窗口，不离开当前阅读位置。
- 完整弹层桌面宽度最多 700px、手机使用底部阅读容器，内部独立滚动，退出动画后关闭；桌面/触屏、Tab/Escape 和焦点恢复须做实页验收。
- 主题共享 `.article-content` 表格样式覆盖文章、说说、术语详情、完整弹层及统一草稿预览。表格默认铺满阅读容器，宽表在局部可聚焦滚动区域内滚动；管理数据列表不继承文章排版。
- 正文后的术语脚注同样在空闲后加载，只列出本页命中项。脚注在 `.article-content` 后、页脚/分享区前，以无序列表显示标题和简要提示；摘要为空时从首个非空富文本区块提取纯文本。标题和提示保持单行并使用省略号，点击进入新窗口的词条页。脚注与 Tooltip 共用同一文章级 pending请求和5分钟缓存。

关闭 `site.glossary.auto_match` 后不再执行正文关键词增强。总开关开启时，每篇内容/页面再按自己的 Tooltip 和脚注设置决定是否加载；两项均关闭时不对应内容请求匹配。提示的最大值只限制正文内装饰，不删除目录或词条。

## 页面触发钩子

术语编辑页的“页面触发”分组属于当前术语，不在后台单独占据一级入口。每条规则可选择所有公开页面或多达32个指定文章/说说/页面目标，并可设置启用状态和0~100优先级。CSS选择器支持`#id`、类、属性、后代和组合选择器；拒绝伪元素、`html/body/*`、危险字符及超长规则。每页最多连接20个元素，指定内容优先于全站规则。

公开页面等待`PagePresentation`就绪后，在空闲时请求只与当前surface、内容/页面ID和语言相关的启用钩子，缓存60秒。MutationObserver对后续生成的元素重新绑定，客户端路由切换清理后重跑。Tooltip与正文关键词提示共用；已有链接/按钮保持原生点击，键盘聚焦和Escape行为相同。

JavaScript挂载是仅管理员可保存的危险模式。它使用共享JavaScript CodeMirror编辑器，限制20KB，并提供`glossary.root`、`glossary.term`、`glossary.select(selector)`、`glossary.mount(element)`；保存区域常驻风险警告。脚本在公开页面主线程运行，不等同于自定义页面iframe沙箱，执行异常只跳过当前钩子。

## 发布与排错

1. 后端按次序显式执行迁移至 `0038_glossary_matching_rules`（包含旧版本 0036、0037），启动 API 后显式同步插件目录；须先在隔离库验证，不能跳过迁移直接部署新 API：

   ```bash
   uv run --locked python -m tools.register_backend_plugins --config config.toml --apply
   ```

2. 保持 Receiver、Worker 和 Scheduler 正常，确认插件状态为已同步；`50389` 表示插件部署清单尚未应用到节点。
3. 访问含术语的文章，等待空闲术语请求；若正文有词但没有提示，检查文章语言、词条是否为发布状态、正文是否在链接/代码/公式中，以及页面大小限制。
4. 访问不含术语的文章，确认接口 `terms` 为空且页面没有 `.glossary-term`；不要用公开 `/glossary` 全量列表填充文章 Tooltip。
5. 若配置为 `popup_source=content` 但没有「完整说明」，检查设置投递是否已应用，以及词条 `body` 是否至少有一个非空块。

## 当前边界

不自动为正文中的每个术语生成永久链接，不跨内联节点拼接被拆开的文字，也不把作者短代码参数当作已验证的可见正文。新增规则时应先补真实 API/浏览器测试，再扩大匹配范围。

后端正则命中的文本仍需浏览器按实际渲染的文本节点寻找同样字面值；同字面值在不同上下文、跨节点拆分或 Unicode 规格化变化时可能产生差异。大词库、高并发和完整读屏测试尚未完成。
