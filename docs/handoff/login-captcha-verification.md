# 登录验证码布局验收

状态：已实现并实际查看。日期：2026-11-10。范围仅为登录页验证码的展示与交互，不改变验证码规则、接口或登录安全边界。

## 调整

- 登录页使用独立的 `login` 展示变体，把验证码图片和输入框合并成一个同行双段控件：共享外框和中间分隔线，图片不再单独浮在一行上方。
- 验证卡桌面高度与用户名/密码输入一致为 50px，手机为 54px；内部图片区域和输入框都撑满同一高度。320px 实测两者 DOM 高度均为 `52.67px`，没有高度错位。
- 刷新操作改为右侧轻量文字按钮，视觉文案为“换一张”，保留“刷新验证码”的无障碍名称。
- 刷新期间继续显示并弱化原图片，覆盖真实加载提示，不再把整段验证码替换成加载文本导致布局跳动；输入框保持原高度并暂时禁用，刷新完成后恢复。
- 验证码错误会同时标记图片容器与输入框，提示仍使用现有语义色；登录提交期间验证码输入和刷新操作一起禁用。
- `dialog` 和普通 `inline` 变体保持原有结构；评论按需验证弹窗仍使用自己的布局。所有变体共享刷新图标旋转和减少动态规则。

## 验证

- 内置浏览器实际查看 1280px 桌面、390px 手机、320px 窄屏；验证图与输入框保持同行等高，320px 下文字可读。
- 320px 视口 `scrollWidth` 与 `clientWidth` 均为 308，无横向溢出；登录卡片和按钮均完整可见。
- 点击刷新后图片、输入框和提示保持原位，新挑战加载完成，输入框恢复可用；按钮悬停/焦点反馈使用现有主题色。
- `npm run check`、隔离生产登录页构建和后台路由检查见本轮最终结果。未使用真实账号提交登录，也未修改验证码服务端配置。
