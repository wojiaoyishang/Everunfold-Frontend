## 实际浏览器

使用 Edge 的浏览器接口，无代码注入到业务页面操作状态：

- 动态状态面板首次/重复打开定位在按钮下方，Escape 关闭；搜索选择框键盘打开与关闭、自选色面板均使用已定位位置，不再显示左上角闪位。后端尚无更新时亦可在水合完成后打开。
- 生产独立 503 页面在后端不可用时仍能开始配对、短暂停留后翻回、重新开始、点击重试。404 页面用 Enter/Space 翻牌，实际完成四组配对；成功消息和尝试次数正确。
- 真实隔离 React 错误边界显示主题 500 卡片，保留导航/侧栏并能玩游戏；根布局 `global-error` 已构建/类型检查，但未另造根布局崩溃浏览器用例。
- 检查默认浅紫、深色蓝色与减少动态（卡片 computed transition 为 0s），最后恢复原先跟随系统、篝火紫、完整动效。
- 浏览器 viewport 覆盖没有生效，因此改用工具自建的 320px iframe 实际检查 CSS 媒体查询：错误页分上下两区，无横向溢出（内容与客户区均 305px，另有原生滚动条）；同一窄框进入首页，状态面板 left=12/right=296，客户区 308px，不越界。不是移动硬件或触摸测试。
- 保存桌面效果于前端忽略目录 `var/qa/error-page-desktop.png`，不提交图片/用户数据。普通错误页与小游戏未观察到运行脚本报错；隔离故意抛错对应的错误日志是预期行为。

## 实际问题与处理

初版尝试在 Proxy 导入 React 服务端渲染器，触发 Next 编译拒绝；已改为构建时生成，最终生产构建通过。生成器初版 `.ts` 被 tsx 视为 CommonJS、不支持顶层 await，改为明确的 `.mts`。浏览器按键直接作用于不可聚焦的 dialog 时未成功，改在触发按钮上验证 Escape，原生关闭正常。视口覆盖/局部截图能力没有生效，改用实际窄框和整页截图，没有把失败操作当作通过。

## 后续复查

1. 正常打开首页，在加载早期点击状态按钮；水合前按钮不可触发，接管后在导航按钮旁展开。重复开关、调整窗口、打开搜索和自选色，确认同样规则。
2. 直接访问一个不存在地址，例如 `/__preview_missing__`，检查主题 404、首页链接与配对卡片。游戏结束/重新开始不请求后端。
3. 修改 `failure/` 的结构、样式或游戏后运行 `npm run failure:generate`，再 `npm run check`；不要直接修改 `src/generated/failure-pages.json`。
4. 需要离线/500 复查时运行上述独立命令。只操作工具端口 3991/3992/8991，输入 `quit` 退出，勿停正在使用的 3000/8001。

没有新增依赖或业务变化，因此未重跑后端数据库测试，也未重做完整缓存/撤回/可靠任务 P0。Safari/Firefox、移动硬件、强制颜色及禁用脚本的浏览器实操未执行；无脚本 404/503 仅验证 HTTP HTML 和可读结构。
