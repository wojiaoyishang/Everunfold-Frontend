## 原主题发现与新设计影响

- `functions.php` 的 `get_post_views`/`set_post_views` 与 `get_header` 钩子提供主题浏览量读取及页面访问自增；元信息优先使用存在的 `pvc_get_post_views` 插件函数，否则读主题值。不能据此假定实际历史统计一定只来自主题 `views`。
- 元信息还包含评论数、日期、分类、字数和预计阅读时间；后三类不需要浏览器每次实时请求。侧栏文章/分类/标签数由 WordPress 公开内容统计生成，也不应等同于流量计数。
- 说说操作模板有点赞总数、基于访客 Cookie 的已点赞外观、评论数量和评论关闭状态；评论模板涉及登录、身份输入、可选验证码和悄悄话。这些明确要求拆开公开总量与访客私有状态，不能复制旧 Cookie 逻辑当正式防重复保障。
- 文章推荐按分类/标签选取，排序可配置；源码含浏览量相关查询与日期/随机选项。当前新前端稳定推荐可继续独立渲染，无需为了恢复外观引入实时推荐服务。
- 在线人数、PV/UV、最新评论小部件不是本轮已证明启用的模块；只记录为可选扩展。高中日记、关于等自定义页面继续不纳入本轮主题/动态能力范围。

## 当前项目边界

前端 `src/core/content/snapshot.ts` 在服务端读取/验证节点 `current.json`，搜索与首页使用同一公开内容来源。元信息中的评论数和侧栏统计来自快照；说说/评论原型互动没有正式持久写入。`presentLegacyContent` 会补 `reaction_count: 0`、`comments_open: true`，生产接入不能拿这些值表示真实统计或权限。

后端在线公开 API 0.1.0 有站点、内容列表/解析、分类标签及 `/v1/contents/{content_id}/comments` 只读分页。`ContentSummary` 有 `comment_count`，没有浏览量；`PublicComment` 没有评论计数版本/增量游标。展示草案 0.2.0-preview.1 有点赞数与访问状态字段，但不是上线的统计或写入接口。

当前没有浏览器动态协调层、正式浏览量记账、个人状态接口或节点全链路同步证明。新增设计不能以已有健康接口、手动快照导出或前端本页演示冒充这些能力。
