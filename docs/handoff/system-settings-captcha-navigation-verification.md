# 系统设置归并与分组快速导航验收

版本：system-settings-captcha-navigation-verification-2；2026-11-11（Asia/Shanghai）。对应 [ADR0106](../decisions/0106-system-settings-captcha-and-grouped-navigation.md)。

## 检查范围

- 验证码提供方、登录/阅读/评论规则和 API Key 设置完整显示在系统设置页。
- 左侧导航只有“系统设置”，没有独立“验证码设置”；设置组仍为直属入口。
- 设置组顺序固定为插件管理、站点设置、邮件配置、系统设置、运行与任务、应用程序接入。
- 右侧快速导航按“节点与发布 / 验证码 / 部署信息”显示一级分组，原有分区为二级链接。
- 旧 `/admin/settings/captcha` 重定向到系统设置验证码分区。
- 验证码保存栏位于部署配置之后，不再悬停或停靠在部署配置标题上方。
- 桌面、390px、无写入、脚本错误和现有检查。

## 自动化与构建

- `npm run check`：ESLint、Next.js 类型生成/TypeScript、插件类型、Prettier 和359项测试全部通过。
- `npm run verify:admin`：隔离生产构建、后台私有入口、后端不可用/无公开缓存、主题与公开读取矩阵通过。
- 后台注册测试额外固定独立验证码入口不从左侧导航出现，兼容页面路由仍可识别。

## 实页结果

使用已登录会话的真实后台数据和当前开发组件，在1440px检查：

- 快速导航一级标题顺序为“节点与发布”“验证码”“部署信息”；二级链接顺序为“节点策略”“站点与主题发布”“验证方式”“登录验证”“阅读验证”“评论验证”“API Key 请求”“部署配置”。
- 左侧“设置”组实际显示六个直属入口，顺序为插件管理、站点设置、邮件配置、系统设置、运行与任务、应用程序接入；独立验证码入口不存在。
- 点击“评论验证”后目标可见，当前二级链接与所属分组同时高亮；原有滚动高亮继续工作。
- 访问旧验证码地址后 URL 变为 `/admin/settings/system#captcha-provider`，页面定位并高亮“验证方式”；异步验证码面板挂载前后的首次 hash 恢复已修正。
- 部署配置之后才是验证码保存栏；滚动到底部时按钮保持在页面底栏位置，不再停靠在“部署配置”标题之前。
- 390px 隐藏右侧目录，保留原单栏表单和保存栏；页面宽度不超过视口。
- 整轮页面错误0，验证码或设置写请求0；没有保存、撤销或改变真实设置。

## 范围与限制

仅改变前端后台信息架构、分区目录和保存栏位置；验证码提供方、规则含义、接口、权限、修订和数据库不变。没有覆盖读屏器、跨浏览器全矩阵或极长自定义分组压力；手机端仍不提供目录快捷跳转。
