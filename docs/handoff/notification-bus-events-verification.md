# 消息总线业务事件验收

版本：notification-bus-events-verification-1。日期：2026-11-11。

## 交付范围

- 新增 `content.scheduled_published`、`content.schedule_failed` 和 `settings.delivery_failed` 三个业务事件；评论待审核继续使用 `comment.pending_review`。
- 三个新事件均提供中英文默认站内/邮件模板、变量目录、HTML 卡片与安全纯文本回退。
- 计划发布事件在内容发布结果、计划清理、审计和通知事件同一事务提交。成功去重键包含草稿、排期运行与事件类型，失败同样按一次排期运行去重。
- 设置/内容快照投递只在达到最大尝试次数后发布一次最终失败；中间网络重试不生成通知事件。
- 后台沿用统一通知策略、模板、平台与投递页面；事件没有启用路由时不投递，接收人和邮件发信配置不由业务模块决定。
- 模板变量填充补充计划时间、失败代码、节点和资源示例，切换事件后安全预览不再空白。

## 实页验收

- 真实后台策略页显示评论待审核、定时发布成功、定时发布失败和站点同步失败四个事件；新增事件在没有启用规则时明确显示“尚未通知任何人”。
- 通知模板切换三个新事件后，邮件 HTML 可视化保留变量占位符，安全预览使用事件示例值显示标题、计划时间、错误代码、节点与资源；英文模板回退及示例填充正常。

- 重启六个组件后四端口监听 `0.0.0.0`，API、代理健康检查和后台页面均返回 HTTP 200。

## 边界

- 不发送真实外部邮件；验收使用开发库与浏览器请求夹具。
- 新事件只进入统一事件目录；需要站内或邮件投递时仍需在通知策略中添加接收规则。成功发布默认不强制通知。
- 运行任务连续失败、待审核积压、译文待核对等摘要事件尚未实现。
- 账号注册、找回密码、邮箱验证等账号操作不进入本轮业务事件。
