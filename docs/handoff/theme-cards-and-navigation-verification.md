## 发现与纠正

初次图片使用新/themes路径，被公开路由守卫返回404；改为既有/reference静态空间并补生产HTTP检查，没有把占位或404当作图片加载成功。

开发重启后，实际出现持续Turbopack entry restart与整页刷新，包含未改设置的页面。普通重启、换直接入口、隔离元数据处理均不能消除。按本机Next 16.4.3捆绑文档关闭experimental.turbopackFileSystemCacheForDev后稳定；保留进程内热更新和生产构建缓存，没有删除.next、业务缓存或用户数据。现象与dev磁盘缓存复用相关为当前实例推断，未声称找到上游通用根因；随后完整检查、生产流程及真实主题切换通过。

调试期间记录过Router action dispatched before initialization及旧HMR chunk加载两次客户端错误；清洁会话复核单独记录，不把历史错误隐去。部分脚本使用错误主题属性、没有等待图片失败完成、混淆首项与全部图片选择器，均按真实DOM和异步完成状态重跑；超时不计作产品成功。无全浏览器矩阵或长期负载结论。
