## 内置浏览器实测

1. 行号原有额外16px顶部 padding、不同字号破坏测量；现共用14px/24.5px指标。两种编辑器可见行的行框顶部差 **0px**。320px 中，折成49px的中文/HTML行仍为0px差，后续行号也不漂移。
2. 每个组件接入后立即检查。工具栏/插入菜单、搜索面板和命令封装分开；自定义段落选择、菜单位置/退出、查找高亮/计数、中文替换、Escape/Enter与输入焦点均验证。初次搜索只有计数而无高亮，已改为共享可见区高亮扩展，没有用隐藏假面板绕过。
3. 两个实际页面打开原生开发草稿94b76ebe-94f8-4f72-ac87-c9f14234abd8。A页 Markdown 选区加粗，B页 HTML 快捷键斜体；跨页同步后，A撤销只移除自己的格式，保留B的格式；B再撤销恢复。搜索全部替换可被另一页收到，且能一次撤销。
4. Markdown 表格插入后在统一安全预览中出现真实 table，撤销后恢复。HTML 输入 <di 出现自定义主题的补全列表，Enter选中div、输入 > 后自动闭合；测试内容已撤销。
5. 去掉固定最小高度后，桌面5行 Markdown **162.5px**、3行 HTML **113.5px**，内容与滚动容器同高；320px折行后分别187px/138px。加入30行测试后，内容897.5px，滚动容器上限 **540px**；撤销后自然缩回。没有为展示添加假空行。
6. 实际 Ctrl+S 保存输入、Ctrl+Shift+S 保存恢复后的原内容，出现“草稿已保存”，仍为草稿。保存结束后 activeElement 回到原正文，contenteditable=true，光标仍在原位置；没有触发浏览器保存网页。新输入时旧保存提示消失，恢复原内容后状态正确。
7. 在有未保存的测试内容时打开“插入媒体”，弹窗内按Ctrl+S：选择器保持打开，后台保存按钮仍是“保存草稿”而非处理中；不会越过模态流程保存。未上传、删除或修改任何媒体。
8. 深色与减少动态检查通过，搜索/插入和高亮从后台变量派生；减少动态时搜索展开 transitionDuration=0s。最终恢复跟随系统、舒适间距、轻量动效和默认视口。
9. 320px 最终 document.scrollWidth=308，innerWidth=320。手机工具自然换行、查找控件分行，不出现全页横向溢出。最终新开页面确认持久草稿正文已恢复49/48字符；所有测试输入均已撤销/恢复，未发布，不恢复任何旧WordPress内容。

早期定向检查发现 SearchQuery 返回 Iterator 的 TS 类型问题和聚合 ref 对象的 Hooks lint 错误，分别改为 next() 迭代及解构；焦点的首次单帧恢复早于控件启用，改为父组件在保存结束/控件恢复之后恢复焦点。修正后才记录最终通过结果。
