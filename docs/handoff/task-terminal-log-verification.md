# 共享伪终端日志验收

版本：task-terminal-log-verification-2。日期：2026-11-12。

## 交付范围

- 统一任务日志组件改为深色伪终端面板，带窗口标识、连接状态、事件序号、时间和等级标签。
- `STEP`、`REQ`、`RES`、`WARN`、`ERR` 与普通信息使用不同颜色。
- 日志先按事件sequence升序，再渲染到页面，最新事件固定在底部。
- 面板默认开启自动跟随；用户离开底部后暂停，回到底部或点击“恢复跟随”后重新滚到底部。
- 任务终态追加为最后一条日志：成功、失败、取消和结果未知分别显示`DONE/FAIL/STOP/UNKN`；即使没有新增事件，终态变化也会触发自动跟随。
- 移除终端上方的收起和跟随按钮；自动跟随及复制并入标题栏右侧。复制包含业务日志和终态日志，并提供“已复制/复制失败”反馈。
- 日志区最大高度360px，内容超出后只在终端内部纵向滚动。
- 运行记录、手动任务和邮件测试继续复用同一个`TaskProgressPanel`，没有创建第二套日志界面。

## 检查

- `npm run check`376项通过；新增测试覆盖乱序事件重新排序、日志等级配色映射和任务终态日志。
- 实际后台打开执行记录：4条业务日志序号严格递增，末尾追加绿色`DONE 任务执行结束`，标题栏只有跟随和复制两个按钮，自动跟随默认`aria-pressed=true`。
- 强制将日志区缩至可滚动高度后上滚，自动跟随切换为暂停；点击恢复后重新到达底部。
- 点击复制得到5行文本，包含序号、时间、`STEP`消息和最终`DONE`日志；按钮短暂显示“已复制”。运行日志区的计算最大高度为360px，`overflow-y=auto`。
- 1440px和390px实页无横向溢出或`pageerror`；移动端保持等宽终端布局并隐藏序号列以保留消息宽度。

## 边界

- 终端颜色只用于区分日志语义，不改变后端事件级别或执行状态。
- 终端面板只展示已经脱敏的日志与报文；认证凭据、密码和令牌仍不得上报。
