# 放弃修改后的客户端导航验收

版本：unsaved-leave-client-navigation-verification-1。日期：2026-11-12。

## 问题与修复

共享离开守卫在确认“放弃修改并离开”后调用`location.assign()`，导致同源页面重新下载整份文档、后台壳重载并丢失当前运行时状态。现在共享守卫区分目标：

- 同源 HTTP(S) 目标使用Next.js `router.push()`，保留当前客户端运行时。
- 跨域目标继续使用浏览器文档导航。
- 取消、忙碌、确认退场、焦点恢复和浏览器`beforeunload`保护保持不变。

账号中心共享守卫和普通后台页面的独立守卫都使用同一修复。

## 实页验收

- 在通知策略添加一条未保存规则，点击“通知模板”，再选择“放弃修改并离开”。
- 页面到达`/admin/notifications/templates`并显示“通知模板”。
- 导航前后主文档`load`事件增加0次，`resourceType=document`请求增加0次，性能Navigation条目仍为1。
- 导航前写入的`window`运行时标记仍存在，证明并非整页刷新。
- 无`pageerror`；验收只创建本地策略草稿并放弃，没有保存设置。临时QA会话已撤销。

## 检查

- 完整`npm run check`373项通过。

## 边界

- 浏览器原生刷新、关闭标签或跨域跳转仍由浏览器控制，不属于站内客户端导航。
- 嵌入实时预览继续使用其iframe离开桥接，不叠加后台原生卸载提示。
