## 已交付

短代码按钮移入两种格式的源码/可视化工具栏，在原区块光标或选区插入；HTML原生调用不被转义成普通HTML文字。视频入口筛选已有视频并复用统一媒体选择/上传；Markdown解析`![](){type=video}`及其URL/说明，HTML使用video。新增HTML文字颜色、源码/可视化光标定位、区块标题范围内吸顶；修正摘要焦点和冲突提示左右间距。

保存修复接入原有onRevision通知：授权读取新修订并更新基线，继续投影同一个Y.Doc，保留标签页正文。保存期间通知补读、异步截点后取当前修订；后端revision通知带已有committed_seq作为最低保存屏障，正文未到齐不能提交，HTTP未来修订也不提前采用；私有访问改动、源文指纹、租约、真实同块冲突继续受保护。没有新后端接口、迁移、依赖或共享rich节点。

## 实页检查

在原容器HTTP入口的内置Chromium，用独立临时草稿完成；该稿从未发布，最终通过正常可恢复回收处理。现有功能长文未改源文或重新发布，WordPress未修改。

1. 源码短代码选择窗口确认后替换选区，只有原来的两个稳定ID区块。HTML可视化在第25段中插入含HTML正文的notice调用，保存后仍是原始分隔符，私有前台预览正确展开。
2. Markdown源码选择视频后得到`![](site://media/UUID){type=video}`；Markdown可视化再次插入视频、保存并切回源码，得到同一扩展语法（目标可有尖括号）。HTML源码/可视化都显示媒体库中的实际video，正文没有上传占位或派生媒体URL替代源引用。
3. HTML选中文字设置红色，切回源码为六位十六进制span。后续把已有颜色改成蓝色，保存、刷新后仍为rgb(36,87,197)，原section/class/data属性保留。私有前台预览显示相同文字色；两个格式的视频都解析为实际播放器，Markdown视频实播到5秒资源的进度后暂停。
4. 35段HTML里搜索并选中第25段文字。切到可视化后选区保留，实测y=509..533，位于720px视口内、区块栏下方；切回源码后选区仍为原文字，对应源行y=291..340。没有自动扩成整个HTML元素。
5. 桌面区块标题top=64px；320px窄屏在导航第二行底部108px之后，区块标题top=116px，保留8px间距。标题只在所属section内sticky，滚过前一个区块后它退出；正文内部仍能滚动，栏内模式/排序操作可用。修正了首次实页发现的祖先overflow:auto造成错误吸顶基准/遮挡工具栏问题。
6. 窄屏工具栏换行，颜色面板280px，左右位于16..296，页面scrollWidth=308、视口320，没有整页横向溢出。摘要焦点为完整边框/轻环。冲突提示与正文块的left/right完全一致，padding=10px 12px。
7. 首次保存取得正式草稿ID后，连续保存、两窗口交替保存、HTML短代码/颜色/视频后续保存及刷新全部成功。最终验收到修订10；正常编辑不再因旧detail.revision误报40951。
8. 两窗口在同一个正文旧基线上编辑，先后保存仍正确出现冲突，后一个窗口的“冲突保留输入B”仍在；主库没有被它覆盖。另一次在插入窗口等待期间远端修改同一HTML块，过期可视化选区拒绝插入，区块/调用数量与远端内容保持。
9. 深色与减少动态下检查颜色校验、禁用应用、弹出/取消及模式切换。Escape关闭颜色面板回原焦点，短代码窗口取消不写入；动效和颜色模式已恢复原来的轻量动效/跟随系统，视口已重置。原文章编辑入口保留供用户验收；后端更新重启后原页面自动重连、修改已同步、无冲突提示。

## 当前边界

短代码在可视化中显示完整调用原子，参数/正文回源码修改；不承诺原子内部直接排版。视频保留源码参数，但本轮未新增播放器参数面板。颜色UI只提供文字前景色和六位十六进制值。跨视图撤销历史仍分开。

本轮没有重测Safari/Firefox、读屏器、触屏实机、长时间断网/媒体故障全矩阵，或模板整条可靠设置投递；相关历史P0结果不等同本轮重跑。运行仍是HTTP与0.0.0.0开发服务，宿主机端口映射由用户管理；具体设备IP/临时URL仅在忽略配置中，不进入交接。
