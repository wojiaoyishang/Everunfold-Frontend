# 编辑操作组随滚动进入顶栏验收

日期：2026-11-06。范围：用户要求文章保存/发布加入原预览组的滚动顶栏行为，页面编辑把实时/前台预览与右侧保存/应用合并，并将返回列表放在左侧。沿[ADR0054](../decisions/0054-scroll-editor-preview-actions.md)，保留独立实时预览工作界面的原保存入口。

## 已实现

- 文章/说说的EditorActions放入同一ScrollHeaderActions，与正文预览、前台预览、实时预览一起移动；发布后的撤回/查看前台沿原条件呈现。只维护一组真实按钮及稳定Portal宿主，原状态、权限、未确认操作和回调保持。
- 页面编辑顶部为左侧返回列表、右侧实时/前台预览及保存/应用；原下方预览行移除，读取服务器版本仍在内容区。表单ID及跨文档实时预览的校验/提交沿原实现。
- 窄屏操作组按实际宽度换行，第二行高度仍由既有观察器记录，区块固定栏继续避让。无新增依赖、迁移或业务写路径。

## 实页发现并修复的保存确认问题

验收顶栏保存时，实际HTTP200且后端版本已递增，但旧前端协作Schema未包含DraftDetail已有的owner_id，严格解析失败后显示“保存结果尚未确认”。此问题来自已有静态契约滞后，与按钮位置无关。

后端重新导出collaboration2.1.0，补充已有可空拥有者字段，新增契约新鲜度检查；前端从`78023b40233e77c86805b0f23e06655b2c76585e`生成，SHA256为`1bb0a047c9c1971219c02b1740f4226dbc15714d323514bb80a973da248c41d4`。HTTP操作、WS帧、持久ACK、修订/合并锁均保持；保留未知字段和非法UUID拒绝。

生成客户端新增真实回执含owner_id可确认、且只请求一次的回归，以及错误UUID/未知属性拒绝检查。原未确认操作在恢复连接后使用同操作ID重试成功，版本未重复增加。
