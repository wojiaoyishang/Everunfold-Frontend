## 说说：当前缺整条展示链路

原站首页确实混排文章和说说；说说“热爱”“救赎”的详情可公开读取。原主题的差别如下：

| 场景 | 原主题/原站依据 | 新版现状与建议 |
| --- | --- | --- |
| 首页 | content-shuoshuo-preview.php：可选标题、正文直接展开显示、日期时间、互动数量及详情入口；不套文章大头图 | 现有列表仅接受 article。新增专用轻量卡片，与 ArticleCard 共用基础部件 |
| 长说说 | argontheme.js：超过约 400px 折叠；原站配置 fold_long_shuoshuo=true | 增加渐隐折叠、平滑展开/收起，处理图片加载后的高度变化 |
| 图片和正文链接 | 说说正文包含图片、引用、链接等内容；原站“救赎”包含图片 | 复用正文/媒体能力；正文链接、图片预览和操作按钮独立点击，不能用整卡链接覆盖 |
| 详情 | single-shuoshuo.php、content-shuoshuo-details.php：轻量正文、独立点赞、评论入口和分享 | 独立详情展示，复用评论、媒体和分享；不强制文章标题/头图/阅读时长布局 |
| 归档 | shuoshuo.php 提供数量、按时间展示及互动/评论预览 | 可沿用 /ss/ 补齐分页说说流；原模板一次取全量的方式不照搬 |
| 互动 | shuoshuo-operations.php：点赞、加载/结果反馈、评论数量及关闭评论状态 | 本阶段可用明确标注的样例演示，预留等待、成功、失败、已点赞和评论关闭状态 |

**区别已启用功能与主题能力：**本次原站 `/ss/` 返回 200，但其正文同样为空；不能把“主题有归档模板”写成“线上归档已正常启用”。补齐新版说说归档属于建议。原首页及说说详情则已有实际公开页面证据。

建议先覆盖六类样例：无标题纯文字、带标题短文、长文、单图/多图、评论关闭、互动失败。多图排布是新版设计选择，不宣称原站固定九宫格。

## 接口草案的边界（建议，非发布契约）

| 能力 | 先约定的语义 |
| --- | --- |
| 内容身份 | 顶层 type：article / shuoshuo / page；共享稳定 ID、原路径、时间、作者。说说标题允许缺省；访问策略、发布状态和正文块类型各自独立 |
| 首页/列表 | 同一分页结构承接混合内容和类型筛选；文章给摘要，说说给受控正文预览及媒体尺寸，避免所有类型硬套 excerpt |
| 内容详情 | 共享稳定块 ID 的正文/媒体能力；按内容类型选择展示组件。评论开放状态、公开互动总数是独立语义 |
| 评论/点赞 | 按内容 ID 复用；公开计数与“我是否点赞”等浏览者状态分离。后者不能进入公开 SSR/共享快照；前端要能演示等待、失败和重试 |

具体字段、端点和兼容版本后续实施时再确定。当前正式契约仍为 0.1.0、kind=article/page，本轮没有改动生成类型或创建另一套权威定义。需要升级时由后端发布，前端生成并通过适配边界接入样例/真实数据。

组件组织建议：内容分发入口 + 独立 ArticleCard/ShuoshuoCard、类型对应的详情头部；正文、图片、评论、分享、时间展示共用。特殊页面以明确模板承接，不靠复制整套文章页，也不把页面模板混入内容 type。

## 下一轮接续与检查

建议顺序：说说首页卡片/详情/分页归档 → 搜索类型 → 原 URL 模板页（归档、高中日记）→ 推荐分享、主题色、特色页面和状态完善。先完成前端样例和契约草案，再按用户安排整体导入；不要继续旧文档中“先全面迁移才做展示”的顺序。
