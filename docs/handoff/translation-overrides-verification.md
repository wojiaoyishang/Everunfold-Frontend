# 自定义翻译覆盖验收

版本：translation-overrides-verification-3；2026-11-11（Asia/Shanghai）。对应 [ADR0111](../decisions/0111-sparse-custom-translation-overrides.md)。

## 检查范围

- 只读基础 JSON 与数据库稀疏覆盖分离。
- 前台/后台/API 消息作用域、语言回退、搜索、分页、恢复默认和保存。
- 占位符校验与修订冲突。
- 公开设置投递和后端消息缓存刷新。
- 桌面与390px实际页面。

## 后端

- 隔离 PostgreSQL 测试创建覆盖后，公开设置投影包含 `public`、`admin`、`backend` 值。
- 删除公开覆盖后该行消失，其他作用域保留。
- 占位符 `{count}` 丢失时返回422，不写入修订。
- 后端 `core.error` 覆盖保存后可立即从进程缓存读取自定义消息。
- 迁移`0042_translation_overrides`已应用，数据库 schema 当前通过；Ruff、mypy和Alembic check通过。

## 前端

- 自定义翻译解析覆盖英文内置值，并支持目标语言与 `ui_locale` 分离。
- 管理页读取前端约2017条基础消息和后端消息目录；搜索、范围/语言/状态切换和分页正常。
- 翻译入口位于“外观”组；范围默认“全部范围”。列表以紧凑三列显示键名、原文与译文，长内容省略；详情保留同一工具和列表，代码编辑器按原文、译文上下排列，右侧只读显示上下文与元信息。
- 彩色进度条按当前范围和语言统计已翻译、默认翻译、未翻译的条目和占比。
- JSON 导出包含已保存与待保存覆盖；导入先校验并合并为待保存修改，支持显式空值删除，超过单批上限时按修订分批保存。
- 1440px、611px和390px实际页面无横向溢出或脚本错误；验收只读，未产生真实翻译写入。

## 实际故障修复

数据库已存在“工作台 → 大香蕉”的 `public`、`admin/zh-CN` 覆盖，但设置接收器仍在运行旧进程，按旧设置 Schema 校验并反复返回 409，节点停留在版本54。重启接收器后在系统设置执行“重新同步”，设置版本56成功应用，后台导航显示“大香蕉”。新增接收器 Schema 回归测试，覆盖含 `translations` 的公开设置写入。

## 范围

首版使用源码中文原文作为兼容键，尚未迁移为全部语义键；机器翻译、复数编辑器、审批流、导入导出和逐插件前端目录自动发现仍待后续。用户正文、标题、评论和名称不参与自定义翻译。
