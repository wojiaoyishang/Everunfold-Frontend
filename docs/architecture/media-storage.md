# 媒体库、上传存储与静态分发

版本：media-storage-3，2026-11-01。**状态：基础图片/视频与图标库、本地存储、Base URL 和设置字段关联已实现；变体、CDN 上传接管与回收流程仍为设计。** 用户已确认后端管理业务媒体、独立 Base URL、相对/绝对 Uploads Path 和可替换存储边界。本期实施细节以 [ADR 0025](../decisions/0025-recursive-menus-and-icon-library.md) 与 [媒体指南](../development/media-library.md) 为准，下文未实现字段和接口仍须后端契约先行。

本设计延续 [v2.11 媒体基线](../baseline/01_Design_Baseline_v2.11.md)、[v0.14 媒体一致性](../baseline/02_Engineering_Plan_v0.14.md) 和 [ADR 0017](../decisions/0017-media-storage-and-upload-lifecycle.md)：媒体 ID 稳定，原文件不可覆盖，WebP 为同一媒体的派生文件，默认公开、默认软删除。Next.js 消费媒体映射，不持有上传路径或存储凭据。

## 当前实现与目标的差别

试导入仍把引用文件复制到前端 `public/uploads/wordpress/`，正文使用 `site://media/{id}` 和 media_urls，头图另存 cover_url；这部分尚未整体迁移。本期新增 `app/modules/media`、media_assets 表、管理员图片/视频及图标上传/查询与后端 `/media` 分发；[media] 的 base_url/uploads_path 已生效。当前支持 icon/library 用途、本地提供器及头像/背景字段绑定；文章正文整体迁移与完整管理生命周期尚未完成。

新目标把文章图片、头图、后台上传的背景/头像等业务媒体交给后端。Next.js 的代码包、CSS、字体、可信图标等构建资产仍属于前端。现有主题参考图片与试导入文件在将来的迁移核验完成之前保留，本轮不搬移或删除任何文件。

## 配置与地址含义

后端已支持下面的配置组；可省略 base_url 使用默认推导。实际部署值不提交，修改后重启相应服务。其余尚未发布的提供器/变体配置仍为设计：

```toml
[media]
base_url = "http://127.0.0.1:8001/media"
uploads_path = "./uploads"
```

| 项目 | 建议规则 |
| --- | --- |
| `media.base_url` | 公开媒体地址前缀；未显式配置时由 `BACKEND_BASE_URL + /media` 推导，不写死生产域名。允许 HTTP(S) 地址及路径前缀，禁止凭据、查询参数和 fragment；统一处理尾部斜杠 |
| `media.uploads_path` | 默认 `./uploads`。相对路径以**实际加载的配置文件所在目录**为基准，绝对路径直接使用；不随 API/Worker 的工作目录改变 |
| 本地静态入口 | 后端 `/media/<object_key>` 只读映射到上传根目录；生产可由后端部署中的静态服务器承担字节传输。不是 Next.js 的 `public/`，也不是 `/v1` 业务 JSON 接口 |
| 逻辑与物理路径 | 数据库存 `storage_id + object_key`；本地文件为 `resolved_uploads_path / object_key`，公开链接为 `base_url / object_key`。不在每行保存可变域名或机器绝对路径作为权威值 |
| 可见配置 | 浏览器只取得本次资源所需的公开 URL；本地路径、存储连接、桶凭据、上传管理信息不进入公开快照 |

例：配置文件位于后端根目录时，`./uploads` 对应 `E:\Programming\Python\Everunfold-Backend\uploads`；也可显式指定 `E:/EverunfoldData/uploads` 或 Linux 上的 `/srv/everunfold/uploads`。先按现有规则定位配置文件，再解析其中相对上传路径，不把 `CONFIG_FILE` 自身的项目根解析规则一起改掉。拒绝空路径、Windows 的 `E:uploads` 盘符相对形式和隐式 shell 变量展开；不使用原 WordPress 备份或前端目录作为新上传根。

配置加载时校验路径形式，实际上传时检查目录写入能力。各 API/Worker 必须使用同一存储配置；同一磁盘可供多进程使用，多台服务器不能把各自同名路径当成同一个存储。跨主机须使用共享存储或明确唯一源站。本期已忽略 uploads 和旁路工作目录；生产权限、共享盘和断电恢复仍须部署验收。

## uploads 的物理目录

建议用上传受理时确定的 UTC 年月加不变媒体 ID；更改展示名称、分类、作者、文章或显示日期不移动文件：

```text
uploads/                              # 只放已校验、可分发的正式文件
  2026/
    10/
      <media_id>/
        original.jpg                  # 原始字节，不覆盖
        variants/
          webp-v1-<variant_id>.webp   # 转换方案及派生身份固定
      <another_media_id>/
        original.png

.everunfold-media-work/                # uploads 的同级目录，不公开、不随 CDN 同步
  <storage_id>/
    staging/<upload_id>/payload.part
    quarantine/<upload_id>/...
```

- `<media_id>` 建议使用服务端生成的 UUID；导入保持已有稳定 ID。`object_key` 示例为 `2026/10/<media_id>/original.jpg`，相对于 uploads 根，不含盘符、开头斜杠或域名；内部统一用 `/`，由本地适配器转换操作系统路径。
- 原文件扩展名来自校验后的实际类型；用户原始文件名作为媒体元信息保存，下载时经安全编码使用。新原图分配新媒体 ID，修改内容不能覆盖原文件。相同内容的主动复用与重复请求幂等分开处理，首版不默认做跨记录物理去重。
- WebP 等派生文件属于原媒体，不在媒体库多显示一条。转换器或规格更新产生新派生 ID/key，旧版本保留引用；不要求首版实现多尺寸缩略图。派生失败仍可使用原图。
- 物理目录不按文章 ID、文章标题、标签或用户名称划分，一张图可被多篇内容复用。媒体库将来的虚拟文件夹/标签是数据库组织信息，调整它们不改变 URL。
- 工作区与目标目录必须位于支持本地发布操作的同一文件系统。工作目录虽然是 uploads 同级，仍须检测独立挂载/符号链接造成的跨文件系统情况；不能仅凭路径相邻认为原子发布可用。文件创建必须防覆盖，不能直接使用会替换现有目标的 rename 语义。
- 不创建公开 `tmp`、配置、清单或日志子目录；软删除只记数据库状态，不把仍可能被引用的原文件移到另一 URL。目录扫描是修复/盘点工具，不是媒体库查询来源。

这种相对 key 可以原样作为对象存储 key。S3 的文件夹表现本身来自 key 前缀，不能依赖真实目录存在或目录重命名能力；因此云端扩展也沿用完整不可变 key。[S3 对象命名说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-keys.html)

## 媒体库列表与上传队列

媒体库是数据库分页列表，**每个逻辑媒体一行**，同一文件的原图、WebP、本地副本和云端副本不展开成重复资源。建议默认按创建时间和 ID 倒序稳定分页，支持文件名/标题搜索，以及类型、月份、上传者、使用情况、存储位置、处理状态和回收站筛选。

| 展示区域 | 内容 |
| --- | --- |
| 列表主信息 | 图片预览或类型图标、展示名/原始名、格式、大小、宽高或时长、上传时间、上传者 |
| 使用信息 | 当前文章/页面、草稿、历史修订、头图/站点设置等引用；“当前未使用”不能等同于“可永久删除” |
| 状态 | 校验中/可用/失败/回收站；需要时显示 WebP 处理中或失败，不覆盖原图状态 |
| 存储详情 | 本地/云端位置、实际大小/哈希、最后校验结果、复制进度/失败、当前分发入口；云端副本已核对不代表 CDN 每个边缘节点都已缓存 |
| 操作 | 插入稳定引用、复制当前公开地址、下载原图、编辑元信息、查看引用、移入/恢复回收站；永久清理是独立受权操作 |

上传队列与可选媒体库分开：队列每个文件显示“等待、传输进度、服务端校验/保存、成功、失败/取消”，可按文件重试。传输到 100% 不能显示“已入库”；必须等后端确认 `ready` 并提交数据库。批量上传逐文件取得结果，一个失败不抹掉已经成功的其他文件。刷新后从后端上传会话恢复已登记状态，不能仅靠浏览器内存声称成功。

管理列表必须鉴权；公开内容接口只返回该公开内容所需的媒体映射，不公开整个媒体库、上传者或存储详情。列表无需实时扫描本地磁盘/远程桶；健康核验与复制任务按需更新记录，避免云端变慢拖垮每次列表请求。

## 数据记录的职责

下面细化 v0.14 的 `media/media_variants/media_locations` 建议，不是正式 DDL：

| 记录 | 主要内容 |
| --- | --- |
| `media` | 稳定 ID、类型、原名/展示名、可选说明/默认 alt、上传者、创建时间、staging/ready/failed、软删除时间；上下文专属 alt 仍存正文块，不强迫多处共用 |
| `media_variants` | 文件表示 ID、media_id、original/webp 等用途、规范化 MIME、字节数、SHA256、尺寸/时长、转换规格/版本与状态；original 也作为一种表示 |
| `media_locations` | 表示 ID、稳定 storage_id、object_key、必要远端对象版本/校验信息、copying/ready/failed、校验时间；一份表示可以有本地与云端多个位置 |
| `media_uploads` | upload_id、申请者、绑定的 provider/storage_id、目标 media_id、幂等键、受控临时对象、上传/确认状态与失效时间；会话创建后不随默认 provider 切换改变归属 |
| `media_references` | 媒体与当前内容、草稿、历史修订、站点设置的关联；按稳定内容/修订/块 ID 追踪，不以当前 URL 作为身份 |

需要保证每个媒体一个不可变原始表示、位置 key 唯一、会话完成幂等；派生唯一性依据原图、规格和转换器版本。引用记录从可信解析/保存链路维护，不能只靠字符串搜索决定“无引用”；历史协同数据与恢复保留范围未核清时不执行永久清理。

`public_url` 是后端根据有效配置和可用位置生成的响应字段，不能成为媒体身份。存储绑定用稳定 ID，不用域名作 ID；CDN 的 HTTP 域名与对象存储上传 endpoint/bucket 是不同设置。凭据通过服务端受控配置引用，数据库仅存位置和运行事实，不存第二份可编辑密钥配置。

## 上传流程与可替换接口

核心负责鉴权/CSRF、配额、media_id/key 分配、验证要求、数据库与引用；可替换 provider 负责文件传输和持久存放。默认 local provider 通过 FastAPI 接收流并写本地工作区。以后 CDN/对象存储插件可以替换传输计划，后端登记、权限和完成确认仍不跳过。

建议先定义能力边界，具体 Python 协议和 HTTP Schema 留到实施发布：

| 能力 | 语义 |
| --- | --- |
| prepare upload | 生成绑定 upload_id 的传输计划；local 为后端上传入口，云端可以是限定对象/大小/方法/时效的直传票据；前端不硬编码某个厂商 SDK |
| receive 或 direct transfer | local/后端转发按流写入 staging；直传模式写私有临时 key，不能让浏览器指定最终 key 或任意回调地址 |
| verify and finalize | 核对完整文件、类型、尺寸、大小和哈希，冻结/绑定实际被验证的源版本，再以防覆盖方式发布最终对象；完成返回可核验的对象描述，不只是一个 URL |
| open/read、stat、copy、remove | 供派生、下载、核验、迁移和获准清理使用，调用者不依赖本地 Path；不支持的能力明确报告，不能伪装成功 |
| delivery/purge 扩展 | 公开地址解析/复制校验和后续 CDN 清理独立于上传传输；插件可支持其中一部分，不要求启用 CDN 就必须改变上传方式 |

核心时序为：登记受控上传会话 → 文件进入非公开 staging → 验证并持久发布 → 短数据库事务提交原媒体/表示/位置的 ready、审计及必要 Outbox → 返回成功。外部文件/网络操作不放入长数据库事务。只有原图及选定位置可用，资源才进入正式映射；WebP 后续由 Worker 生成，成功后再发映射变更。

文件存储与 PostgreSQL 不具备共同事务：文件完成但数据库失败可能留下孤儿对象，须按会话、key 和哈希恢复/隔离；不得返回成功，也不得自动删除仍有引用的原文件。数据库先登记的 staging 不能被当作可用媒体。重复完成返回同一媒体，冲突请求不覆盖它；超时未知先查询确认，不能盲目重传到原图 key。

云端不能信任浏览器“上传成功”或未经验证的回调。预签名 URL 在有效期内可重复使用，同 key 上传可能替换已有对象，因此直传仅写隔离临时 key；后端校验后封存/复制到不可由该票据覆盖的最终 key，绑定源版本/条件以防校验与复制之间发生替换。SHA256 单独验证记录，不能把所有存储的 ETag 当作文件哈希。[S3 预签名上传语义](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)

扩展由可信后端模块注册，FastAPI 仍用 `router_init(ctx)` 唯一装配；Worker 独立装配所需存储能力，不调用路由注册。首版先实现 local 和清晰接口，不建通用运行时插件安装器；后续插件不得绕过状态机、强行覆盖原图或直接改正文。

## CDN 分阶段接入

**只做静态分发：**保持本地上传，CDN 可以回源后端，或将 uploads 的相对目录完整复制到云端。对外仍通过统一 Base URL 生成地址；数据库中的媒体 ID、原名、引用和对象 key 不变。后续新增上传必须持续回源或有可追踪的复制任务，不能只复制历史文件后就停止同步。

**接管上传：**切换默认上传 provider，由后端返回云端传输计划并完成确认。新媒体可直接拥有云端原始位置，旧媒体的位置记录保持真实；上传队列与媒体库界面无需按厂商重写。是否保留本地副本是独立策略，不假定云端直传后本地也有文件；云端故障不能擅自落到本地并返回不可达的 CDN URL。

建议迁移顺序：

1. 保持相同 object_key，导出受保护的媒体清单（表示 ID、key、大小、SHA256），复制已完成正式文件及仍有历史引用的版本；不使用删除镜像模式清掉软删除文件。
2. 核对对象字节与必要 HTTP 元信息（MIME、编码、缓存策略）；不是仅比较文件数量或 Last-Modified。对象写入成功不等于新公开域名已可读，须验证分发入口。
3. 处理迁移期间新增/派生文件：可短暂冻结写入，或追平增量并校验水位；本地与云端位置分别记录，不提前把全部资源标成云端 ready。
4. 所有现有映射目标在新 Base URL 下可读后，激活新分发配置。只部分复制时维持旧入口；若以后支持按资源回退，由后端依据真实位置明确返回 URL，不由前端猜域名。
5. 记录分发配置代次并生成可靠映射刷新：内容 `media_urls`、头图、站点设置、列表、SEO 图片和关联页面/框架缓存都需要更新。配置文件变化必须经显式激活/检测流程转换为可追踪变更，不能只靠某个进程重启或缓存 TTL。
6. 等有关前端节点激活并确认后再考虑停旧入口；离线节点仍持有旧映射时继续兼容旧地址，或在上线前完成重建。失败回滚发布更高代次的旧分发配置，不回退内容/撤回水位。

因此用户侧可以保持“同步 uploads，修改 Base URL”的操作心智，但工程上必须自动或显式完成校验、增量收尾和缓存更新；不需要修改文章正文。目前可靠配置/缓存投递未完整实现，不能宣称改一个配置就已完成上述切换。

公共媒体 URL 不携带短期下载签名，否则无 TTL 快照中的地址会自行失效；直传上传票据只出现在认证的上传会话中，禁止进入公开快照和日志。原文件不可变适合长期静态缓存，具体 HTTP 缓存时长仍待实施决定；媒体公开和页面访问控制分开，公开资源不能保证在删除源文件后立即从所有缓存消失。

## 最小访问边界

上传接口必须经过真实身份/媒体权限验证，不能使用当前演示访客身份授权。限制流式大小、图片像素/解码资源、并发与磁盘预算；文件名、请求 MIME 均不可信。公开静态入口仅提供允许的文件类型、正确响应类型和 nosniff，禁目录浏览和脚本执行。HTML/SVG 等主动内容默认拒绝或按后续隔离/过滤策略处理，不因来自后台就同源放行。参考 [OWASP 上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。

媒体依照既定基线默认公开，无独立媒体 ACL；需要保密的文件不进入此公开 uploads。软删除阻止新的选用并可恢复，涉及现有引用须先处理；永久删除检查当前、草稿和历史引用，并由有权管理员明确发起。CDN purge 后续通过具名任务处理，不把普通删除误报为全网撤回。

没有 CDN 且后端媒体源站离线时，Next.js 已缓存正文仍可阅读，但未缓存图片可能无法加载。前端保留尺寸占位、alt 和失败反馈；独立正文能力不等于独立媒体副本。是否离线复制媒体属于另一个可选能力，本轮不加入实现范围。
