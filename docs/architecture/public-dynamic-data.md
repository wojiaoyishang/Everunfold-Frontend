# 公开首屏与浏览器动态数据设计

最新实现补充：[ADR 0015](../decisions/0015-reader-feedback-and-comment-likes.md) 已增加真实匿名历史评论点赞、无空位的浏览量和按登记能力计算的圆周进度。下文关于“点赞为演示”的现状描述保留为初版历史；当前说说点赞和本页评论发布仍是原型。真实认证、浏览计数及可靠快照同步仍后置。

版本：public-dynamic-2，2026-10-31。状态：**请求基线与演示能力已实现；正式业务能力分阶段继续**。跨仓库同步；原设计见 [ADR 0013](../decisions/0013-public-dynamic-data.md)，本轮实现边界见 [ADR 0014](../decisions/0014-page-registered-reader-requests.md) 和 [验收记录](../handoff/reader-requests-verification.md)。本文是职责与交互规范，不是第二份 API Schema。

## 需求、建议与现状

**用户明确要求：**Next.js 可以独立提供公开内容；浏览量等动态字段在请求完成前不显示，成功后自然出现，失败就不显示。设计交付后，用户授权实现基础请求、假登录/浏览量和导航状态图标，并测试后端离线有/无缓存；进一步要求状态面板不写死业务明细，而由各页面注册所需请求与额外内容。

**既有已确认边界：**浏览器直接请求配置的 FastAPI；公开 SSR 不含用户态；公开评论快照加浏览器异步更新；离线评论只读；公开快照无时间 TTL，已知撤回/转受限不回退旧正文。依据为 v2.11 的 Q20/Q21/Q34/Q54/Q57 及相关缓存章节。

**本文工程建议：**下面的数据分类、状态图标文案、请求调度、浏览计数口径和建议参数用于下一步评审/实施。它们不代表用户已确认全部细节，也不表示接口、同步或计数已上线。精确字段、路径、存储结构由后端另行发布正式契约。

**现状：**Next.js 读取本地完整公开快照，在线内容契约为 0.1.0；0.2.0-preview.1 仅为展示草案。另发布 0.1.0-preview.1 演示读取契约，已接生成客户端、页面请求注册、共享调度、状态图标和假身份/浏览量；演示默认关闭，不创建会话或浏览记录。评论只读 API 已有，前端仍未接异步更新；点赞及本页评论为原型演示。当前适配器的 `reaction_count: 0`、`comments_open: true` 是演示默认值，不能迁作生产事实。下文未在 ADR 0014 列为已实现的能力继续属于设计，正式计数口径仍待确认。

## 首屏原则与 SEO

这里的“静态内容”指 **不必等待实时 FastAPI 的公开内容**，可以由 Next.js 根据节点公开快照渲染；不等同于整站必须使用静态导出或只在构建时生成页面。

- 文章/说说正文、标题、摘要、可访问链接和关键元信息在首份 HTML 中可读。开启 JavaScript 后增强交互；后端动态接口失联不应把正常公开页面变成空白或加载页。
- `title`、description、canonical、robots、OG、已发布语言替代链接以及后续结构化数据/Sitemap 使用后端授权的公开元数据。不可等浏览量或登录检查完成才生成，也不因计数失败改变文章索引策略。
- 列表、归档、分类、标签和分页使用真实 URL 与可抓取链接。无限滚动/客户端筛选只能增强已有入口，不能让唯一发现正文的入口依赖滚动或点击。
- 字数/阅读时长来自同版正文；目录、阅读进度、相对时间可由已有公开字段本地派生。浏览量不是本文的首屏 SEO 必需字段；不为凑结构化数据填入未知互动数或假零值。浏览/点赞变化不改文章正文的更新时间或 Sitemap `lastmod`，也不触发整篇公开快照重新发布。
- 没有合法公开内容时仍区分不存在与暂不可用，使用真实 HTTP 状态；不能用“动态字段可隐藏”掩盖正文获取失败。已知权限撤回优先于离线可读。

这些是本项目的实现选择，不是“搜索引擎完全不执行 JavaScript”的结论。Google 说明它会渲染 JavaScript，同时仍建议服务端或预渲染，并强调链接和真实状态码；本文据此优先保证可独立阅读的 HTML。[Google JavaScript SEO 文档](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)

## 按页面与数据划分

| 数据/区域 | 建议首屏来源 | 浏览器随后做什么 | 不可用时的行为 |
| --- | --- | --- | --- |
| 站名、顶栏/侧栏同一菜单、公告、作者资料、社交链接、页脚 | 同一代公开站点配置 | 后续配置版本变更时一致替换公共壳，不按控件轮询 | 保留仍允许公开的完整配置；后台改动依靠正式同步链路 |
| 首页文章/说说、正文、头图、发布时间、作者、分类标签 | 公开内容快照与媒体映射 | 懒加载非关键媒体，增强折叠/图片预览；不另请求正文来补空首屏 | 保持可阅读；撤回例外按不可见标记处理 |
| 归档、分类/标签列表、分页、文章/说说数量 | 同一代公开列表及统计 | 发布/撤回/类型变更后更新快照；不单独用即时总数改旧列表页码 | 保留一致版本，不出现“有下一页但没有内容” |
| 侧栏文章数、分类数、标签数 | 公开快照统计 | 随对应资源更新，不需每次浏览实时拉取 | 正常保留；不把它们误归为访问流量 |
| 字数、预计阅读时间、目录、相对时间、阅读进度 | 正文派生数据/公开时间 | 本地计算显示变化，无后端请求 | 正文及绝对日期仍可读 |
| 上下篇、同类推荐、相关文章 | 公开关联内容与真实链接 | 当前推荐沿用稳定的分类/标签/时间规则 | 保留推荐；不因指标失败整栏消失 |
| 文章/说说浏览量 | 无数值 | 真实 ID 的公开统计读取成功后显示 | 等待、超时、失败均隐藏该字段，绝不显示假 0 |
| 说说/评论及未来文章点赞总数 | 建议不把实时数当首屏依赖 | 公开计数补充；操作成功后应用服务端结果 | 隐藏未知数字；操作入口能否使用由业务能力决定 |
| 首批已批准公开评论、回复关系、历史评论数量 | 公开评论快照 | 异步核对更新/分页；动态计数与评论版本一起理解 | 保留合法快照，提示当前只读；不清空为“暂无评论” |
| 新评论、评论最新总数、后续分页、回复对象定位 | 已有快照可用部分 | 按需读取；新评论提示用户加载，定位时补目标页 | 保持现有列表/滚动位置；局部提示加载未完成 |
| 当前访客登录状态、本人是否点赞、评论资格、本人待审核留言 | 不进入公共 HTML/快照 | 浏览器按需向 FastAPI 获取私有状态 | 未确认不等于“未登录/未点赞/被禁止”；不能展示上个账号状态 |
| 评论提交/点赞/登录/验证/密码解锁 | 仅公开表单外壳可首屏 | 用户操作触发正式业务请求，明确提交中/成功/失败 | 不声称已提交；保留输入供用户重试，不离线自动代发 |
| 定时开放提示 | 仅已获准公开的摘要状态/时间 | 本地倒计时，到点请求权威状态 | 到点不自动放出受限正文；以后端结果为准 |
| 搜索结果页 | 当前从 Next.js 本地公开快照查询 | 搜索建议可按输入动态请求；后续完整搜索设计另定 | 搜索建议失败仍可提交真实搜索页；完整搜索失败不是零结果 |
| 最新评论侧栏、热门榜、站点 PV/UV/在线人数（可选） | 本轮不新增；如启用可有版本化公开种子 | 仅在明确有产品用途时动态补充 | 隐藏无结果模块/提供已有公开种子；本轮未证明原站都启用 |
| 外部视频/嵌入服务（如正文确实包含） | 安全的公开说明、链接及尺寸占位 | 进入可视区域或用户操作后加载媒体 | 局部替代链接；外站失败不算本站后端失联 |
| 阅读设置、首页筛选、背景播放、折叠、复制/分享 | 公开默认值与本机偏好 | 浏览器本地执行/持久化；保持已有设置规范 | 存储不可用降级为本次会话，不请求业务库 |

其中评论数量具有两种时间语义：快照中的历史公开数量可以保留；随后成功获取的数量代表某次更新结果。必须明确所属版本/时间，不能把快照数称作实时数，也不能把演示留言计入真实总数。热门推荐若将来启用，不在用户已阅读或正在点击时自动重排。

## 动态字段与阅读流程

### 可选指标的状态

1. **未请求/等待中：**浏览量的图标、数字及分隔符均不可见，不显示骨架闪烁、“加载中”或 `0`。首屏正常显示其余文章信息。
2. **成功且有效：**核对 HTTP 状态、统一外壳、契约、内容 ID 和当前请求代次后自然淡入。真实 `0` 是有效值；字段缺失、`null`、不支持、解析错误与请求失败均不是零。
3. **失败/超时：**继续隐藏未知指标；同批其他成功字段照常显示，不弹全站错误横幅。状态图标可以表达这次更新不完整。
4. **重新检查：**首版建议不从上次访问的持久缓存预显指标；新的导航/恢复检查中暂隐藏相应指标，成功再显示。检查失败仍隐藏。短时复用同一次进行中的请求，避免组件分别请求；不把失败状态写成数字缓存。

“隐藏字段”不等于要把页面挤来挤去。建议在元信息末端预留受控的小区域，保持整行高度与窄屏换行稳定；等待时没有可见占位字。数值使用稳定数字宽度/紧凑格式，图标与数字一起显示，分隔符只跟随实际可见字段。大数、窄屏和字号偏好都要验收。

淡入建议约 160–220ms，可配轻微透明度/位移变化；这是未实现的建议初值，服从已有全站动效偏好。减少动态直接切换，不滚动、不转移焦点、不反复向读屏播报每个数字。动态插入内容应预留布局空间以减轻位移，不能仅靠动画掩盖重排。[web.dev 布局位移说明](https://web.dev/articles/optimize-cls)

### 与文章软导航的关系

页面就绪继续由合法公开页面内容决定。新文章准备完成后切换、再按现有规则定位；随后启动其动态读取。浏览量、登录检查或评论增量不加入导航的等待门槛。旧页面晚到的结果不得更新新页面或覆盖新导航的状态。

现有导航 5 秒慢网、20 秒超时、失败横幅 10 秒倒计时属于 **页面导航**；不复制给每个指标请求。用户主动加载更多评论失败可以在评论区给出重试入口；点赞/发评论失败必须明确反馈，不能按可选指标悄悄隐藏。

### 评论更新的特殊规则

- 首批公开评论直接可读，异步失败保留快照；全局按时间从早到晚、同时间稳定 ID 排序，回复仅统一缩进一级。不要重新引入多层讨论串或默认倒序。
- 新增评论成功拉取后提示“有新留言”，用户选择再载入，保留阅读锚点、页码、回复对象和编辑草稿。不得后台强行跳页/滚动。用户主动进入新分页可以直接展示该页。
- 更新总数、分页游标、列表与回复定位需要同一有效评论版本；增删期间先保证去重/不漏项。现有按页码 API 未承诺一致游标或增量版本，不伪装成已解决。
- 确知评论撤回/转私密时立即移除对应公开内容/引用，不等用户点“新留言”；错误回退不得复活已撤回评论。其余仍合法的快照评论可以继续读。
- 私密评论、待审核内容、邮箱/身份信息等只在相应权限通过后动态返回，不入公共评论快照。表单可离线编辑，正式提交在连接/资格未知时不得虚报成功；提交超时用幂等状态核对，不能自动创建第二条。

## 导航右侧状态图标建议

建议放在导航右侧搜索入口旁，使用已有封装控件与 SVG 图标体系。固定占位，主题色一致，默认低调；悬停、键盘聚焦或触摸点击可显示简短说明。不是新的遮罩层或常驻横幅。

建议名称为 **“动态数据状态”**，而非“后端已同步”。一次成功读取无法证明所有页面快照已落盘、所有节点已激活或所有写操作都可用。公共读、本人状态、写入结果、缓存复制分别有自己的证据。

| 状态 | 建议说明 | 判定与展示 |
| --- | --- | --- |
| 尚未检查/当前页无需请求 | 动态数据尚未检查 | 中性色静态图标，不显示成功勾 |
| 正在更新 | 正在更新动态数据 | 使用克制动效，减少动态时静态；不显示百分比假进度 |
| 本次读取完成 | 本页动态数据已更新 · 最近更新于… | 当前页本轮已触发的读取均成功；时间是最近一次完成时刻，不承诺持续在线 |
| 部分未更新 | 部分数据暂未更新，文章可继续阅读 | 某些独立能力失败；成功字段保留，未知字段隐藏 |
| 暂不可用 | 暂时无法更新动态数据，文章可继续阅读 | 超时/网络失败等；不能仅据此断言后端服务器宕机 |
| 浏览器报告离线 | 当前网络离线，已加载内容可继续阅读 | 本机网络信号只作提示；恢复在线后仍须实际请求成功 |

聚合范围是“当前页面已经注册并启动的能力集合”：尚未靠近评论区而未请求评论、不存在登录功能、未启用某类指标，均不算失败。**公共面板不固定列出业务明细**；页面按需要注册额外说明/控件，文章页的演示身份仅是一个接入例子，其他页面不需要提供相同项目。没有登记不能显示已同步；组件释放后移除登记。取消导航和过期响应不算后端失败。

401 是某次身份未通过，403 是对应权限受限，404 可能是资源不可公开，429 是限流，均不能直接归为整站宕机。部分业务失败可在相应能力中说明。状态图标不展示数据库/Redis/内部节点、Token、堆栈或原始错误；不为了一个勾频繁请求 `/health/ready`。第三方图片/视频失败也不改变它。

若未来需要公开“页面快照与源站版本一致”，必须另有明确的节点/资源版本核对与激活结果，并注明覆盖范围；不能把动态请求成功或通知接收 ACK 当成该证据。本轮不设计第二套缓存同步协议。

## 请求组织、缓存与组件边界

### 职责分离

| 层 | 责任 |
| --- | --- |
| Next.js 服务端公开读取 | 读取/验证节点快照，输出正文与公开壳；不向公共缓存注入用户态 |
| 后端正式公开/私有契约 | 定义 ID、能力、计数口径、版本/时间、字段缺失语义、真实状态码；公开和私有投影分开 |
| 前端生成客户端 | 从锁定的后端契约版本生成；提供受控的业务请求入口，不手写第二套业务 DTO |
| 浏览器共享协调能力 | 页面请求代次、合并批次、进行中去重、取消、超时、退避、内存状态及局部状态汇总；按实际需要在 `src/core/` 组织 |
| 主题组件/钩子 | 订阅内容 ID 对应状态并呈现；共用指标展示、状态提示和现有 ui 封装，不在每张卡片内复制 fetch/定时器 |

浏览器业务地址只从白名单公开配置提供，使用 `BACKEND_BASE_URL` 的公开含义；仅服务端 `[backend]` 的内部覆盖、凭据和节点配置不下发。开发可选代理不改变生产浏览器直连 FastAPI 和 CORS/Cookie/CSRF 验收。

### 调度规则

- 详情就绪后读取当前内容的公开统计；首页/列表只合并读取可视或即将可视的真实内容 ID，批次有上限，不按卡片逐个 N+1 请求。示例说说/示例评论不发送真实业务请求。
- 评论首批检查在首次接近评论区/用户进入该区域时触发；有公开快照时不为等待更新阻塞阅读。私有状态在已启用的登录/互动入口需要时获取，不因每个数字而查询会话。
- 页面切换取消无用读取；通过请求代次与资源 ID 检查抛弃旧结果。独立能力部分成功可独立呈现，不用一个全有或全无的总等待阻塞全部补充数据。
- 隐藏标签页不后台轮询；恢复可见、网络恢复、显式重试时按冷却策略合并检查。首版建议不引入每几秒轮询、SSE 或 WebSocket 来刷新计数。
- 只读请求有限退避；非法参数、权限拒绝或明确不存在不盲重试，429 尊重服务端重试提示。超时后清理定时器和订阅，不让失败无限刷请求。

### 缓存规则

- **正文、评论公开种子、菜单/站点配置快照没有时间 TTL。** 按事件、资源版本与激活机制更新；已收到更高版本不可见标记时，任何动态成功结果都不能复活旧正文。
- **动态统计是独立的补充读取。** 首版建议只在页面会话内保存成功结果并共享进行中的请求，不写入正文快照、不持久化到 localStorage，不凭一个指标变化重建整页 HTML。若将来增加短期缓存，其时效只适用于统计响应，不能变成公开内容的过期规则。
- 后续统计缓存键至少隔离站点/后端、内容 ID、契约/来源代次；适用时含语言。响应必须防乱序，统计自己的版本不等于正文 revision；计数合法修正/删评可以减少，不能简单取最大值。
- 用户态与公开统计分请求/分存储边界，使用私有不可共享缓存策略；账号切换、退出时清除旧用户状态。不能把携带身份的响应存入公共 SSR、CDN 或共享去重条目。
- 列表和统计只返回允许公开的记录；不可见 ID 的批量结果不能泄露其存在或互动规模。收到当前内容不可见信号时进入既有访问/撤回处理，不能只把眼睛图标藏掉后继续忽视权限变化。
- 公共评论异步成功只更新浏览器的对应展示；它不是把浏览器结果写回节点快照的同步捷径。正式节点同步仍走基线规定的服务端链路。

### 建议初值，尚未冻结

| 项目 | 下一步可采用的初值 | 边界 |
| --- | --- | --- |
| 补充只读请求超时 | 单次 8 秒 | 与导航 20 秒超时分开；超时后进入不可用/部分状态 |
| 自动重试 | 暂时性错误最多 1 次，约 1.5 秒加随机退避 | 后续恢复事件冷却约 30 秒；429 以服务端更严格提示为准 |
| 列表统计批次 | 每批不超过 20 个内容 ID | 由后端契约上限与实际首页容量共同确定 |
| 指标出现 | 约 160–220ms | 服从用户减少动态偏好，不用逐字计数动画 |

上表超时、最多一次退避和 20 个 ID 批次已用于本轮演示请求，淡入采用 200ms；它们是有界实现初值，不承诺延迟或容量。恢复前台检查冷却 30 秒，重连仍须请求成功；没有周期轮询。演示开关由后端加载器显式实现，真实计数和会话策略仍未冻结。

## 浏览量：读取与记账分开

展示浏览量是读取；增加一次浏览是写业务。**GET 统计、SSR、Next.js 预取、鼠标悬停预取、首页卡片曝光、图片预加载均不得增加浏览量。** 原 Argon 的 `get_header` 自增方式不能直接迁移。

建议首版用“有效内容详情访问次数”，不宣称独立访客数或实际读完人数。建议只有当前公开详情已就绪、标签页可见、正文区域进入视口并累计可见约 2 秒后才尝试一次记账；停留时间和文章/说说/普通页面适用范围仍待业务口径确认。默认建议文章/说说计数，普通自定义页面按需启用；首页阅读说说是否另算曝光需要另定义，不能偷偷混入详情浏览。

- 每次合格访问使用稳定幂等标识；同一次导航的重复挂载、重试、锚点切换和历史缓存恢复不能重复增加。浏览器临时状态不可用时也不能生成无限新标识。
- 建议刷新/返回在同一短会话去重窗口内不重复记账；窗口候选为 30 分钟，**尚待确认**。幂等请求去重与“相同访客重复阅读”去重是两件事，前者必须由服务端保证，后者需明确匿名身份和隐私保留策略。
- PostgreSQL 是权威源，原子更新与去重记录须能跨 FastAPI 进程工作。真实持久成功以数据库提交为准；不能 Redis 加一就承诺已永久保存，也不能浏览器先自增冒充权威结果。
- 记账失败不阻塞阅读，可与统计读取结果分别记录状态；没有记账成功不妨碍显示已成功读取的总数。超时重试沿用原幂等标识，刷新/关闭页面不要求补发历史积压事件。
- 匿名去重和防刷不能承诺绝对准确；优先短期、不用于跨站跟踪的标识，后端限流与机器人过滤另验收。不为了一个数字引入设备指纹或暴露完整访客记录。原始 IP/身份信息不进公开响应、URL 或普通业务日志。
- WordPress 历史计数是否采用主题 `views` 或插件值，要先只读盘点确定来源和新口径的衔接，再做显式迁移。本轮不导入、不重置计数，不把新统计开始于零伪装成历史总浏览量。

## 后续实施顺序与验收

1. **契约与语义：**确定浏览计数口径/历史衔接，发布公开统计读取契约、逐字段未知/不可用语义、错误码和版本策略；单独划清私有能力。同步前端生成客户端与兼容说明，不能直接修改 0.1/展示草案生成文件。
2. **第一阶段动态读取：**先接公开统计、共享调度和状态图标，验证失败隐藏/无位移/独立阅读。只有正式来源才显示真实数据；未上线的能力继续明确标作演示。
3. **计数与评论：**实现幂等浏览记账，接评论公开快照核对/分页/回复定位，补评论版本、撤回与计数一致性。涉及持久性、缓存及权限时执行对应基线 P0 和真实多进程验证。
4. **身份与写交互：**在会话/权限/CSRF/审核设计落实后接真实点赞、评论写入、待审核本人状态和解锁。站点统计小部件、实时推送、个性化推荐后置，不自动扩大当前范围。

完整业务后续验收清单（本轮实际覆盖子集见 [验收记录](../handoff/reader-requests-verification.md)，不得把演示检查当作全部完成）：

- 禁用 JavaScript 或阻断 FastAPI，合法已缓存的正文、标题、元信息、内部链接、分页与公开评论仍可读；本就不存在/缺少可用内容的页面返回合适状态。
- 快速/慢速/超时/断网/部分失败：未知指标隐藏，真实 0 可见，无页级阻塞与正文位移；主题色、窄屏、大字和减少动态符合现有规范。
- 快速切换文章、浏览器返回/前进、后台标签恢复、重复挂载：请求去重，旧响应不串页，不增加重复浏览，不刷状态图标。
- 每页请求次数有界，批量请求不含虚构 ID；一个接口失败不被另一个成功健康检查“洗成全成功”。未启动的能力不让图标永远停在加载中。
- 评论更新/新增/删除期间分页与锚点稳定，撤回评论和受限正文不回退；未知总数不是零，演示条数不进入真实统计。
- 切换账号、公开/私有缓存边界、跨源 Cookie/CSRF、服务器重启和多进程幂等；数据库提交失败不返回持久成功，已提交但响应丢失的重试不重复写。

原设计交付只检查文档。本轮已实施请求演示子集并重新进行运行验证；真实认证、持久记账、评论增量与完整节点同步仍须在对应功能落地时单独验收。
