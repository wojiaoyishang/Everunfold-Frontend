# 后台导航注册与扩展对接

版本：admin-navigation-4，2026-11-09。依据：用户提出系统菜单由前端注册生成，后端通过挂钩提供特定页面入口。前端注册基线已实现；下文后端挂钩和请求契约仍为后续设计，这里描述后台导航目录；独立插件运行时已由 ADR0079/0087 实现，不等于动态注册任意后台路由。

图标库 `/admin/icons` 和基础媒体库 `/admin/media` 使用已有系统页面注册，不手写第二套侧栏。这里是后台工作空间的导航注册；前台站点导航已由 ADR 0025 改为递归数据树，二者职责不同。代码页面「页面」清单的后续规则见 [页面注册设计](registered-pages.md)。

## 当前实现与职责

原实现是一份 `core/admin/navigation.ts` 静态数组，桌面侧栏、移动抽屉、面包屑与登录返回白名单共用它，并非逐个复制菜单 HTML。本轮把它改为确定性的模块注册表：

- `core/admin/registry.ts`：纯函数 `createAdminRegistry`，组装、校验、排序并冻结元信息；不依赖 React、请求用户或主题。
- `core/admin/builtin-module.ts`：内置 `core` 模块，登记工作台、内容、媒体库、图标库及工作空间分组。
- `core/admin/navigation.ts`：唯一装配点，显式导入可信模块后生成目录与查询函数；服务端代理和浏览器消费同一个构建产物。
- `themes/argon/admin/layout/navigation.tsx`：按分组渲染，语义图标映射到主题 SVG；桌面和移动复用。页名及当前项来自登记内容。
- `src/app/(management)/admin/**/page.tsx`：实际路由适配器仍由可信代码提供，页面组件归主题、用例归 core。登记菜单不会凭空产生页面或后端业务。

条目包含稳定且带命名空间的 ID、规范站内路径、名称、描述、语义图标与可选菜单分组/顺序。`menu: null` 表示只注册页面，不放入侧栏，适用于后续详情页。分组与条目按顺序和 ID 稳定排序；空分组不显示。当前都为明确静态路径，动态参数匹配尚未实现。

组装会拒绝重复模块/条目/路径、跨模块冒用 ID、未知分组、非整数排序、非规范路径；禁止外站 URL、查询/片段、路径穿越和编码路径进入登记表。编译得到的条目及数组冻结，不能由请求或后端响应修改全局目录。新增登记仍需提供真实路由并加入生产验证；业务权限始终由后端强制校验。

## 增加一个前端功能

1. 编写实际主题页面和必要的 core 用例，使用项目封装控件。
2. 内置功能登记到 `builtin-module.ts`；独立功能以可信代码导出自己的 `AdminModuleRegistration`，在唯一装配点导入。不依赖 import 的副作用向全局对象注册。
3. 分组可复用已有组，也可登记自己命名空间的组；相同排序按 ID 排列。详情页可不显示菜单。
4. 创建 Next 路由适配器，并核验 metadata/noindex、私有壳、登录回跳、直接访问权限。不能只写登记项后把 404 当作功能完成。
5. 桌面/移动导航、当前项与安全返回路径无需各写一遍。主题可替换视觉，但不定义权限。

## 后端挂钩：后续设计

建议后端模块在既有唯一入口 `router_init(ctx)` 的装配阶段登记一个“后台页面声明提供器”，具体方法名待扩展注册器实现时确定。装配只登记函数和可信声明；当前用户、语言和数据库会话在实际请求时传入，禁止存入全局初始化上下文。Worker/Scheduler 不调用该入口。

后续由后端发布经过鉴权的导航/能力描述契约（建议路径 `GET /v1/admin/navigation`，尚未实现），前端按该版本生成类型和客户端。描述至少考虑契约版本、启用配置修订、可用页面 ID；菜单名称、分组或排序可选覆盖需受前端约束。具体 Schema 由后端发布，本文不是第二份可编辑业务定义。

请求处理根据启用模块与当前用户权限筛选声明；前端只把返回的页面 ID 匹配到已经注册、已经打包的页面。后端关闭的扩展不展示；未知 ID、版本不兼容或缺失组件应隐藏对应扩展并记录可排查诊断。已有系统入口和整体布局不能因此崩溃。

“后端显示特定页面”意味着启用和配置已支持的页面能力，不意味着返回 HTML/JS、任意组件路径或任意 URL 让浏览器执行。全新插件 UI 需要安装可信前端适配器并重新构建；以后若有通用表单/列表，只接入受限、版本化的展示描述。该后台导航协议不授权执行远程脚本或生成万能路由；独立插件运行时另见 ADR0079/0087。

菜单可见性只是展示规则，不能代替接口权限：知道 URL、改 localStorage、篡改菜单状态都不能获得访问权。页面直接访问仍需校验，关闭插件后的旧地址安全降级；插件卸载不删除历史数据。

## 请求、缓存与错误边界

后续描述请求由 core 的会话级协调器管理，主题只消费展示结果。浏览器直连配置 FastAPI，身份确认后才请求；同会话可合并并发。退出、账号变化、后端地址变化或会话失效时取消未完成请求并丢弃旧结果，避免旧权限列表闪回。

描述属于用户态：响应使用 private/no-store，不进公开快照、SSR 共享缓存、浏览器长期存储或后台外观偏好。活动会话内如复用短期结果，必须绑定账号与配置/权限修订，重新鉴权后再验证；失效时不回退到上一账号的菜单。初次失败保留已注册系统壳，对需要远端确认的扩展保持隐藏并提供重试。接口仍独立校验权限。

浏览量、待审数量等可选徽标后续通过按页/功能注册的动态请求更新；不要把持续变化计数混入全局菜单登记或阻塞首次渲染。正式授权和版本契约发布前，不用演示会话或假权限填充扩展菜单。

## 已实现与待交付

已实现：可信前端模块组合、分组/排序、命名空间与路径校验、不可变目录、三处展示复用、既有安全返回路径复用，以及注册表测试。

待交付：后台导航专用的后端 provider 挂钩、导航/能力 Schema 与生成客户端，以及会话级描述请求。内容、媒体和插件的实际业务现已交付多个阶段，以 STATUS 为准，不再是最初准备页。规范决定见 [ADR 0022](../decisions/0022-admin-navigation-and-motion.md)。

## 系统子菜单（2026-11-09）

注册模块可声明 `branches: [{ id, group, label, icon, order }]`，页面的 `menu` 增加 `branch`。父级是分组按钮，不配置业务 URL；其 ID 必须属于模块命名空间，所属 group 必须存在。注册器拒绝重复、未知或跨分组引用，排序仍确定且目录冻结。

`adminMenuEntries(group, visible)` 先按权限保留页面，再组合父子条目；无可访问子项的父级不显示。原始扁平页面目录不变，因此直接访问、安全回跳和父级展开状态互不影响。

当前「系统管理」包含系统设置、运行与任务、邮件配置。桌面与移动共享组件，点击展开/收起，移动保持单个父级展开；进入子页自动打开所属父级。折叠桌面侧栏时点击父级先展开侧栏，关闭的子项设置 inert/aria-hidden；按钮声明 aria-expanded/aria-controls。动效服从减少动态设置，链接自己承载高亮，不再通过固定索引定位背景。

所有当前菜单采用有区别的语义图标，主题集中映射 SVG；后续新增菜单应检查与现有图标的区别及窄屏排布。邮件配置和后续发送路线见[指南](../development/mail.md)。
