# 后台界面与主题架构

版本：admin-ui-3，2026-11-01。状态：用户批准样例后，后台壳、独立外观和三个页面入口已实现；内容/媒体写入仍未实现。用户已明确“简洁专业、视觉可独立于前台、后台样式归于前端主题、目录整洁”。下文仍区分已实现范围与后续业务设计。依据见 [官方参考调研](../design/admin-reference-research.md) 与 [ADR 0021](../decisions/0021-admin-theme-and-workspace.md)。

## 1. 一个前端主题，三个展示区域

- 博客前台：继续服务阅读、动态背景与现有主题偏好。
- 通用登录：继续服务所有账号，保持当前紧凑登录页及 ADR 0020 的角色回跳。不能因开始设计后台又改成管理员专属入口。
- 管理后台：采用独立工作台布局、语义配色、密度与轻量动效。它仍是可信前端主题的一部分，不由 FastAPI 渲染模板，不拆成第三个应用。

“归于主题”指布局、样式、图标、展示组件和交互外观的所有权。权限、会话、请求、内容规则、存储与后端契约不由主题决定。切换主题不得改变业务含义或放宽权限。

建议主题提供 `public/auth/admin` 三个展示出口。首步仍接现有 argon 实现；需要第二个主题时，再加入小型可信代码注册表和明确的内置后台回退。可只定制 public、显式复用默认 admin。后台展示不完整的主题不能导致管理入口失效；不支持从数据库或上传文件执行任意主题代码。名称和接口需在实施时按真实组件收敛，不预建插件平台。

## 2. 信息架构

| 导航分组 | 内容 | 展示重点与边界 |
| --- | --- | --- |
| 工作台 | 继续编辑、待处理事项、最近活动 | 从真实业务状态产生；空态明确下一步，不制造统计数字 |
| 内容 | 文章与说说、分类/标签、回收站 | 同一内容模型的不同 type，不建两套 CRUD；发布状态和访问策略独立 |
| 媒体库 | 网格/列表、上传队列、详情与引用 | 对接后端媒体库；虚拟目录与物理路径分离 |
| 评论 | 筛选、上下文、审核与回复 | 权限来自后端；按接口就绪阶段上线 |
| 自定义页面 | 页面元信息、可信模板/正文 | 高中日记、关于等属于这里，不当成主题固定功能 |
| 外观 | 前台主题、共享菜单、站点展示配置 | 前台顶栏/侧栏共用一份站点菜单；后台操作菜单是另一套用途，不混为一份 |
| 设置/系统 | 站点、账号权限、媒体交付、系统状态、扩展 | 后续按实际功能及权限登记入口；首步不渲染一排不可用菜单 |

这是目标信息架构，不代表以上功能已经实现。当前开放工作台、内容和媒体库三个入口。工作台显示真实当前账户；内容和媒体库仅交付页面结构和明确的准备状态，搜索/筛选/新增/上传暂不可操作，不展示假文章、文件或统计。其余菜单未渲染。

后台导航的 ID、路由、标题键、权限条件由非展示层集中维护，侧栏、面包屑、手机导航消费同一来源；主题只提供图标映射和展示。不是站长任意改 URL 后就能得到一个管理功能。权限能力和业务字段以未来后端版本化契约为准，不把此表当 API Schema。

## 3. 视觉与交互初值

| 项目 | 建议初值 |
| --- | --- |
| 视觉 | 浅灰背景、白/深色中性表面、细分隔线，小面积强调色；阴影主要留给弹出层 |
| 桌面 | 侧栏 224px，可收为 72px 图标栏；顶栏 56px；主区边距 24–32px |
| 内容宽度 | 列表随可用空间伸展；长表单约 720–880px，正文编辑区另按阅读宽度约束 |
| 字体与密度 | 正文 14px、说明 12–13px、标题 22–24px；单行表格 48px、双行 60–64px |
| 控件 | 细边框，6–8px 圆角；一个操作区域只突出一个主要动作；图标使用项目 SVG |
| 配色 | 建议后台默认蓝色强调；token 内派生 hover/focus/selected，成功/警告/失败独立语义色 |
| 动效 | 150–300ms 的轻微反馈与布局过渡；独立轻量/系统/减少动态偏好；不强制延时后才允许操作 |
| 滚动 | 原生滚动；页头/表头按需要 sticky，避免页面、表格和卡片同时出现多层纵向滚动 |
| 移动端 | 主区 16px；侧栏换抽屉；触控目标约 44px、输入 16px，筛选折叠并显示已选摘要 |

断点建议从 1024px 和 768px 起验证，不作为硬性设备判断。窄屏列表优先保留标题、状态和主要操作，其他字段进详情；不能靠缩小字体塞进整张桌面表格。抽屉、菜单、焦点返回、Esc 与滚动锁定均复用封装。

## 4. 页面模式与组件

先做实际需要的壳与页面模式，再随业务增加组件，不提前生成空文件夹。

- `AdminShell`：唯一顶栏、侧栏、移动导航、用户菜单、内容出口。
- `AdminPageHeader`：标题、面包屑/描述及主要动作；避免每页重新调整间距。
- `CollectionToolbar`：搜索、筛选、排序、布局选项；批量操作在选中后出现。
- `AdminDataTable` / `MediaGrid`：消费明确的列/数据/状态，不用一个巨型万能表格兼任所有编辑器。
- `FormSection`：字段组、帮助、校验、提交/保存状态；底层继续使用 Button、FormField、Select 等封装。
- `EmptyState` / `RequestState` / `ConfirmAction`：统一空、失败、无权限、危险操作和恢复反馈。

以上名称是建议。共用控件维持原生语义与键盘操作；第三方控件如确有必要，先在项目 UI 层适配，不直接导入到页面。样式重用靠 token/variant 与组合，不复制一份原生控件来换颜色。

内容列表筛选/排序/分页保存在 URL，类型为既定 article/shuoshuo，正式枚举仍以后端契约版本为准。选中范围要明确“本页”还是“全部结果”；发布、撤回、删除不静默批量执行。点击标题编辑，行内其他操作避免嵌套链接。编辑离开提醒保留未提交修改；已保存只表示后端持久提交确认，协同 Y.Doc 与 ACK 约束不变。

媒体库对接 [媒体存储设计](media-storage.md)：显示原名、类型、大小、时间、可用状态、引用等；CDN/存储适配在服务层，界面不拼磁盘路径/桶名。改变 Base URL 后刷新交付地址派生数据，不改媒体 ID 或已存正文。上传/处理中与 ready 分开，失败可重试；删除默认可恢复，永久清理单独确认。

## 5. 目录建议与依赖方向

以下为已落地目录与后续按需扩展位置；当前未创建 core/theme、通用万能表格或未交付业务的空目录：

```text
src/app/
  layout.tsx                       文档级骨架、reset 与受范围限制的共享基础样式
  (blog)/                          公开路由与博客壳适配
  (management)/
    layout.tsx                     最薄公共边界，禁止在此装载整个博客皮肤
    login/                         通用登录入口
    admin/                         管理路由/元信息，共享 layout + workspace 适配器
src/core/
  auth/                            既有 Session/CSRF/权限校验生命周期
  admin/                           导航、认证协调、账户上下文与个人外观偏好
  config/                          仅服务端配置
  theme/                           接多个展示出口时再加最小可信主题选择器
src/generated/                     后端发布的类型、验证器和客户端
src/themes/argon/
  components/ui/                   既有共享控件与无障碍行为
  auth/                            已从 management 迁入通用登录展示
  admin/
    layout/                        后台壳、侧栏、顶栏、移动导航
    components/                    后台页头、列表工具栏、状态/表单模式
    pages/                         按已交付业务拆分的页面展示
    styles/                        tokens、layout、components、pages（实际四份）
  components/ + styles/            既有公开主题展示，暂不为改名整体搬迁
```

路由适配层组合 `core` 用例与主题展示；`core` 不导入 `themes`，生成契约不导入主题；主题消费数据/状态/回调，不决定请求认证、提交/缓存或权限事实。原 `management/admin-page.tsx` 已拆分并移除；`core/admin/use-admin-access` 协调认证/退出，复用 `useSession`，由路由层 `admin/workspace.tsx` 组合 `AdminShell` 与账户上下文，没有第二份身份缓存。

同一后台 layout 保持壳稳定，导航只换工作区；不同时套 BlogShell 与 AdminShell。公开 AppLink 的整文档导航事务不直接用于私有后台；后台需要封装后的 Next Link 适配与自己的未保存/加载反馈，普通站内链接仍保留可访问语义。

## 6. 样式隔离与偏好

已落实：根布局改为导入 `themes/argon/shared.css`（基础、公开外观、滚动条、封装控件）；博客特有 `argon.css` 由 `(blog)/layout.tsx` 导入。登录布局只导入 `auth/auth.css`、`scene.css`、`entry.css`，后台布局只导入 `admin/admin.css`。原 management 混合样式已移除。

已建立 `[data-surface="public|auth|admin"]` 区域边界与 `--admin-*` 语义 token。共享 UI 在 admin 根把所消费的通用变量映射到 admin token；新增组件不得读公开阅读偏好来决定后台字号、色调或滤镜。管理表单/错误/禁用状态也必须来自同一后台 token 表。

仅把 CSS import 移入路由组不够：客户端切换可能保留已加载样式，选择器和副作用仍须有范围。公开 `:root/body/html` 的染色、字体、滤镜、滚动条与 JS 动效须逐项限定到相应区域；真正中性 reset 可以共享。回归必须覆盖“前台→后台→前台”与直接刷新，不能依赖整页刷新恢复外观。

Portal 容器、popover、dialog、tooltip 也要放在后台主题范围内或显式复制展示上下文，避免移至 body 后失去 token。隐藏、浮层定位、焦点和打开/关闭动画复用原有控件，不绕过已修复的定位就绪门控。

三种配置分开：

| 数据 | 权威与保存 | 失效/切换规则 |
| --- | --- | --- |
| 前台站点主题、菜单与展示设置 | 后端持久配置，公开快照/可靠失效传播按既有基线 | 管理保存区分“主库成功”与“公开节点已确认”，不能把 toast 当全部生效 |
| 后台个人外观、密度、列宽、侧栏折叠 | 建议先浏览器本地版本化命名空间（站点/主题/账号范围）；将来账号偏好再用版本化 API | 与前台阅读键分离；切账号销毁内存私有查询；持久偏好不得含 Session、权限或正文 |
| 管理业务数据与身份 | FastAPI/PostgreSQL；浏览器私有短生命周期状态 | `private, no-store`，不进入公开共享快照；退出/失效/撤权清理，断网不以缓存身份授权 |

深浅模式已默认跟随系统，支持后台独立选择浅色/深色；普通访问前台不会把后台改成前台自选品牌色/纯黑/滤镜。当前仅保存 mode、density、motion、sidebarCollapsed，键为 `everunfold.admin.appearance.v1:<编码后的后端地址>:<编码后的账号 ID>`。先由后端确认账号再挂载偏好；损坏值回落默认，storage 事件同步同浏览器标签。主题目前只有 argon，未来多主题的偏好迁移另定，当前本地结构不是后端业务 Schema。

公开 palette/font/filter 选择器显式排除存在 admin 根的页面。根级公开动效禁用规则也排除 admin；后台使用独立短动效，默认轻量动效，可选择跟随系统或减少动态（ADR 0022）。admin 根映射共用控件变量，文档根使用同一后台配色/字号/滚动条，退出区域后规则自动失效；没有读取/改写公开阅读偏好来配置后台。CSS 的 `:has` 范围是实际边界，不能只依赖路由切换移除样式。

## 7. 请求反馈

- 首次确认会话有截止时间与重试；复核合并请求，不因 focus 反复延长超时，保留 ADR 0020 的修复。
- 列表初载使用局部骨架；后续筛选保留内容并标记更新中，较旧请求不能覆盖新条件。保留数据只作查看，需权限的操作按有效会话和请求状态判断。
- 保存/上传/审核在操作位置显示结果；失败保留输入并提供重试。401 回登录，403 显示无权限，网络错误不能当成功或“没有内容”。
- 后台以明确、简短文案反馈状态，不沿用前台颜文字横幅/游戏/烟花。无障碍直播只播报必要状态，减少动态不隐藏信息。

## 8. 分期与验收

1. 先拆后台壳与样式范围，保留真实登录、退出、直达/刷新校验及空工作区；不得出现双顶栏、自动刷新循环、0,0 浮层或无限确认动画。
2. 先完成一个内容列表的真实纵向流程，再推广共享页头、筛选、分页、空/错态；由后端发布类型与列表契约，前端生成后接入。
3. 实现媒体库与上传流程，复用列表状态与详情模式；真实上传确认、引用和 CDN 接口按媒体 ADR 验收。
4. 再扩展编辑、评论、自定义页面、外观设置与账号/系统；协同/发布可靠性在对应阶段执行原始 P0，不借界面完成宣称已实现。

每期至少验证：宽屏/平板/320–390px、键盘与焦点、深浅/减少动态、前后台往返隔离、会话有效/失效/403/超时、直接刷新、请求竞争与重试、私有数据未入公共缓存、已封装控件无漏用。真实变更还需契约/权限/事务对应验收。本轮已完成第 1 期及内容/媒体结构预备；实际执行和未执行项见 [后台验证](../handoff/admin-workspace-verification.md)，不能把结构页当成第 2/3 期业务交付。

## 9. 导航注册与动效补充（2026-11-01）

内置菜单已从单一静态数组升级为可信模块注册表，统一分组、顺序、稳定 ID、私有页面识别与主题展示。后端页面声明挂钩尚未实现，设计边界见 [后台导航注册](admin-navigation.md) 和 [ADR 0022](../decisions/0022-admin-navigation-and-motion.md)。

后台外观增加独立的轻量动效/跟随系统/减少动态偏好，默认轻量动效。此项按用户最新要求替代旧版只跟随系统的策略。页面区块依次进入、侧栏与导航选中项平滑变化、控件轻微反馈；慢导航保留当前页面并显示真实 pending。动画不等待数据以外的额外计时，也不保存或重播私有页面副本。
