# 前端扩展与组件注册预留

版本：frontend-extensions-5，2026-11-07。状态：**历史提案与当前实现索引**。2026-11-07已按ADR0077交付可信插件/主题自动发现、页面/短代码贡献和具名模型控件；实际API见[运行规范](frontend-plugin-runtime.md)及[开发指南](../development/frontend-plugins.md)。下文早期SDK提案不自动成为已实现接口。用户希望为组件、编辑器、部分页面与挂钩保留接口，尚未商定完整前端插件规范。本轮不交付运行时插件加载器，不冻结 npm 包格式/公共 SDK；下列能力名称是设计用语，不是可直接导入的代码接口。

相关：[当前后台导航注册](admin-navigation.md)、[设置设计](settings-design.md)、[ADR 0023](../decisions/0023-settings-and-extension-boundaries.md)。

实施更新（2026-11-01）：三个设置入口已复用可信页面登记，实际 `SettingsStore`/`FileSettingsStore` 在 `src/server/settings` 提供设置副本存储边界。完整组件/编辑器注册域、模块设置 Schema、通用运行时插件加载器仍未实现，不能把下面建议 API 名称当作现有方法。见 [ADR 0024](../decisions/0024-versioned-settings-delivery.md)。

用户细化（2026-11-01）：自定义代码页面通过可信注册出现在「页面」，后台只修改显式暴露字段与通用开关，不编辑源码。具体身份、路由、选项 Schema、权限和停用缓存边界见 [页面注册设计](registered-pages.md)；该注册域已按ADR0072实施可信静态清单、部署登记与组件版本守卫；独立源码页授权仅在隔离沙箱生效，不改变可信组件装配边界。图标库与基础媒体库页面已复用现有后台注册，各自页面/弹窗共用浏览组件；不把公开桌面弹出菜单与移动端展开菜单混成同一交互。

## 从已有实现继续，而不是平行建立第二套菜单

当前 `src/core/admin/registry.ts` 接受可信模块的分组/页面元信息，`navigation.ts` 是唯一装配点；路由仍由 `src/app` 的真实适配器提供。它不包含组件工厂、编辑器或缓存存储提供器。页面声明由pages1.5、插件setup及显式部署命令实现；本轮提供的是可信本地展示扩展，不是任意npm包/远端JS加载器。

下一次实现设置时优先复用这套确定性装配：页面登记引用设置分组 ID，主题负责表单展示，业务字段引用后端生成契约。为后续编辑器等扩展保留各自注册域，不把所有模块的任意对象塞进一个全局 register 表。

内置功能同样可作为第一方模块登记。可扩展不表示核心功能必须依赖一个可随时关闭的第三方插件；没有可选插件时，基本阅读、登录、权限检查、设置保存和默认磁盘快照能力仍应完整。

## 建议保留的注册域

| 注册域 | 示例 | 边界 |
| --- | --- | --- |
| 页面与菜单 | 设置页、媒体子页、插件工具页 | 共用现有页面 ID/分组/路径校验；注册元信息不等于生成 Next 路由或授予权限 |
| 页面插槽/组件 | 侧栏区块、文章尾部工具、后台卡片 | 已命名的 slot + 可信组件 ID + 配置引用；主题定义可用区域和布局约束 |
| 设置分组/控件 | 图像提供器的设置、扩展自身选项 | 后端声明业务 Schema/权限/公开性，前端匹配已打包控件；不执行后端返回的代码 |
| 编辑器 | Markdown 编辑器、后续块编辑器 | 共享草稿模型、权限和宿主保存链路，不能自建另一套正式正文事实源 |
| 正文渲染 | 公式、代码、自定义可信块 | 与编辑器分开；有公开服务端/只读渲染策略与未知版本回退，不让 SEO 正文只在浏览器出现 |
| 用户态动态请求展示 | 当前页面同步状态、扩展计数 | 复用已有按页面请求注册与插槽；离开页面取消/注销，身份切换清理 |
| Node 服务能力 | 公开快照存储适配器、框架缓存适配器 | 只在服务端装配；配置路径/凭据/Node 导入不得进入客户端包 |

前台、登录、后台展示仍属于主题分区。插件可以提供功能组件，通过主题的控件/语义变量适配视觉；权限、业务请求、存储与任务不放进主题。主题只是样式和布局的所有者，不成为业务插件的依赖事实源。

## 装配和生命周期

建议静态清单描述稳定命名空间 ID、扩展协议版本、兼容应用/数据 Schema 范围、依赖及所需能力。组件实现由代码显式导入；懒加载只指加载部署包内已知模块，不从数据库脚本路径/远程 URL 导入可执行代码。

- 公共元信息、浏览器组件入口、服务端入口分离；服务端模块加 server-only 边界，不通过一个 barrel 文件误导出到浏览器。
- 构建/进程装配时检查重复 ID、依赖/循环、版本、路由冲突、未知插槽与多个独占提供器，按稳定顺序构建不可变表。缺少必须能力应明确失败，不能悄悄换一个驱动。
- 页面/会话的激活状态按请求或会话派生，不修改全局登记表，不把当前用户、语言、数据库 Session 放在初始化上下文。
- 不为每个 SSR 请求重复注册，也不靠 import 副作用执行初始化。前端页面挂载和用户态 hook 有清理函数；取消旧请求，防止退出后迟到响应复活私有信息。
- 单一能力（默认编辑器/存储驱动）显式选择一个提供器；多项插槽按 order + ID 排序。不依赖插件导入先后“最后写入覆盖”。
- 安装/升级代码走构建部署，启停已安装的可选展示组件可以是合法配置；不承诺热安装。停用不自动删除设置、正文块或媒体；数据迁移由明确部署步骤执行。
- 同进程可信插件不是安全沙箱。命名空间/能力声明约束接口与维护边界，不能声称阻止恶意 Node 代码访问宿主；第三方代码仍需受信任和审阅，首期不设计不可信代码执行。

后端通过 `router_init(ctx)` 登记已信任 provider，实际请求再按身份/权限返回已知页面/能力 ID。双方版本不匹配或出现未知 ID 时，保留基本壳并给管理员诊断；不要拉取远端脚本补齐组件。浏览器内菜单隐藏也不能代替后端 API 授权。

## 编辑器的预留边界

宿主负责取得经过鉴权的草稿、草稿版本、媒体服务、保存/发布动作以及会话生命周期。编辑器负责输入、选择、撤销和受控变更回调；不能在控件内部偷偷调用另一条写库流程。

- 沿用整篇草稿一个 Y.Doc、有序 JSONB 块列表和稳定块 ID；UI 编辑器选择不改变内容类型 article/shuoshuo，也不把每个块改成独立发布单元。
- Markdown/HTML 编辑器与未来块编辑器应通过明确可逆或显式提示的转换适配；禁止不支持的内容被空字符串覆盖。
- 服务端稳定块 Schema、访问策略和持久 ACK 仍归核心/后端；ACK 必须等 PostgreSQL 提交，不能因插件本地渲染完成而显示已保存。
- 扩展定义的新块类型需同步后端 Schema/迁移与公开只读渲染器。旧节点无法识别时拒绝激活不兼容快照或使用经协议允许的安全只读回退；不能执行存储的脚本。
- 编辑器懒加载/失败只影响编辑区域；有错误提示/重试且保留未保存草稿，不让整个后台白屏。插件卸载后历史块保留原数据，未知块只读显示其状态。

第一批设置表单不需要把整套编辑器接口实现出来。先在架构上禁止表单/页面依赖某一编辑器的内部实现，等编辑用例落地时确定实际接口与验证样例。

## 挂钩要区分查询、展示和可靠副作用

| 类别 | 执行方式 | 错误策略 |
| --- | --- | --- |
| 展示插槽/设置分组提供 | 从已装配注册表确定性取值，带明确输入/输出类型 | 可选组件局部回退并记录，核心操作仍可用 |
| 公开元数据贡献 | 结构化片段提交给核心合并、转义、去重和访问校验 | 不允许覆盖强制 noindex、权限或加入重复 canonical/可执行脚本 |
| 界面生命周期/用户态请求 | 浏览器范围，绑定页面/会话，定义注销与取消 | 限时、可取消，不把 observer 当事务成功条件 |
| 保存校验/快照激活 | 核心有序流程调用明确能力 | 关键校验失败拒绝保存/激活，不可当作可忽略监听器 |
| CDN 清理/通知等外部副作用 | 后端提交可靠事件，Worker 具名任务执行 | 幂等、重试、失败记录；不由浏览器 hook 或进程内广播保证可靠性 |

首期只增添有实际消费者的命名挂钩，不预建“任何函数前后都发事件”的通用总线。纯展示的插件失败可以隔离，持久化/权限失败不能吞掉后继续报成功。

## 缓存：统一门面与可替换实现

建议业务组件依赖 `CacheCoordinator` 这一类核心服务边界，存储实现走专用提供器；名称尚未冻结。调用顺序概念如下：

```text
页面 / 公开数据读取
  → 核心校验：权限范围、source_epoch、修订、撤回标记、完整性
  → 公开快照存储提供器：读写、原子提交、持久化、恢复
  → Next.js 专用适配：渲染缓存、标签失效、版本协调
```

“都经过统一接口”是合理方向；“所有正确性逻辑都由可选插件决定”不采用。核心固定掌握：

- 公开与用户态隔离、无 TTL 公开快照、旧版本不可回流、撤回标记优先、读取兼容性和完整性检查。
- 写入/校验/激活/渲染预热各阶段状态，成功响应必须对应真实完成的阶段。
- 并发/取消/幂等与资源版本比较；存储返回值经核心验证，不能因驱动说成功就省略持久性要求。

公开快照提供器需暴露足够的原子性/持久性语义：读取已提交版本、暂存并校验、以预期版本原子激活、持久撤回标记、列出可回收旧代。这里是能力要求，**不是只设计 get/set/delete 后宣称能保证跨进程一致性**。第一方文件实现可以通过相同边界，成为默认必需能力；替换时验证相同故障矩阵。

Next.js 派生缓存适配器与公开快照提供器分开：前者受锁定框架 API 和缓存标签约束，后者持久业务公开数据与版本。CDN 清理属于后端外部任务适配，浏览量临时缓存属于动态请求层；这些不是一个可以混放会话与公开正文的“大缓存”。

存储切换须验证目标位置、迁移完整代际、保留最后有效版本和撤回水位后再切换，并保留明确回退方案；禁用当前唯一存储驱动应拒绝。具体方式/容量留节点服务端配置，是否提供后台远程策略管理另行商定。首次仅预留边界，不注册没有实现的 Redis/对象存储/CDN 选项。

## 实施目录建议与门槛

以后有实际代码时可逐步扩展 `src/core/extensions/`（清单/装配和纯元信息）、`src/core/cache/`（核心流程/提供器协议）、单独 server-only 适配目录；主题内继续放 admin 表单和组件。不要先为每个候选能力创建空目录或巨型单文件注册器。

设置第一期只需要页面登记、共享字段控件和设置分组装配；业务 Schema 后端发布，前端生成。后续新增编辑器或缓存实现时再落实对应协议版本与真实替换样例。最低检查包括：重复 ID/路由冲突、前后端兼容、SSR/浏览器入口隔离、未知扩展降级、停用保留数据、权限切换/请求取消，以及缓存多进程/断线/重启/撤回的 P0 验证。
