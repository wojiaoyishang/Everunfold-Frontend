# 站点、主题与系统设置设计

版本：settings-design-1，2026-11-01。状态：**讨论提案，尚未实现设置管理页面、写 API 或新配置字段**。用户已明确要求区分主题/站点设置、预留扩展接口；配置存放方式仍待商定。[盘点依据](../design/settings-reference-inventory.md)、[扩展提案](frontend-extensions.md)、[ADR 0023](../decisions/0023-settings-and-extension-boundaries.md)。

## 当前事实

- 后端已有 `app/modules/content/models.py` 的 `SiteSettings`：单例 `site_settings.data` JSONB、`source_epoch`、`generation`；公开 `/v1/site` 按 `SiteDTO` 输出且统计实时派生。它是公开阅读初始实现，尚不是完整设置管理。
- 前端已有公开 Site 数据、主题参考补全、个人阅读/后台偏好，以及三个可信后台菜单注册项。没有通用插件加载器、设置编辑或节点配置下发接口。
- Next.js 当前读取 `[cache].directory/current.json`，文件大小检查后解析完整公开快照。`React.cache` 用于读取复用，不能据此声称有定时过期、分布式缓存或发布接收器。
- 配置加载器已有目录/大小/并发等字段，但仅声明不代表运行限额全已启用；`cache_receiver=false`，完整可靠投递/撤回/激活仍未交付。
- 本提案不新建另一份站点事实库，也不改变原始 v2.11/v0.14、现有配置优先级或运行行为。

## 设置的归属

| 类型 | 负责什么 | 建议权威存放位置 | 公开范围 |
| --- | --- | --- | --- |
| 站点设置 | 身份、公开资料、菜单数据、区域/阅读规则、SEO、讨论业务政策 | PostgreSQL；从现有 SiteSettings 显式演进 | 只发布经过白名单筛选的公开投影 |
| 主题设置 | 当前主题的布局、表现、展示默认值、组件顺序/开关 | PostgreSQL，按 theme_id 与配置 Schema 版本分区 | 当前主题的合法公开设置投影 |
| 插件业务设置 | 对应模块的业务政策、可信能力选择 | PostgreSQL，模块命名空间和版本隔离 | 每字段声明，缺省私有；不是整包发送浏览器 |
| Next.js 节点运行配置 | 节点身份、后端连接、缓存存储实现/目录/容量、安全限额 | 首期节点服务端 TOML + 环境变量密钥引用 | 后台授权只读状态；公开页面不得获取文件路径/凭据 |
| 后端运行配置 | DB/Redis、Cookie/CORS、内部认证、Worker、媒体存储路径和提供器 | 后端 TOML + 环境变量密钥引用 | 后台按权限脱敏展示 |
| 个人偏好 | 阅读颜色/字体/动效、首页筛选、后台密度与折叠 | 沿用浏览器个人偏好存储 | 仅当前使用者，不写公共设置/共享快照 |

同一字段只有一个权威来源；表格不是“任何文件、数据库都可以同时覆盖”的约定。后台系统页建议先显示来源、实际生效值、节点/版本、最近报告时间和是否需重启，暂不开放远程修改路径或密钥。

## 两个首要设置页面

### 站点设置

建议后台入口为「设置 / 站点」，通过现有可信菜单注册表接入。具体路径/页面 ID 与 API 字段由实施契约确定。

| 分组 | 目标字段/操作 | 第一批范围 |
| --- | --- | --- |
| 基本资料 | 站点名称、简介、Logo/图标、公开作者昵称/头像/简介、社交链接 | 优先接已有 Site 数据；媒体选择依赖真实媒体库，期间不伪造上传成功 |
| 导航与公告 | 一棵有稳定 ID 的多级菜单、名称/目标/图标/顺序/启用，公告及链接，页脚版权/备案/链接 | 顶栏、侧栏、移动菜单共用；不因登记菜单自动创建页面 |
| 阅读 | 首页 article/shuoshuo 默认范围、公开列表每页数量、摘要默认长度、允许的分类范围 | 与真实公开查询能力一起接入；个人首页偏好只覆盖自己的浏览 |
| 区域 | 默认语言、IANA 时区、日期/时间格式 | 存储/接口 UTC 不变；格式值与 Python/浏览器共享明确语义，不复制 PHP 格式串 |
| SEO | 首页标题/描述、标题模板、分享默认图、规范域名状态、索引策略 | 优先统一已有 metadata；域名变更和 Sitemap/robots 必须连同公开发布链路验证 |
| 讨论与账户 | 评论开放/审核/必填、访客权限、编辑期限、私密模式、回复通知、注册政策 | 后续能力就绪再启用表单；未实现功能说明状态，不给可保存但无效的开关 |

站点资料属于站点，即使换主题也保留。主题的 Banner 可以引用站点名，或设置该区域的展示标题；明确标为展示覆盖，不能把覆盖值写回站点名。公开统计是派生数据，不提供手工填文章数/浏览量的输入框。

### 主题设置

建议「设置 / 主题」显示主题名/版本与分区导航，保持现有后台简洁样式。以下是目标清单，按已实现渲染能力分批开放，未具备的布局/能力不出现假选项。

| 分组 | 目标设置 |
| --- | --- |
| 全局外观 | 默认主题色、允许访客自选、默认深浅/系统模式、纯黑背景、字体/字号、卡片圆角/阴影、页面宽度 |
| 封面与背景 | 封面标题/副标题、尺寸、图片/视频媒体引用、日/夜背景、遮罩/透明度、默认播放；暂停与低动效策略沿用现有用户选择 |
| 顶栏与侧栏 | 顶栏顶部透明/滚动状态、Logo 显示、侧栏组件开关/顺序、作者卡片/统计展示、菜单所用位置 |
| 列表与说说 | 卡片样式、头图比例、摘要长度覆盖、元信息显隐/顺序、说说折叠与媒体布局 |
| 正文与阅读工具 | 头图位置、目录/序号、分享/赞赏入口、上下篇、推荐展示数量、过时提示、代码/公式渲染器皮肤与图片灯箱 |
| 评论与搜索外观 | 评论折叠/分页或连续阅读、头像/表情展示、搜索筛选控件展示；不越过站点允许范围 |
| 动效与辅助 | 默认动效、惯性滚动、图片显现、工具列显隐；保留失败横幅与无障碍约定 |
| 登录与后台外观 | 同属主题但按 public/auth/admin 分区；管理员个人的密度/动效选择不变为全站强制值 |

背景、Logo、头像、分享图等业务媒体用稳定媒体 ID 和后端发布映射，沿用 [媒体存储设计](media-storage.md)。前端构建图标/字体仍属于部署资产。页脚与附加文案采用安全文本/受限结构，不照搬任意 JS/PHP/HTML 注入。

所有控件继续通过项目封装组件；插件控件也先适配主题控件契约。保留键盘、焦点、错误提示与减少动态模式。页面分组/表单渲染器复用，业务字段不得复制成前后端两套 DTO。

## 配置存在哪里：推荐分层方案

**首期推荐：业务设置入数据库，运行配置留本机，系统页先只读。**

- 站点/主题设置通过 FastAPI 保存 PostgreSQL；Next.js 读取经过验证且版本一致的公开配置副本。后端离线继续使用仍允许公开的最后完整配置；未同步过的节点给出配置未就绪状态，不从空对象猜造站点。
- Next.js 缓存目录、存储驱动 ID、容量/并发上限放节点服务端配置。相对缓存目录继续按当前加载器的项目配置根解析；不要顺手改成后端 Uploads Path 的相对路径规则。
- DB/Redis 连接、内部地址/Token、媒体 uploads_path、提供器凭据保持各服务部署配置。后台显示脱敏来源/是否生效，不把配置文件作为可任意编辑的网页文本。
- 媒体 Base URL 的权威来源首期也沿用后端部署配置和 [ADR 0017](../decisions/0017-media-storage-and-upload-lifecycle.md)。以后改 CDN 时显式发布资源映射并刷新受影响快照，不将 DB 中每条媒体的 URL 当独立配置修改。
- 可调的动态刷新/页面派生缓存策略，首期按节点服务端配置定义；系统页可展示。将来若要在后台修改，**另设中心策略**，必须做下面的 desired/effective 确认，而不是静默改本机 TOML。

若之后确实需要网页管理多个 Next.js 节点：数据库保存非敏感的期望策略与策略版本，按现有稳定 FRONTEND_NODE_ID 下发，节点经过本地允许范围验证后报告实际应用版本、失败原因或待重启。界面分开显示「已保存」「待应用」「已应用」；本机配置作为不可放宽的资源/安全上限。驱动更换、数据路径迁移、密钥与模块代码仍走部署流程。中心策略缺失时用本地基准；已经应用过时用本地最后有效策略副本；非法/超上限新策略拒绝整批应用并报告，不能偷偷截断数值。这是后续提案，本期不建立该控制链路。

### 规范域名的单一来源

现有 `PUBLIC_SITE_URL` 是 Next.js 服务端配置。若未来让「站点设置」维护规范公开域名，需显式迁移：初始化时导入已确认的部署值，以后已激活的站点配置成为 canonical 权威，旧环境项只作引导/一致性校验，不再覆盖它。第一批可以先只读显示域名，避免保存表单后 canonical 仍被环境变量覆盖。`BACKEND_BASE_URL`、节点回调地址、媒体 Base URL 与公开站点域名职责不同。测试节点限制索引，不能凭请求 Host 生成生产 canonical；不由改域名自动修改内容路径或生成历史重定向。

## 缓存有效期需要分层

| 层 | 建议可以配置什么 | 必须保持的行为 |
| --- | --- | --- |
| 公开文章/评论/列表/搜索文档与配置快照 | 存储提供器、磁盘目录、容量、并发；将来可见的版本/追赶状态 | **无时间 TTL**；由可靠变更事件替换/撤回，不因到期自动删除或强制回源 |
| Next.js 派生渲染结果 | 经过适配验证的重建/失效策略、存储方式、必要时页面缓存有效期 | 可从已激活本地快照重建；配置/主题版本参与一致性判断，已知撤回不走 stale 回退 |
| 浏览量等动态展示数据 | 新鲜时间、重试退避、最大请求时长、允许显示旧值的窗口 | 初始失败隐藏字段，不伪造 0；可显示的旧值须区分陈旧；不进入正文事实层 |
| 登录、权限与后台数据 | 请求超时/短期会话内去重等 | private/no-store，不进公共快照、共享渲染或浏览器持久身份缓存；后端当前权限为准 |
| 浏览器个人偏好 | 已有偏好版本/迁移与恢复默认 | 不决定服务器共享页面的个性内容，也不作为后台设置事实源 |

「刷新间隔」不是「公开快照保留时间」，请求超时也不是 TTL。首期不新增一个名叫“全站缓存过期时间”的统一数字框。原始 Q34/Q69 已确认公开缓存无 TTL 与撤回规则，本轮请求先解释不同层，不擅自推翻。

Node-only 缓存适配器可以更换磁盘/共享存储实现，但必须满足节点离线可读、原子激活、版本比较、重启恢复和撤回标记要求。纯内存或仅依赖家庭后端在线的远端存储不能作为唯一公开快照源。Redis 适合派生/临时缓存候选，不能直接把已有 Broker/通知实例等同可靠快照仓库。旧代清理由核心按引用/激活/撤回状态决定，禁止清空 `.next` 或删除唯一仍可用快照当“刷新”。

当前锁定 Next.js **16.4.3**。已对照随包文档与官方文档：普通增量缓存的 `cacheHandler` 与 `use cache` 的 `cacheHandlers` 适用范围不同；`cacheLife` 还依赖对应 Cache Components 配置。本项目当前没有启用这些自定义适配。实施时由 Next 专用适配层接入，不能把它们当同一个通用存储接口，也不把框架默认 TTL 套到业务快照上。

## 保存、发布与失败反馈

沿用 [已有主题配置边界](theme-configuration.md)，下列为未来设置功能的验收条件：

1. 前端用后端版本化 Schema 生成契约。私有读取带真实鉴权；写入验证权限、CSRF、字段白名单、类型/范围、当前配置修订号。版本冲突保留编辑草稿并提示重新比较。
2. PostgreSQL 一次事务写配置、审计与可靠事件；失败一起回滚。统计、secret 和不可编辑运行字段不能从请求绕过表单写入。
3. 新公开配置只包含可公开字段、受控菜单/组件 ID、媒体引用与兼容版本。不发布编辑表单全集；私人通知邮箱、审核词表、上传路径和提供器凭据留后端。
4. Worker 定向通知节点，按真实 socket 来源 IP AND Token 再鉴权；配置和依赖媒体/渲染器完整后原子激活。重复、乱序、旧 epoch、重启恢复按现有缓存协议处理。
5. 页面显示「保存成功，前台更新中」与「节点已应用」的区别；重试投递不重复保存一版。失败时保留表单及明确状态，不能用成功 toast 代替公开生效确认。
6. 顶栏/侧栏/移动菜单/metadata/列表/已预取路由同代更新。新增已知撤回优先阻断旧内容，不等普通刷新完成；离线节点或外部 CDN 尚未收到不能宣称全部清除。
7. 预览与恢复默认仅修改编辑草稿，点保存才生效；取消不写入公共配置。可编辑字段缺省、显式空值/false 与“恢复默认”分开；换主题/移除扩展保留原配置与历史数据。

数据库演进建议按“scope + owner/module + Schema 版本 + revision + values”划分配置聚合，关系资料仍用业务模型；不要一项一项任意 Key-Value 写入，也不要把所有秘密和公开外观混成一个 JSON 回传。具体表/迁移、权限名和端点由后端下一步发布，当前不冻结第二套 Schema。

## 实施顺序与验收

1. 先商定本地运行配置与中心策略的边界；冻结第一批可保存字段。后端从现有 SiteSettings 显式迁移，发布读写/公开投影契约和版本约定。
2. 先交付站点资料/共享导航/基础 SEO 与已有主题能力的默认值。实现真实保存、可靠发布和节点确认后再称“前台可配置”；单纯表单原型须明示。
3. 增加两个主题内后台页面及共享表单/预览/脏状态组件，通过现有菜单注册。缺少媒体上传、评论政策、账户注册等后端能力时，延后相应可编辑项。
4. 系统设置先只读：Next.js 节点的缓存方式/来源/已应用版本；后端展示版本、已实现能力、数据库/Redis 最近检查、媒体提供器和任务状态。没有检测接口的项显示未提供，不能造“正常”。连接地址/路径按授权脱敏，secret 永不回显。
5. 实测保存冲突/重试、事务失败无半成品；前后台权限与多用户隔离；公开配置无私密字段；空菜单不复活默认；访问者偏好不被重置；切主题仍保留站点/SEO。
6. 缓存变更必须做真实多进程验收：新旧版本乱序/重复、激活前崩溃、重启、后端离线有/无缓存、节点失联再恢复、撤回先到与旧正文回流、配置和媒体不同步、浏览器预取后导航。文档或构建成功不能代替。

目前未执行上述新功能验收，因本轮没有修改运行实现。
