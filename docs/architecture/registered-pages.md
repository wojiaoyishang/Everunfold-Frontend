# 内容链接选择与自定义代码页面注册

版本：registered-pages-design-1，2026-11-01。**状态：用户已确认产品边界；下面的契约形状是待实施设计。** 本轮菜单和图标库已交付，本文涉及的新端点、页面管理路由、注册持久化与代码页面运行链路尚未实现。

## 页面来源与后台操作

「页面」应同时列出数据库内容页面和代码注册页面，明确标记来源，避免编辑能力混淆。文章、数据库页面沿用正式内容模型；代码页面由仓库或可信扩展中的代码实现，通过受控注册清单暴露。

代码页面允许的后台操作只有：启用/停用、通用展示与 SEO 选项，以及作者明确暴露的设置字段。没有代码编辑器、源码上传、任意模块路径/URL 输入或数据库脚本执行。后台未暴露的内部参数不自动变成可编辑字段。未安装、版本不匹配或已停用的页面显示明确状态，保留原设置，不把它伪装成正常可访问的页面。

## 注册清单（工程提案）

| 字段 | 职责 |
| --- | --- |
| `id` | 含模块命名空间的稳定 ID，例如 `campfire.links`；改标题不改变身份 |
| `version` / `schema_version` | 页面实现与暴露选项的版本，用于兼容和迁移判断 |
| `title` / `route` / `icon` / `order` | 「页面」列表与可选导航条目的元信息；注册不自动插入前台菜单 |
| `options_schema` / `defaults` | 明确字段、类型、约束、默认值、公开性；未知字段拒绝，不存整段任意 JSON |
| `controls` | 对应项目已封装控件的标识；不接收可执行模板或 HTML 片段 |
| `capabilities` | 需要的服务端、浏览器和插槽能力；声明不授予权限 |

页面组件工厂留在可信代码装配层，和清单分开；Node-only 实现不能通过公共导出进入浏览器。现有 `createAdminRegistry` 负责后台菜单元信息，需扩展独立的页面注册域和路由解析器，不把“注册列表里有记录”当作 Next.js 路由已经存在。构建部署时拒绝重复 ID、保留路由、冲突路径、循环依赖和不兼容 Schema。

部署清单须经可信发布链路登记到后端，前端浏览器提交的 Schema 不能成为验证权限的依据。若使用节点内部登记接口，仍验证真实 socket 来源 IP **AND** Token，并绑定稳定节点 ID/发布版本；具体路径在正式后端契约发布时确定。多节点装配版本不一致时要显示状态并拒绝把缺失实现的节点标成可用。

## 选项、启用状态与缓存

PostgreSQL/FastAPI 保存启用状态、公共选项、私有选项与修订；代码和部署密钥不入业务设置表。每次更新带 expected_revision，校验、业务记录、审计和可靠事件同事务。仅白名单公开投影进入 Next 设置副本，私有字段不得进入 SSR 公共缓存。

停用属于可访问性变更：发布带修订的停用标记，节点确认后不得再用旧公开页面回退；应遵守既有撤回/转受限规则。离线节点的生效边界和故障策略必须在实现时一并验收，不能只隐藏后台菜单。卸载代码保留数据；重新安装时按 Schema 迁移后恢复，不能让默认值覆盖旧配置。

## 菜单链接选择（工程提案）

菜单编辑器保留手填链接，并增加一个共享资源选择器，支持文章、数据库页面、已启用代码页面。后端提供鉴权的分页/搜索/预览接口，只返回操作者有权查看且符合链接条件的目标；不为了预览泄露草稿正文、私有选项或服务器路径。当前的 `href` 输入仍是唯一已实现入口。

建议选择记录保存 `kind + target_id`，辅以已解析公开路径；禁止把可变标题或列表索引当成身份。目标类型区分 URL、文章/内容页面、注册代码页面。路径变更后重新投影导航，目标失效时显示无法解析的状态，不自动建立历史永久重定向。接口应返回标题、目标类型、可用状态、公开路径和可选缩略图，不要求整篇正文。

预览选择器与后续「页面」列表复用同一目录/权限解析服务，避免各自维护目标列表。正式端点与字段必须先由后端发布版本化契约，再生成前端类型和客户端；本提案不是第二份可调用 API 定义。
