# ADR 0165：配对凭据读取与前端发布地址归属

状态：已实现。日期：2026-11-16。版本：ADR0165-1。

用户已导入 Base64 仍遇到 inventory_token_missing，并要求后端沿用 setup 配对字段，不再重复填写前端公开地址。本决定替代 ADR 0164 的公开地址必填交互及 ADR 0151 的手工登记来源流程。

## 凭据读取

前端 YAML 私有环境与解析结果原先通过模块内 WeakMap 关联。生产 ESM 入口与 CommonJS 配置加载器产生两份映射，使已保存令牌在上报进程中不可见。改用配置对象上的非枚举 Symbol.for 属性跨加载方式保留关联，不注入进程全局，也不进入 JSON 或对象展开。循环重新加载 CONFIG_FILE；凭据变化或上次失败会立即重新尝试。接收器的身份和令牌仍在启动时固定，更改后需重启前端。

日志增加 config_file 和 token_env，帮助检查挂载、令牌引用和外部环境覆盖，不输出令牌值。升级修复需要重新构建前端产物一次，日常配置更改无需编译。

## 配对与发布地址

后端 /_nodes 显示节点 ID、内部接收器 URL、私网 HTTP、双向令牌状态、实际内部来源及启停。令牌和来源规则沿用 setup，仅在 setup 修改；浏览器不返回令牌值和引用。登记允许没有发布 URL，启用仍要求绑定；成员、审计、修订与同步计划同事务。启用节点须先停用才能更换接收器。数据库已有绑定优先，重复导出相同凭据保留在线修改的接收器。

前端的 PUBLIC_SITE_URL 通过扩展上报的 X-Everunfold-Public-Url 头传递。后端先验证真实 socket 来源、已登记且启用的节点和对应令牌，再校验 HTTPS 或回环 HTTP 根地址，拒绝用户信息、路径、查询和片段。事务内复核授权绑定，仅更新当前节点及审计修订。Origin、Host 和转发头不能登记来源，未知节点不能自助启用。

头缺失时兼容旧前端并保留地址；空值明确清除地址。尚未上报的节点可内部同步，但没有浏览器来源许可。更改或停用会撤销该节点旧来源；静态 CORS 规则独立生效。前端发布 URL、后端发布 URL、监听与接收器地址各司其职。

Settings 契约升为 1.46.0，NodeRegistration.base_url 缺省为空，监控返回仍为字符串。部署配对字段只在独立控制台返回，不进入共享管理员监控。先升级后端，再构建启动前端；无需数据库结构迁移。

## 验证

独立 ESM Node 回归复现并修复缺令牌错误，覆盖轮换、发布地址头及脱敏。隔离 Uvicorn、PostgreSQL、Redis 和 Node 验证真实 setup Base64 导入、上报入库、地址和 CORS 更新、停用、错误令牌和伪造来源拒绝、修订冲突及重复导出。浏览器核对表单、取消回焦和无公开地址保存。具体检查结果及限制见两仓库 STATUS。
