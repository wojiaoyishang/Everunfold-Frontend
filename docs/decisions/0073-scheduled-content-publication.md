# ADR 0073：一次性定时发布与阅读进度提示

状态：2026-11-06，依据本轮用户明确要求实施；验证结果以交接状态为准。

## 决定

文章与说说共用定时发布：编辑器选择未来时间，点击「安排发布」创建检查点并登记一次性计划。排期截取已持久确认的协作序号及本次显式源码修订，与当前草稿后续编辑分离；不改变已有公开版本。「保存版本」本身不会安排发布。显示日期仍是显示属性，密码下的「定时开放」仍是访问策略，两者不替代定时发布。

计划存 PostgreSQL 草稿行：执行时间、捕获修订及私有完整快照，同一篇最多一个有效计划，重新安排替换旧计划。稳定操作 ID 保证重复请求返回原回执。取消、立即发布、撤回、回收及整组回收同事务清除计划；恢复回收不复活旧计划。排期快照参与媒体引用保护，用户删除历史检查点不会使已安排正文丢失。密码哈希仅在私有计划内，不返回接口，不进入队列、公开快照或日志。

独立单活 Scheduler 只投递无正文的具名周期 tick，Celery Worker 扫描已登记且到期的计划。过期 tick、重复消息、多个 Worker 与重启由 PostgreSQL 事务串行化；公开内容、搜索、完整不可变 Release、可靠投递意图、计划完成及审计一起提交。数据库失败回滚后保留待执行计划；停机时已登记的单次执行在恢复后补执行，不把它视为未登记的周期漏跑。不承诺秒级准点，实际受轮询、合并与服务可用性影响。

执行时复核原发布人的当前权限及本人/翻译组范围；API Key 排期还复核原 Key 的到期、撤销、应用及权限上限。当前合并锁有效时等待下次 tick，不修改最新版，也不阻挡其他文章。路径占用、权限失效或正文/媒体不再有效时停止计划并显示固定错误类别，保留工作稿及原公开版本，不自动换地址或绕过权限；修改后由有权用户重新安排。

编辑器显示待发布时间、捕获版本、取消及失败状态，后台列表标识待定时发布。到点状态刷新只更新发布元信息，不覆盖本地私有访问输入或 Y.Doc。公开入口仅指向已实际发布的路径，草稿和排期不能提前公开；列表编辑配铅笔图标。

公开阅读百分比放在右下角工具组底部，以主题底色、随百分比增长的背景填充与细进度线展示，保留数字与无障碍进度语义，遵循减少动态。页面编辑器删除通用「读取服务器版本」按钮及替换确认弹窗；版本冲突仍保留输入及原版本保护。

## 契约与迁移

显式迁移0025，启动不自动迁移。content-admin1.11增加排期/取消命令与发布元信息，collaboration2.2增加同一协作截点下的排期动作；原立即发布/保存请求形状及幂等指纹保持。契约先由后端提交，再由前端生成并固定来源 SHA，不放宽客户端响应校验。公开快照格式不变，未来内容只在真正发布后进入既有可靠同步。
