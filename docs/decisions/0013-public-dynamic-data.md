# ADR 0013：公开首屏独立阅读与动态补充

日期：2026-10-31。状态：**设计提案；用户要求及既有基线边界已记录，动态能力未实现**。来源为本轮“先盘点、先写规范，不写代码”的要求、v2.11 Q20/Q21/Q34/Q54/Q57、当前两仓库及 Argon 源码。

## 需要解决的问题

Next.js 必须能独立渲染已有合法公开内容；浏览量、互动数和用户态则可能晚到或不可用。把所有内容都动态请求会让正文/评论离线消失，把所有内容都写入公开快照又会混入易过时或私有状态。导航是否完成也不能被浏览量拖住。

## 已确认约束

1. 浏览量请求前隐藏，成功后自然显示，失败不显示；本轮仅设计。
2. 公开正文由 Next.js 节点公开资源支持，浏览器业务请求直接访问 FastAPI；公开 SSR/共享缓存不带用户态。
3. 评论已有明确基线：公开快照先读，浏览器异步更新，后端不可用时保留合法快照并只读。
4. 公开快照无时间 TTL；已知撤回/转受限不回退旧正文；后端发布契约、前端生成类型和客户端。

## 建议采用的设计

- 内容、站点配置、目录、上下篇、公开分类/标签及对应统计仍随快照渲染；浏览量与互动总数属于独立补充，身份/个人互动状态只能私有动态读取，本机阅读偏好无需业务 API。
- 共享请求协调与主题展示分责；列表统计按真实 ID 批量读取，处理部分失败、取消、乱序、超时和有界重试。可选字段不加入现有软导航的就绪门槛。
- 未知数值不填 0。指标在稳定的元信息区域淡入；失败安静隐藏，评论快照保留，用户主动写操作失败则明确说明。
- 顶栏建议增加低调的“动态数据状态”图标。它只说明当前页面已启动请求的更新情况，不把一次读成功、健康检查或通知收件说成“所有缓存已同步”。
- 浏览量读取与记账分开；预取、SSR、首页曝光不记账。有效访问口径、历史基数与去重窗口须在实施前确定，服务端跨进程幂等与持久确认必须成立。

详细分类、状态转换、缓存边界、建议初值、待定口径和验收入口见 [设计规范](../architecture/public-dynamic-data.md)。参数和端点并未冻结；不提前建目录空壳、配置键或接口字段。

## 与旧决定的关系

延续 ADR 0002 的公开快照读取、ADR 0007 的评论/说说语义、ADR 0008 的公开配置与本机偏好隔离、ADR 0012 的共享控件/配色规则。ADR 0009/0010 的导航横幅只管理页面导航，本文新增的可选动态读取不复用全页失败反馈。

当前 `reaction_count: 0` / `comments_open: true` 为展示适配默认值，与正式未知数值/权限语义并不等价，接入真实数据时必须替换。在线 0.1.0 契约及 0.2.0-preview.1 展示草案本轮均不修改。
