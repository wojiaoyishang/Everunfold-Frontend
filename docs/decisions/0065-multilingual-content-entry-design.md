# ADR 0065：多语言内容关联及切换入口提案

日期：2026-11-05（Asia/Shanghai）。状态：**设计提案，尚未实施**；首批简体中文＋英文及默认简体中文已由用户本轮选择。

## 要求与已有约定

用户要求开始多国语言内容工作，一篇文章/说说可关联多个语言，先复盘旧约定，再考虑前台和后台入口。基线Q31/Q35/Q36/Q37/Q52/Q57已明确独立内容ID、翻译关联组、各自协同草稿/历史/发布、URL决定公开SSR及请求级语言隔离；这些不应重新当成未决选择。说说纳入同一关联模型是本轮范围。

## 推荐方案

- 语言版本复用现有编辑/发布/历史用例，一组每语言唯一；关系由后端受约束业务命令维护。原文更新只提示待检查，不覆盖或发布译文。
- 前台顶栏提供站点语言，正文附近提供同文译文；后台顶栏切界面，文章/说说内容设置增加语言与译文面板，列表提供语言筛选/紧凑标记。
- 前台仅列真实已发布且策略允许发现的版本，后台按权限显示草稿和发布状态；受限译文仍验证自己的访问策略。SEO只指向可索引公开版本。
- 首批代码zh-CN/en；英文前缀建议/en/。早期默认语言前缀与后来ADR0034根级中文URL存在取舍，推荐保留现有URL和中文根级生成，只给新英文译文建议前缀，允许自定义；此路径建议尚未成为用户新定案。
- 前后端分别维护代码语言包；后端i18n.t通过ContextVar取当前语言，不改全局locale；前端SSR/字典/html.lang/元信息必须与明确URL一致。偏好头建议X-Site-Locale，内容筛选与界面偏好分开。
- 复用全站完整ContentRelease，成员发布/撤回/改址/访问收紧和关系变更更新整组公开导航和SEO，同事务登记Outbox；已有协同、缓存和访问不变量继续执行。
