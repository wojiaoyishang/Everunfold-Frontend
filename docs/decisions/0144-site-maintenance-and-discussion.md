# ADR 0144：站点维护与讨论设置

## 原生数据包

站点维护分为健康检查、数据导出、数据导入和导入记录。健康检查沿用站点设置读取权限。数据包操作和导入历史限管理员浏览器会话，写操作沿用 Origin 与 CSRF 校验。健康检查探测数据库与表结构、Redis、队列与任务进程心跳、媒体目录、发信配置和查询缓存。复制报告仅含检查时间、项目和状态。发信状态不进行实际投递。

原生 JSON 数据包格式为 `everunfold-content` 版本 1，每份最多 2,000 条、16 MiB。导出按类型、状态和修改时间筛选。包内使用稳定记录标识，包含最新内容及所需的显式引用。媒体原文件由部署侧另存，用户凭据、内容访问密码、私有设置及投递配置不随包导出。公开站点设置可选导出以便查阅和手动还原。正文的密码访问模式保留，导入后需要重新设置密码。

导入先解析并校验类型、同名/同路径冲突和媒体、语言及插件依赖。预检摘要绑定管理员和数据包。确认时重新计算预检，结果变更时要求重新预检。已有记录保持，新增文章、说说、页面和词条从草稿开始，新增评论等待审核。分类、标签和模板作为可复用资源写入。评论关联现有正文或满足依赖的页面。导入事务包含记录和审计回执，相同管理员重试同一份已确认请求时复用回执。

## 后台入口

「设置」末项为「节点状态与维护」。使用同一个页面布局，按「节点状态」和「站点维护」提供快速导航。窄屏在标题下提供站点维护快捷链接。原维护地址经 HTTP 重定向进入合并页，已加分区锚点的书签可继续直达。页面的健康、导入导出和缓存管理沿用各自权限。

## 讨论规则

规则保存在 SiteSettings 的私有区，使用独立修订号。读者接口只公开是否允许访客评论。默认允许访客提交，评论进入人工审核。站点可要求登录，可按拒绝词拦截，按审核词或链接数转人工。自动通过限本人验证过邮箱且已有获批评论的账号。每篇内容继续使用自身评论开关。Markdown 使用受限渲染，仅允许 HTTP 或 HTTPS 个人网站地址。新评论保存格式，历史评论沿用纯文本。新版前端需要与更新的公开快照及评论契约一起部署。

自动审核在评论事务中产生公开投影、缓存事件和已有的回复通知。普通人工审核流程与验证码、保护内容阅读凭据继续生效。开发库由显式 Alembic 升级到 `0062_discussion_comments`。
