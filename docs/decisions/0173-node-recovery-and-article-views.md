# ADR 0173  节点同步恢复与文章浏览量

状态为已实现。版本为 ADR0173-1。补充 [ADR 0171](0171-glossary-deployment-catalog.md) 和 [ADR 0172](0172-sync-failure-pages-and-first-card.md)。

## 三端手动同步

前端、后端、统一部署的 `setup.sh` 增加「触发同步」，命令行子命令为 `sync`。前端使用活动连接的节点令牌，通过后端校验实际来源 IP、节点 ID 和启用状态后，仅重排该节点的公开内容、站点设置、节点策略。后端和统一部署使用部署进程已有的数据库权限，先登记运行版本的后端插件清单，再重新排队。手动操作可恢复已达到重试上限的任务，记录操作审计，由 Worker 投递。

加密文章缺失术语是后端运行的插件构建与数据库登记不一致。文章可以正常解锁，匹配请求仍会被插件清单守卫拒绝。需要用当前运行版本登记清单。受保护的术语继续验证阅读凭证，结果保留私有的禁止缓存策略。独立后端启动同时检查插件清单。

## 自动恢复公开副本

收到前端确认清空后，后端将当前修订重新排入该节点的投递队列。前端进程在启动、公开请求和定期检查时检查副本，缺失或损坏时可通过已鉴权节点连接请求恢复。定期间隔读取 `cache.recovery_interval_seconds`，默认 60 秒。先处理首页所依赖的公开内容。自动请求保留在途投递及退避，管理员可用手动操作重新启动已耗尽的投递。

状态页区分接收器检查时间、上次和下次同步检查，使用所选节点前端进程报告的时间和浏览器时区。修复期间仍走现有副本验证及 503 状态。错误文案为「请管理员查看同步日志，确认同步状态。」

## 文章浏览量

公开可访问的文章详情记录浏览，包括密码保护和定时开放的文章。详情挂载记一次，当页解锁不增加；列表只批量读取。计数与发布副本分开，由 PostgreSQL 原子更新，读取仅返回文章 ID 和累计浏览量。浏览写入需要已配置的浏览器来源并按实际连接来源限流。原 `show_views` 继续控制可见性。

后端迁移 `0066_article_view_count` 将现有文章计数初始化为零。读者契约升至 0.2.0，设置契约升至 1.48.0。更新三端时先运行后端数据库迁移，再用匹配版本启动。文章标题闭锁和开锁图标共享轻微下移量，首页卡片沿用自己的对齐量。
