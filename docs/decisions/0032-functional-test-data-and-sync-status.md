# ADR 0032：功能联调数据范围与同步状态排版

日期：2026-11-02。来源为用户最新要求：优化文章管理页下方同步区域，测试期间不展示原博客文章，只使用当前后台发布的数据验证功能逻辑。已实施，结果见 [验收](../handoff/content-test-data-verification.md)。

## 决定

- 本轮替代 ADR 0031 在开发环境中继续展示既有 WordPress 公开数据的阶段选择。当前测试仅使用新后台创建并发布的文章/说说；恢复旧博客内容或再次导入，需要用户明确调整本阶段范围。原站与原始备份继续只读。
- 不通过前端临时筛选、改本地快照或删除文件隐藏历史文章。开发库把 `source=wordpress` 的公开内容状态改为 withdrawn，并提升各内容公开版本；保留行、正文、历史评论、分类关系和媒体。原博客普通页面也退出当前公开测试集，避免搜索/详情/推荐继续混入旧内容。
- 撤回、记录修改前身份/状态/版本的审计，以及新完整 release/逐节点 Outbox 必须同事务提交；通过已有 Worker/Scheduler/Node 接收器分发。API、首页、归档、搜索、统计与直链统一读取公开状态。重复执行为空操作，不产生新 release。
- 显式开发工具 `tools.withdraw_wordpress_preview` 默认只预检；`--apply` 才写入。只接受本地开发库或显式隔离测试库，要求现有有效管理员作审计归属。不接入启动流程，不修改生产默认过滤规则，不增加契约或迁移。
- 同步状态组件依旧复用封装按钮、图标和请求钩子；组件旁的 CSS Module 负责排版，避免依赖全局样式的装载顺序。图标、主次文字、操作在桌面端三列对齐；窄屏将操作放在正文下方，颜色与减少动态继续服从后台主题。

旧 release 和旧本地导出文件保留诊断历史，但最高已知新版本控制读取；不能以手工覆盖 current.json 恢复已撤回的旧文。已打开的旧浏览器页需刷新/新导航；本轮没有增加浏览器主动刷新。
