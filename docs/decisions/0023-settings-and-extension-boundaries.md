# ADR 0023：设置归属与前端扩展边界提案

日期：2026-11-01。来源：用户要求预留前端插件的组件/编辑器/页面/挂钩注册能力，盘点 Argon 和原站后台可配置项，优先设计主题设置、站点设置，并重点讨论 Next.js 缓存设置的存放位置。

状态：**待讨论提案，仅完成调研与文档**。没有新增设置 API、数据库迁移、插件执行器或修改任何实际配置。已确认边界、建议方案与未决定项分开记录；本 ADR 不替代原始基线。

## 已确认约束

- PostgreSQL 是业务配置事实来源，前端读取公开投影；公开快照无时间 TTL，已知撤回/转受限后不得回退旧正文。
- 后台 UI 归主题展示分区，权限/请求/缓存正确性不归主题。页面控件用项目封装，菜单沿用现有可信模块注册。
- 媒体先由后端上传/存储和发布 URL，Base URL/Uploads Path/CDN 接口沿用 ADR 0017；不把业务媒体保存职责回推给 Next.js。
- 公开快照不含身份/私密字段，后端发布 Schema 后前端生成；原 WordPress 只读，历史源码选项不是新产品必须移植的要求。

## 建议方案

1. 站点设置承载身份、菜单内容、业务政策与 SEO；主题设置承载布局、表现和显示默认值；个人偏好独立。原主题中的评论权限/验证码/通知等归站点业务。
2. 站点/主题配置从现有 SiteSettings 显式演进，按作用域/命名空间/Schema 版本维护；保存、审计与可靠事件同事务。预览/取消不写公共配置，成功保存与前端生效分别显示。
3. Next.js 缓存目录/驱动/容量与各服务秘密/连接留部署配置；系统页首期脱敏只读。后台中心策略是后续可选方案，需要独立 desired/effective 版本与节点应用确认，不让网页任意写服务器配置文件。
4. 预留受信任的组件/页面/插槽/设置分组/编辑器/渲染器注册域，显式装配、兼容与冲突校验；浏览器和 Node-only 能力分离，不做运行时远程代码加载或热安装。
5. 缓存采用核心统一流程与可替换提供器。存储实现可以扩展，权限隔离、版本/撤回、无 TTL 公开快照和持久 ACK 不可由可选插件绕过。普通页面派生缓存与动态数据可有各自有效期，不设置一个“全站 TTL”。
6. 下一阶段先提供站点/主题两个设置入口，优先实现已有渲染能力的真实设置；未完成注册、评论政策、媒体上传等业务不提供假保存开关。正式配置交付前必须完成对应可靠发布与 P0 断线/多进程验证。

## 待讨论而未冻结

- 是否采用推荐的“业务设置入库、运行配置本地、系统页先只读”，或现在就需要网页集中管理多个 Next.js 节点策略。推荐前者，后者增加投递、失效恢复和应用确认范围。
- 首批具体字段/默认值、派生缓存策略的时间初值；原始公开快照无 TTL 不因这个待决项暂停或失效。
- PUBLIC_SITE_URL 迁入可管理站点配置的时机；首期可只读展示，避免与现有部署字段双重权威。
- 插件清单/版本协商、编辑器适配和扩展页面参数路由的最终形态，待真实消费者确定后发布契约。

没有因旧主题能力提出自动安装插件、执行脚本、改站点 URL 或启用注册的建议。新方案的具体协议/数据库结构由后续后端设计发布，本轮不写应用代码接口占位。
