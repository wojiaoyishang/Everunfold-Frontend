# ADR0107：后台侧栏刷新后恢复滚动位置

版本：ADR0107-1。状态：已实现并验证。日期：2026-11-11。补充 [ADR0022](0022-admin-navigation-and-motion.md) 与 [ADR0105](0105-admin-navigation-and-glossary-media.md)。

## 背景

后台入口较多时，桌面固定侧栏本身需要纵向滚动。当前页面入口位于下方时，刷新会重新挂载导航并把侧栏滚动到顶部，使当前入口暂时不可见。浏览器不会自动保存这个内部滚动容器，单独依赖原生片段定位也会受后台客户端布局影响。

## 决定

1. 只为桌面 `.admin-sidebar` 保存内部 `scrollTop`，不改变正文滚动或移动端抽屉。
2. 存储使用 `sessionStorage`，键由稳定账号 ID 和规范化后台路径组成。相同账号的不同路径分别恢复；刷新同一路径保持原位置，关闭标签页后无需长期保留。
3. 恢复在首个动画帧执行，先恢复保存的精确位置；若菜单结构、折叠状态或视口变化使当前 `aria-current="page"` 入口不可见，再按侧栏可视边界做最小幅度对齐。
4. 滚动事件通过 `requestAnimationFrame` 合并写入，避免每个滚动像素同步访问存储。存储不可用或值无效时安静回退到显示当前入口，不阻断导航。
5. 当前入口始终使用导航现有语义标记，不依赖显示文本或坐标硬编码。侧栏折叠、分组展开和权限过滤继续由原导航组件负责。

## 影响

- 仅前端后台交互状态，无后端接口、权限、契约、数据库或公开页面变化。
- 存储不包含账号资料、令牌或页面内容，仅包含数值滚动位置。
- 移动端导航仍按每次打开抽屉的原有行为，不共享桌面滚动状态。

## 验证

`admin.test` 固定账号/路径隔离、路径规范化和非法值回退。真实后台在 1440×700 视口把当前“系统设置”滚到侧栏下方，刷新后滚动位置误差不超过 2px，当前入口完整可见；页面设置写请求为 0，脚本错误为 0。
