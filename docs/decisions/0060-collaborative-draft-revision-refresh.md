# ADR 0060：接收草稿修订通知，避免使用旧版本保存

日期：2026-11-05（Asia/Shanghai）。状态：已实施。

## 问题与决定

用户报告保存反复提示“内容已在其他地方修改”。排查发现DraftSession已经接收sync/revision帧并提供onRevision，但文章编辑用例未接入该回调。另一个窗口完成保存后，当前页面可以收到正文更新，却继续用旧的detail.revision提交，产生40951误报。

编辑用例现在接收修订通知，经原授权detail接口读取新快照，并单调更新保存基线、当前修订和发布状态。表单继续从现有Y.Doc投影，标签页的未保存正文缓冲保持；不以HTTP旧JSON覆盖共享文档。等待保存/截点期间的新通知排队，结束后补读；异步截点后构造提交使用当前修订引用，避免闭包仍持有旧版本。后台revision帧同时携带契约已有的committed_seq，作为该修订对应的最低同步截点；DraftSession在回调前把它加入保存屏障，正文更新晚到时cutoff必须等待，不能只拿新修订号提交旧正文。若HTTP快照比收到的通知更新，则等对应通知后再采用，避免把未收到的未来修订提前授权给保存。

访问策略、开放时间、文章密码在共享文档之外。如果本页有这些私有修改，新的他人保存不会自动覆盖它们，继续要求查看最新内容。读取失败也保留原修订守卫，不通过盲目提高expected_revision或强制覆盖绕过校验。服务端40951、40976、源文指纹和租约检查不变；同一正文确有冲突时仍保留输入并提供对照。

前端用例和协同会话、后端socket通知同时调整；使用原ServerFrame字段，没有新契约字段、接口、迁移或授权变化。已完成实页双窗口交替保存、单窗口连续保存、同块冲突/本地输入保留，以及既有真实双API/PostgreSQL/Redis P0回归。证据与未测范围见[验收](../handoff/editor-inline-tools-verification.md)。
