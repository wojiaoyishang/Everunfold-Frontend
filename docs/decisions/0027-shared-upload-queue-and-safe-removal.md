# ADR 0027：统一上传队列、同哈希复用与安全删除

状态：已实现；2026-11-01。来源为本轮用户要求，补充 ADR 0025/0026；原始 v2.11/v0.14 不修改。验证见 [验收记录](../handoff/media-uploads-verification.md)。

## 用户确认的行为

- 界面继续叫「媒体库」，能力扩展到普通文件。精简说明文字；类型和大小限制放在上传按钮旁。
- 所有上传入口，包括媒体库、图标库及后续附件入口，共用多文件、逐文件进度和降级实现。
- 新上传按完整原件 SHA-256 复用既有记录。不会改写该记录的名称、元数据、原件；编辑另存仍有独立来源/配方，不合并成原图。
- 删除和保存资料同行。默认移入回收站；「删除实际文件」和「安全删除」为两个独立选项，安全删除默认开启。

| 删除实际文件 | 安全删除 | 已实现结果 |
| --- | --- | --- |
| 关闭 | 任意 | 仅当前记录移入回收站，文件保留，可恢复 |
| 开启 | 开启，另有同哈希记录 | 永久移除当前记录，保留文件；其他记录不变 |
| 开启 | 开启，已是最后一条 | 永久移除当前记录，清理该哈希下所有留存原件，包括先前安全删除保留的副本 |
| 开启 | 关闭 | 一次移除全部同哈希记录并清理该组原件 |

回收站记录仍可恢复，因此计入“其他记录”；已经永久移除的墓碑不计入。现有重复历史记录不会在升级时被擅自合并。即使旧记录使用不同 object_key，只要原件哈希一致也按上述组规则处理。

## 上传与传输边界

后端维护 media_assets 内容身份和独立 media_upload_receipts 请求身份。按上传者/upload_id 稳定记录请求，签名绑定字节哈希、文件名、用途、来源和配方；改变内容复用同一请求 ID 返回冲突。普通上传使用请求锁与哈希锁，在 PostgreSQL 多 API 进程间串行发布；返回 reused 让队列展示“已复用”。图标复用已有合格媒体时开启 icon_enabled，不修改其原用途和资料。

前端 core/http/upload-transport 封装 XHR 字节进度、Cookie、CSRF、取消与超时。上传进度不可用时，发送前退回一次 fetch，并使用不定进度；已发送 XHR 的网络失败不暗中再发一份请求。字节上传 100% 后显示正在保存，只有契约验证成功才显示完成。

core/media/upload-queue 保存每个文件的独立状态，默认并发 2，失败互不阻塞；重试复用同一准备结果和 upload_id。主题只呈现队列，使用封装 FilePicker 多选和 UploadQueueView。取消不承诺撤销已受理的后端请求。关闭页面/上传选择器后不会持久保留队列，没有跨刷新续传。

媒体上传均为二进制端点，图标通过 purpose=icon 复用。旧 JSON 图标上传端点为兼容保留。已识别的 PNG/JPEG/WebP/SVG/MP4/WebM 继续严格验证；其余类型作为通用文件保存，以 application/octet-stream、attachment、nosniff 下载，不同源执行 HTML/脚本或解包压缩包。

## 删除范围与一致性

删除前通过 remove-preview 获取实际影响范围和摘要。最终请求携带 expected_revision、expected_plan、稳定 operation_id。检查和写入持有哈希协调锁及引用写入事务锁；范围变化返回 40939，不扩展用户此前确认的范围。

默认回收检查当前设置、内容和评论引用；永久移除还检查保留的设置审计/投递载荷与编辑来源。整组删除检查每个成员，组外任何引用都会阻止整组操作。组内随本次一起移除的来源关系不阻止清理。当前为保守检查，可能阻止可删除项，不以此宣称完整草稿/Revision/插件引用图已实现；这些未来写入者必须登记引用、使用同一守卫，再开放物理删除。

事务先原子写入全部成员的不可见/永久移除标记、审计和 media_removal_receipts 固定范围，再提交；文件清理在事务外逐个按受控 key 和预期哈希执行。成功后提交清理完成状态。磁盘故障或进程中断保留 pending，回收站可重试，重复操作只处理当初固化的范围，不纳入后来上传的新记录。未完成物理清理时同哈希新上传暂停，避免复用正在删除的原件。

永久移除的条目从库和回收站消失且不能恢复；数据库保留内部墓碑与请求回执用于审计、外键和幂等，这些不是可选用的上传记录。安全移除保留的文件路径仍在墓碑上，最后一条删除时可完整清理。物理清理不等于清除浏览器或尚未实现的 CDN 副本。

## 迁移与后续

显式迁移 0007_media_library 和 0008_media_safe_delete，不清空现有行；服务启动不执行 DDL。契约 settings 1.6.0；数据库/API 先升级，再部署对应生成前端。此次新增端点和删除请求形状须协调部署。

文件存放继续遵循 [media-storage](../architecture/media-storage.md)：不可覆盖原件、稳定 object_key、服务端 Base URL 和 Uploads Path。存储接口新增受控 matches/remove；CDN 接管传输、远端条件删除、复制/清缓存、变体与分片仍未实现。后续插件应复用上传队列和删除用例，不能绕过记录/引用/回执直接删除文件夹。
