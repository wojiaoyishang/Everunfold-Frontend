# ADR 0001：建立两个独立项目与可持续交接入口

- 状态：本轮初始化采用；不代表后续业务功能已完成。
- 日期：2026-10-30。
- 依据：当前用户要求、设计基线 v2.11、工程规范 v0.14。
- 范围：开发环境、项目骨架、文档、依赖锁定与协作方式。

## 背景

用户希望全量重构 WordPress 博客，但本步只要求先对齐两份文档、初始化指定的两个空目录、创建 Python 虚拟环境、规定开发规范、建立交接资料，并提交推送到指定 GitHub 仓库。两份原文确认的业务和运行边界保持有效，其中完整模型、契约和运行适配器仍待实现。

## 决定

1. 使用两个独立仓库：`Everunfold-Backend` 与 `Everunfold-Frontend`；分别维护依赖、检查、运行说明和状态。它们不共享运行进程，也不建立第三个契约代码仓库。
2. 后端使用 Python 3.12、uv、根包 `app/`，先建立最小 FastAPI 骨架。以 `pyproject.toml` 与 `uv.lock` 复现依赖，本机环境为 `.venv`。Celery、Scheduler、数据库迁移和业务模块按后续任务逐项交付；不引入 Celery Beat。
3. 前端使用 Node.js 22、npm、Next.js App Router、TypeScript 和普通 CSS，以 `package-lock.json` 锁定依赖。初始化只提供可运行入口，不在本步提前确定 UI 框架、源码编辑器或认证方案。
4. 本机工具核验记录为 uv 0.9.0、Node.js 22.15.1、npm 10.9.2。框架及其他包的精确版本以最终依赖文件、锁文件及状态记录为准；候选版本、官方兼容信息与实际检查结果不能代替彼此。
5. 两仓库均保存两份原始附件的逐字节副本和 SHA256。公共 `AGENTS.md`、文档入口、架构约束、开发协议与本 ADR 同步维护；各仓库 `docs/handoff/STATUS.md` 单独记录实际进度。
6. 根 `config.example.toml` 从工程原文完整代码块提取，并加上“规划模板、当前未完整加载”的说明。实际配置、密钥和备份不提交。配置加载器另行实现并验证，不能假设 FastAPI/Next.js 自动加载 TOML。
7. 本轮只验证骨架能够安装、检查和构建/运行，不把它当作全文重构完成或生产就绪。后续按数据模型与显式迁移、契约、缓存/协同适配、故障验收逐步推进。

## 不在本步决定的内容

完整 DDL/主键/枚举、公开 API/WS/ICP 完整 Schema、业务错误码、Cookie 生产范围和 Session 存储、编辑器/Python Yjs 适配、中文搜索、语言列表、审计留存及运行限额继续列为待定。Scheduler 兼任 Outbox relay、配置严格加载及恢复代际等 v0.14 新增工程提案需在对应交付中定稿并验证，不在本 ADR 宣称已经实现。

云端主动校对、CDN 自动清理与自动切换仍属于后续阶段；本轮不执行 WordPress 导入、生产部署或线上切换。

## 后果与验证

两个项目可独立打开并保持各自环境，代价是跨仓库契约版本和公共规范必须显式同步。后端仍是契约权威，前端只消费指定版本；同步文档副本不产生第二份事实来源。

初始化检查、实际版本、未执行项与下一步记入各自 `docs/handoff/STATUS.md`。依赖升级或骨架选择变化时更新/替代 ADR，并重跑相应检查。原始基线副本保持不变。
