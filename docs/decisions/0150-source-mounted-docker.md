# ADR 0150 · 源码挂载的双容器部署

## 决定

前后端各提供一套 `docker/`。运行容器把对应宿主源码只读挂到 `/workspace`，运行配置和数据单独挂载。后端镜像在 `/opt/everunfold/venv` 预装锁定的 Python 依赖，启动时核对挂载的依赖清单。API、Worker 和 Scheduler 在同一个容器中以独立进程运行，保持原有显式迁移、插件登记与调度边界。

前端通过同镜像的一次性构建器复制源码至可写的 `/build/work`。宿主挂载的源码、容器内依赖和 Next.js 编译缓存各有固定位置。主体构建不读取插件源码，构建成功后原子写入 `/releases/<版本>`；运行容器通过 `FRONTEND_RELEASE` 选择版本。构建时只需要锁定契约和软件依赖。实例配置与密钥在运行时挂载。

前端插件独立构建到 `/plugins`，沿用内容哈希资源、原子清单及运行清单核对。主题源码随主体构建。公开快照和设置在 `/data` 保留，主体回滚复用现有数据，发布前核对兼容性。两端端口、构建并发、API 进程数与 Celery 并发由部署环境传入。两端共用部署网络；跨容器的内部凭据仍按现有 HTTPS、真实来源 IP 和令牌规则校验。

## 影响

一次部署默认有两个长期运行的业务容器，前端构建临时启动一个使用同镜像的构建器。主体切换重建运行容器。前端产物按完整版本保存，部署者按回滚需求保留版本。环境、挂载和启动顺序见各仓库 [Docker 指南](../../docker/README.md)。
