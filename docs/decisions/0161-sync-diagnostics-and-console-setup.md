# ADR 0161：同步诊断日志与节点控制台配置

- 日期：2026-11-16
- 状态：已实现

## 原因

前端扩展清单上报的异常原先完全忽略，接收设置/内容失败也只返回笼统错误，无法从 Node.js 日志定位网络、凭据或存储原因。旧 setup 将发布 URL 复制到独立的控制台 origin，修改发布 URL 后仍可能跳回旧监听地址。后端缺少控制台启用开关，前端 setup 没有控制台密码配置。

## 决定

1. Node.js 使用 `[Everunfold sync]` 结构化日志记录方向、操作、节点、实际内部目标/来源 IP、HTTP 状态及明确原因。覆盖扩展清单上报、后端健康探测、设置/内容投递和副本读取；来源拒绝、凭据缺失/不匹配、节点/来源 UUID、协议格式与文件系统错误分别诊断。
2. 日志不输出请求/响应正文、令牌、密码、查询参数或任意异常正文。已知错误使用固定解释，系统异常从受限的 cause/AggregateError 链提取已知代码。未知异常仅报告未分类，不把私密数据混入日志。
3. 扩展上报仍每 3 秒重试，相同失败每 30 秒重复记录；原因变化立即记录，成功恢复单独提示。只有后端返回成功外壳、对应节点 ID 和 registered=true 才确认上报，代理返回 HTML 或错误节点不能算成功。浏览器直连 API 的请求及未到达前端的网络失败须查看浏览器/后端/Worker 日志。
4. 两端使用同一套 setup 控制台字段：启用开关、密码和会话密钥。新配置默认启用并随机生成凭据，既有显式启停状态及哈希保留；可手动编辑、复制或重新生成，旧哈希留空不重置。后端使用 Argon2id；前端保持与 Node.js 默认参数兼容的 scrypt。回显值沿用受保护的根 YAML environment 存放规则，日志不打印。
5. 按用户要求，后端控制台优先跟随 BACKEND_BASE_URL，前端优先跟随 PUBLIC_SITE_URL；不再由独立 origin 覆盖发布 URL。origin 只兼容未配置发布 URL 的旧实例，setup 保存时移除它。此前显式使用另一控制台域名的部署需改用发布域名。绑定 IP/端口、内部连接 URL 与发布 URL 仍各司其职。
6. 前端本机密码仅在后端离线时生效，在线仍要求后端管理员身份与操作证明。HTTPS、真实来源 IP AND Token、后端可信 TLS 代理、独立会话、权限和客户端响应格式保持现有边界。

## 验收

验收项目包括：真实 HTTP 上报被拒、错误确认、恢复及日志不泄露凭据；接收器来源与令牌拒绝、节点/来源 UUID 不匹配、无效 JSON 和磁盘权限失败；发布 URL 覆盖旧本地 origin、可信代理登录、停用页面；setup 生成/编辑/保留密码与重复保存、窄屏交互及前端 scrypt 运行时兼容性。实际执行结果和环境限制见两仓库 `docs/handoff/STATUS.md`。
