# ADR0118：账号用户选择器与通知策略快速导航

日期：2026-11-11。状态：已实施。

## 背景

通知策略的“指定用户”原先要求人工粘贴稳定 UUID。UUID 不易识别，也无法确认账号是否启用、显示名称是否正确；直接展示自由文本还会增加输错和选错接收人的风险。通知策略同时包含多个事件，桌面端缺少与系统设置一致的页面内导航。

## 决定

1. 新增共享`AccountUserPicker`。触发器显示头像、显示名称、用户名和 ID 前缀，保存值始终为稳定用户 ID。
2. 选择器通过现有账号目录读取启用用户，支持姓名、用户名、邮箱和完整 UUID；不增加绕过账号权限的新公开目录。
3. 用户目录查询继续要求`users:manage`。不能浏览目录但能修改通知策略的账号保留手工填写稳定 ID 的降级路径。
4. 用户选择属于通知策略本地草稿；未点击“保存策略”前不写入数据库。
5. 弹层沿用共享`ActionPopover`、`TextField`、`Avatar`和后台语义 token；键盘焦点、Escape 关闭、选中态和清除操作使用现有交互边界。
6. 通知策略的事件卡声明`data-settings-section`并使用稳定事件 ID 生成锚点，由共享`SettingsLayout`自动生成桌面右侧快速导航。
7. 手机端不显示快速导航，接收规则继续按单列布局，弹层宽度受视口限制。

## 结果

- 指定用户可以通过可识别身份选择，不必记忆 UUID。
- 保存与路由校验继续使用稳定 ID，不依赖显示名称或用户名。
- 通知策略与系统设置复用同一种桌面页面内导航，不对事件顺序或后端路由做第二套定义。
- 若站点未来调整账号权限，选择器必须重新审视目录读取边界，不能把管理权限扩大到普通通知编辑者。

## 验证

真实后台覆盖姓名搜索、精确 UUID 搜索、选中回显、快速导航跳转与聚焦、1440px 桌面和390px手机布局；未保存策略时通知写请求为0。详见[验收](../handoff/notification-policy-user-picker-verification.md)。
