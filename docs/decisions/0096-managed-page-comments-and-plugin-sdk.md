# ADR 0096：托管页面评论与插件 SDK

版本：ADR0096-1，2026-11-10。状态：已实现，部署与实页检查结果另记。承接页面管理、验证码和插件 SDK，回应用户对 HTML 自定义页面评论开关、注册页面公共评论组件及自定义请求能力的要求。

## 决策

在 `PageValue` 增加 `comments_open`，默认 `true`，旧页面缺字段按开启处理。通用编辑器的开关随原工作稿保存与应用，覆盖完整编辑器和实时预览，不新增独立写接口。“保存草稿”不影响公开状态，“保存并应用”才发布；关闭只禁止新评论和回复，保留已审核历史可读。`PageRegistration.comments_open` 只初始化首次创建的注册页，不在再次登记或插件更新时覆盖管理员配置。

HTML、CSS、JavaScript 仍运行于原有不透明来源 iframe；评论 UI 放在沙箱外，由宿主提供阅读、验证码与互动上下文。可信注册页通过前端 `comments: { placement: "auto" | "manual", selector? }` 声明放置方式：默认页尾；`PageComments` 提供优先锚点；选择器限定当前页面正文，目标迟到时移动同一个宿主容器，不重复挂载表单和验证码。manual 无锚点且无 selector 时不追加；声明 selector 但目标缺失时回退页尾。此放置配置属于前端组件定义，不混入后端通用页面数据。

提供 `usePageComments()` 上下文与 `usePageCommentClient()` 请求适配器，后者复用目标 ID、阅读凭据、验证码和稳定幂等操作 ID。`CaptchaField` 供自定义 UI 使用共享验证码展示；低层客户端仍沿用现有评论提交端点，不开放任意 URL 或绕过验证的新入口。主题以 `public.page.comments` 替换或包装展示，保留业务门禁与预览约束。

分页读取使用 `POST /v1/reader/page-comments`，受保护页面在请求体携带内存态 `read_receipt`，避免凭据进入 URL、公开快照和持久缓存。后端重新检查当前已应用状态、阅读策略和凭据，提交继续校验评论开关、验证码、审核流程与回复目标；关闭或撤回后的旧回执也不能绕过最新准入条件。阅读凭据与验证码响应不持久化到前端，不交给 HTML 脚本。预览不进行评论验证码、分页读取、点赞或提交；SDK 拒绝预览 read/submit，主题与插件自定义实现遵守同一规则。

## 影响与边界

沿用开启默认值保持现有页面行为；未来插件可声明不同初值，管理员可独立调整。保留旧评论需要与关闭新提交分别处理，页面不可访问时仍受原门禁限制。单一宿主评论容器避免重复 ID、重复验证码和异步重新挂载导致输入丢失。完全自定义 UI 需自行处理 pending、错误、取消、重试和“待审核”反馈，不能把成功提交视为自动发布。

开发入口、准确签名及最小锚点示例见[页面评论指南](../development/page-comments.md)。本 ADR 不声明未经记录的浏览器、并发或部署验收结果。
