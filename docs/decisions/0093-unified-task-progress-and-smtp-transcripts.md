# ADR 0093：统一持久进度、连续监控与SMTP诊断

版本：ADR0093-1；2026-11-09。状态：已实施。来源：用户要求Worker任务可连续监控、邮件测试有详细日志和报文，并提供统一可复用接口。

## 决定

使用业务任务ID、后端事实状态和递增事件序号作为统一口径，PostgreSQL保存进度事件；前端通过带游标的长轮询连续读取，断网重连只恢复读取，不重新提交业务。总量未知时不用虚构百分比。runtime执行与mail-test是首批适配资源。

执行端提供统一async上报函数，Worker包装器注入执行上下文，插件使用同一SDK。上报检查认领所有者/租约，进度持久化不替代业务提交；历史已终结任务没有详细日志时明确保持空日志。

邮件同步SMTP调用通过受控事件回调持久化，避免原始debug日志泄露认证载荷；命令/响应/MIME测试正文按文本展示，所有认证对话脱敏并限制日志大小。读取测试日志继续限制为发起者且具备settings:write。

前端提供统一hook和主题组件；测试任务ID按账号/后端保存在会话存储以便刷新恢复，敏感日志不持久化。运行管理按需订阅展开的执行，避免一百条记录同时建立监控。

## 影响

新增显式迁移0034与settings1.21.0契约。长轮询最多20秒、不长期持有事务，前端超时需高于后端等待预算；终态需读完has_more分页后停止。重连状态与任务状态分开，其他页面可沿同一协议扩展。开发和验收见[指南](../development/task-progress.md)与[记录](../handoff/task-progress-verification.md)。
