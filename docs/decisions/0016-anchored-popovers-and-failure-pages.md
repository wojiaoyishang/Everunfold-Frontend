# ADR 0016：悬浮层就绪与主题错误页

日期：2026-10-31。来源：用户要求修复加载过程中状态面板闪到 (0, 0)，并让 404/错误页更贴合主题、提供轻量小游戏；文字仍须直接清楚。状态：已实现，实际检查范围见 [验收记录](../handoff/failure-pages-verification.md)。

## 定位完成后再显示

`useAnchoredPopover` 统一用于动态状态、搜索 Select 和自选色面板。服务端首屏及水合完成前触发按钮禁用，避免原生 `popoverTarget` 先于客户端定位接管。此就绪只等组件水合，不等后端动态请求成功。

每次原生 `beforetoggle` 打开时清除位置就绪标记；原生打开后在微任务中按最终宽度测量、约束视口、写入坐标，再设置 `data-positioned=true`。未定位面板使用 `visibility:hidden`，仍可测量，禁止任何 (0, 0) 可见帧。关闭沿用已知位置以保留退场过渡。打开期间继续观察大小、滚动和窗口变化；快速重开重新定位，不复用旧坐标。原生 top layer、外点关闭、键盘与焦点语义保留。

## 错误展示与 HTTP 语义

本决定更新 ADR 0015 的“中性排版”部分，保留明确文案及其余数据/导航规则：

- 404：地址未找到，保留返回首页。公开快照不存在或不可读：503、“后端同步失败”，提供返回首页及重试。
- 404/503 仍由 Proxy 在正文渲染之前返回真实状态、noindex/no-store；503 保留 Retry-After: 60。未知/不可用不能伪装成 200 或回退已撤回正文。
- `error.tsx` 与新增 `global-error.tsx` 使用同一主题组件，渲染异常显示 500 的明确文案，不伪称后端一定故障。500 是错误类别；浏览器已收到的 HTTP 状态不因后来的客户端异常而改变。框架错误边界的完整交互仍依赖 Next 客户端脚本。
- 星点底纹、状态数字、柔和卡片、主题色按钮和 SVG 图标统一设计；沿用保存的配色/深浅/减少动态偏好。不引入图片、字体、动画或游戏依赖。

## 共享组件与独立文档

主题边界集中在 `src/themes/argon/failure/`：`FailureSurface` 是展示结构，`FailureView` 安装交互，`styles` 提供作用域样式，`pair-game` 是纯状态逻辑，`enhance-failure` 只管理本组件 DOM、监听和短暂翻回定时器。按钮/链接使用既有 ui 封装；核心仅提供状态文案。

Proxy 不能在运行时导入 `react-dom/server`。采用**构建时生成**：`tools/generate-failure-pages.mts` 使用同一 React 组件生成 HTML，TypeScript 显式编译同一游戏源码，输出 `src/generated/failure-pages.json`。运行时只组合固定的受信任产物，不注入 URL、配置、异常堆栈或用户正文。该文件是主题构建产物，不是业务契约，也不产生第二套 API 字段。

- `npm run failure:generate` 更新产物，禁止手改 JSON；`predev`/`prebuild` 自动生成。
- `npm run failure:check` 检查来源一致性，纳入 `npm run check` 及独立构建工具；保留热更新时，修改错误页后显式重新生成。
- 404/503 的文字、样式、首页链接无脚本和无快照也可用；小游戏增强脚本内联，不依赖 Next chunk 或 FastAPI。禁用脚本时说明仍在，游戏不伪装成可操作。

## 小游戏范围

翻牌配对共四组、八张卡片，手动开始、记录本局尝试次数、支持重开。未匹配的两张短暂停留后翻回；同张重复点击、待翻回期间输入及已配对牌不重复计数。键盘可操作，卡片名称/状态与完成消息可读，减少动态关闭翻转过渡。只使用本地内存，不存成绩、不读写后端、不做自动重试，不把通关当作后端恢复。

不扩展登录、浏览量、缓存同步、评论写入或后台主题设置。本轮不改业务契约、数据库、依赖或实际配置。
