# ADR 0158：单端口前端与保留配置界面的操作反馈

- 状态：已实施；Docker 实机验证仍待部署环境。
- 日期：2026-11-15。
- 来源：用户要求前端只保留一个端口、检测后端内部地址；两端“仅保存”和后端节点导出后均保留程序，导出时显示文件绝对位置。

## 决定

1. 前端使用一个 Node HTTP server，把 `/internal/*` 交给既有设置/快照接收处理器，其余请求交给 Next.js。Web、内部同步与节点诊断统一 `FRONTEND_HOST` / `FRONTEND_PORT`，默认 3000；生产、开发和 Docker 均不再单独启动接收器。真实 socket 来源 IP AND Token 校验保持，不用转发头或应用内代理替代。Next.js 的开发热更新使用同一 HTTP server。
2. 旧接收器配置键仅兼容读取、不参与监听，向导保存时移除。Docker 只暴露、映射一个前端端口。旧部署更新后需重建主体和镜像，并把接收 URL / 代理上游迁到这个端口；发布 URL、内部后端 URL、绑定 IP 和宿主映射仍各司其职。
3. 前端只探测服务端内部地址的 `/health/ready`，支持现有运行加载器接受的容器 HTTP/HTTPS 地址。内部地址为空时，以发布 URL 为唯一连接目标，不额外探测另一个公开入口。
4. 前端 `--connection-file 文件绝对路径` 使指定宿主文件只读挂入配置工具容器并导入；不扩大到整个后端数据目录，不挂 Docker socket，不挂入运行中的前端容器。缺文件、权限和内容错误分别提示，仍可回到配置修改。
5. “仅保存”写根 YAML 后更新文件并发校验基线和界面已保存状态，显示成功并允许继续编辑。外部修改仍会阻止覆盖；退出时只放弃最后一次保存后的修改。更改网络后，检测仍提醒重新打开助手，不把刚保存的网络误当成已接入网络。
6. 后端“登记并导出节点”在界面内异步执行原有登记/导出流程，成功显示真实文件绝对路径，失败可重试。原生通过已有启动入口执行；Docker 由宿主短期操作桥只执行固定 `export-node` 操作，配置工具不获得通用 Docker 控制能力。宿主根据已保存挂载设置重新生成配置并返回宿主文件位置，而不是容器 `/data` 路径。此操作仍会登记节点内部连接，公开节点地址与启用状态继续由 `/_nodes` 管理。

## 验证

- 两端助手与编排各 36 项：前端 27 通过/9 按组件跳过，后端 32 通过/4 跳过。覆盖连续保存、外部修改、放弃未保存值、导出失败/重试/绝对路径、网络提示、唯一端口映射、只读导入挂载和固定宿主操作。
- 前端 412 项测试、TypeScript、ESLint、Prettier、真实生产构建通过；同一 TCP 监听测试继续拒绝错误令牌和伪造来源头。后端默认 pytest 353 通过/85 项显式服务测试跳过。
- 隔离 PostgreSQL/Redis 初始化与真实 API 双 worker、Celery Worker、Scheduler 启动；后端就绪 200，database/redis/schema 全部 ok。真实原生 TUI 连续导出两次，界面保留且完整绝对路径匹配实际文件。
- 新生产前端在唯一端口提供网页与同步，真实接收快照持久回执后就绪从 503 到 200；重启保留副本、不编译。发布 URL 故意不可达时，内部就绪检查仍通过，内部地址未进入网页 HTML。
- 保存/导出在 110×38、80×24 界面和真实 PTY 回归检查；内置浏览器核对真实导出路径、保存成功与公开页面。SVG 中文字距沿用导出器限制，终端交互与宽度由 PTY / Textual 验证。
- 开发模式的页面和 `/_next/hmr` WebSocket 在同一端口通过，六个独立插件构建成功。
- Bash、Ruff、Compose v2 静态渲染、两端 Sphinx 严格构建通过。环境没有 Docker daemon，命令桩与原生进程不能替代实际镜像和容器网络验收。未修改用户实际配置、数据库或运行实例。

此决定替代 ADR 0150、0152、0154、0155 中的双前端监听及保存/导出退出行为；历史记录保留。正常容器重启仍直接运行既有产物，独立插件构建和持久化安排不变。
