# ADR 0085：主题和插件共用字体注册接口

日期：2026-11-09。状态：已实现并完成本轮验收。用户要求字体可注册并统一路径，进一步明确主题也可使用接口，不限定为插件贡献。

将上传库、预览、稳定媒体字体渲染及新注册能力集中在src/core/fonts。保留原媒体身份、引用、URL、上传队列和后端事实，不迁移用户文件；新静态主题字体约定public/reference/fonts/<主题ID>/。原功能专用字体资源路径保持。

defineFont是主题与插件共用的纯声明接口。主题在ThemeDefinition.fonts声明，插件在同步setup中fonts.register；宿主合并受控目录并提供FontStyles、useFont和useRegisteredFonts。字体ID属于贡献者命名空间；声明校验URL、格式、字重、回退栈和unicodeRange，拒绝CSS注入和不合法资源。不存在/停用条目使用系统字体回退，注册不会下载文件。

主题typography提供正文、标题、代码三个角色，父到子合并、null清除继承，默认字体只作用于前台。标题CSS钩子低优先级，允许主题/插件覆盖。上传的显式站点/代码字体选择优先，已有正文内字体仍按实际引用。只为引用角色生成CSS，代码文件只在含代码正文声明；font-display固定swap，不增加批量预载。

独立插件支持asset:相对字体路径，按原内容哈希资源规则打包；禁止目录逃逸和逃逸软链接，服务端验证manifest、文件、声明与来源归属，热替换保留旧文件。fonts是前端包的可选元数据，旧包在摘要校验前保持原对象，不能通过补默认字段改变旧摘要。新SDK能力需要更新宿主，原后端DTO、权限、配置和数据库不扩张。

后台字体库将代码注册项与上传项分开显示，注册项支持搜索/按需预览，代码维护；上传项继续原选择、资料编辑和删除。当前不把注册字体ID写入只接受媒体UUID的设置字段。具体API、边界及范例见[字体注册指南](../development/font-registration.md)；真实检查见[验收](../handoff/theme-browser-paper-fonts-verification.md)。
