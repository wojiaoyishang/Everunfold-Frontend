# ADR0103：按需术语脚注与文章/说说独立开关

版本：ADR0103-1。状态：已实现并验证。日期：2026-11-10。补充 [ADR0099](0099-article-scoped-glossary-tooltips.md) 与 [ADR0101](0101-glossary-rules-and-reader-ui.md)。

## 背景

文章和说说正文已有文章级术语匹配与 Tooltip。读者需要在正文结束处快速回看本页出现的术语，但不能为了这份列表在首屏加入词典、阻塞正文，也不能强制文章和说说使用同一种展示选择。

## 决定

1. 术语脚注在正文渲染完成、页面空闲后动态加载；复用 `loadGlossaryMatches` 的“API 地址 + 内容 ID + 修订”5 分钟缓存与 pending Promise。脚注与 Tooltip 同时启用时仍只有一个文章级匹配请求。
2. 脚注只列出后端针对当前公开文章/说说实际命中的已发布词条，不下载全站索引。没有命中、请求失败或请求被取消时不渲染空容器，正文继续可读。
3. 脚注位于正文 `.article-content` 之后、文章页脚/分享区之前，使用无序列表。每项显示术语标题和简要提示，整项链接到独立词条页并在新窗口打开。
4. 简要提示优先使用 `summary`；摘要为空时，从第一个非空术语正文区块经共享安全渲染后提取纯文本。提取时移除 `script/style`，按标题、段落、列表、表格、代码、引用等块分组并合并行内文字；图文但无可提取文字时使用“查看词条了解详情”。
5. 标题和提示都保持单行，超长自动省略并保留完整 `title`。桌面和手机均为“标题 / 提示 / 进入”三列；手机缩短间距，不产生整页横向滚动。
6. 站点设置新增 `site.glossary.article_footnotes` 与 `site.glossary.shuoshuo_footnotes`，默认开启且互不联动。它们独立于 `auto_match`：关闭正文内 Tooltip 后仍可保留末尾脚注；关闭某一类脚注不会关闭另一类，也不删除匹配数据。
7. 设置契约升至 `settings-v1 1.27.0`。字段位于已有站点设置 JSON，不新增数据库列或迁移；旧设置缺少字段时按开启处理。
8. 样式只使用主题变量和强调色：左侧强调线、轻微渐变表面、紧凑列表和清晰分隔，与正文及普通卡片区分；悬停/聚焦与减少动态偏好沿用共享 tokens。

## 理由

- 脚注是派生阅读增强，不是 SEO 正文；空闲后加载能继续保持正文首屏静态输出。
- 文章级匹配与缓存复用避免一次阅读重复请求术语数据。
- 摘要与首个富文本区块的两级回退能覆盖 Markdown、HTML、标题、列表、表格、代码、公式和混合区块，同时不让复杂结构撑破脚注。
- 文章和说说分别控制符合不同内容形态的展示需要，也让站点可在不关闭 Tooltip 的情况下只隐藏某类脚注。

## 影响与限制

- 脚注依赖浏览器 Text/DOM 提取富文本首块；纯图片、复杂嵌入或没有任何可见文字的区块显示通用入口。
- 后端命中是安全可见文本近似，跨节点拆分的词汇可能无法获得正文内装饰，但脚注仍按该文章的匹配结果列出相关词条。
- 脚注不参与阅读进度计算，不使用独立统计，不改文章公开快照、正文块、术语正文或 WordPress 数据。

## 验证

- 真实文章返回 4 个命中术语，脚注位于正文之后、页脚之前；Tooltip 与脚注共用 1 次匹配请求，链接 `target="_blank"`，浏览器脚本错误为 0。
- 390px 实页验证：空摘要从富文本首块生成可读提示；超长提示 `text-overflow=ellipsis`、`white-space=nowrap` 且确实溢出；页面无横向滚动。
- `npm run check` 351 项通过；读者端和管理端隔离生产验收通过。后端设置模型/术语定向测试 16 passed、1 skipped（专用 PostgreSQL 库未配置），设置契约生成与一致性检查通过。
