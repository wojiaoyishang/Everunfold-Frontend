# ADR0101：术语匹配规则与分级阅读弹层

版本：ADR0101-1。日期：2026-11-10。状态：代码已实现，待真实浏览器与数据库迁移验收。补充 [ADR0099](0099-article-scoped-glossary-tooltips.md)。

## 决定

1. 术语标题与正文匹配解耦。新增 `auto_match_title` 和 `match_rules`：规则分为 `literal` / `regex`，支持单条启停、大小写、ASCII 整词边界、优先级。优先级较高先选，同起点再选较长词，不重叠，最后以词条稳定 ID 决定。
2. `match_rules=NULL` 代表兼容模式，继续按旧标题和 `aliases` 匹配；空数组表示显式没有额外规则，不能回退旧别名。前端初次编辑旧词条时，现有别名显示为普通规则；新保存后别名从普通规则同步，正则不进入公开词条别名字段。
3. 后端文章级 `for-content` 仍是事实来源。后端只计算当前公开文章实际命中的文字，返回 `matched_patterns`（实匹配字面值、大小写、边界和优先级）并保留兼容 `matched_texts`；浏览器仅按这些字面值装饰安全可见文本节点，不下载全站规则和索引。
4. 正则使用明确受限的 Python 3.12 正则子集：表达式最多 160 字符、最多 6 处非嵌套有限重复（上限 32）、最多 6 处分支且每处至多 6 选项；拒绝无限重复、断言、反向引用、空宽度结果等危险构造。每规则最多采集 40 个命中、总计 200 种文字；请求正文依旧受页面可见内容范围约束。预览 POST `/admin/preview` 走相同引擎，仅检验给定的短样本，不持久化。
5. 公共阅读采用两级弹层：悬浮/点击先显示标题、别名和简短提示；若 `popup_source=content` 且有正文，可主动打开原生 dialog 形式的完整说明，复用共享安全富文本渲染和代码/公式/媒体处理；`popup_source=summary` 仍只提供简短提示和词条入口。
6. 表格作为 Argon 主题共享 `.article-content` 样式实现，列宽默认铺满、清晰表头与斑马纹，窄屏只滚动表格区域。文章、说说、术语详情、弹层和统一草稿预览复用，不向后台管理数据表格传播正文样式。表格滚动容器由共享 `ContentMarkupView` 在挂载时提供，键盘可聚焦。
7. 新增显式迁移 `0038_glossary_matching_rules` 与插件契约 `glossary-v1 3.0.0`。不修改文章快照、原 WordPress 数据或其他业务模型；未经迁移不得部署新服务。

## 限制与后续验证

- 文章命中来源是 Markdown/HTML 的安全文本近似；内联拆分、全文规格化导致的字形差异和短代码动态输出，仍可能使浏览器装饰与后端筛选存在偏差。不得称作完整 DOM 正则扫描。
- 规则冲突只对普通字面值执行静态重复校验；无法预判两条任意正则是否相交。执行时以优先级与最长结果决定。
- 完整弹层和表格需在桌面/390/320、深浅主题、触屏、Tab/Escape/焦点恢复及减少动态模式作实际 UI 验收；后端需在独立 PostgreSQL 测试库执行迁移/读写/发布/撤回/多进程测试。当前不因编译通过而标记这两类为完成。
