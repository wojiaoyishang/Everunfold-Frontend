# ADR0102：SEO 内容静态嵌入、交互增强按需加载

版本：ADR0102-2。状态：已实现并验证。日期：2026-11-10。来源：用户要求文章标题、摘要和正文直接出现在首屏 HTML 中以服务 SEO；随后要求继续做网页性能优化，尽可能去掉客户端边界中的正文、列表数据和主题组件的冗余载荷，同时保留术语、查阅量等非正文数据按需加载。

## 背景

公开文章的数据原本已在服务端读取并由 `renderContentForReader` 生成 HTML，但主题具名组件通过 `React.lazy` 与 `Suspense` 加载。服务端首屏因此先输出“正在加载组件…”，最终文章仅在水合和后续脚本执行后出现。搜索引擎虽可能等待页面稳定，但初始响应没有完整阅读表面，禁用 JavaScript 的用户也会看到加载占位，不符合 SSR/SEO 目标。

## 决定

1. 公开文章、标题区、正文和页脚等 SEO 阅读表面必须在服务端直接输出最终语义 HTML。服务端静态主题实现从 `src/themes/<主题>/components.tsx` 解析；需要水合的业务组件从独立的 `client-components.tsx` 注册。文章阅读表面不得使用异步组件占位。
2. 文章标题、摘要、正文、分类/标签、基础元信息和已有服务端 SEO 输出继续来自公开内容快照；主题只负责展示，不把正文生成移到 `useEffect`、水合后的脚本或客户端拼装。
3. 保留主题自动发现、父子主题继承、组件局部错误边界和缺失实现回退。静态实现和水合实现分开注册只改变代码进入哪个构建图，不改变主题所有权、模板/槽位或业务权限。子主题覆盖需要水合的组件时，在 `client-components.tsx` 提供同名实现。
4. 术语匹配继续按[ADR0099](0099-article-scoped-glossary-tooltips.md)执行：正文先在服务端输出，空闲后懒加载 Tooltip 组件，再请求当前文章实际命中的已发布词条；术语响应按 API、内容 ID 和修订缓存，空结果也缓存 5 分钟。术语不得进入正文快照或首屏 SEO 内容。
5. 浏览量仍只在指标元素接近视口后由客户端请求；身份、临时阅读状态、评论交互和其他私有数据不得因本次静态化进入公开 HTML 或 SEO 元数据。
6. 新增主题的阅读组件必须可在无浏览器 API 时完成服务端预渲染。`window`、`IntersectionObserver`、弹层定位和交互监听只能存在于水合后的 Effect 或独立客户端增强组件。
7. 文章、说说和列表只有在客户端确实需要时才传递展示 DTO；原始正文块、完整快照和已经渲染为 DOM 的 HTML 不再作为客户端 props。文章正文由服务端输出目标容器，小型增强岛按稳定容器 ID 接管代码工具、表格滚动、公式增强和术语提示。
8. 服务端渲染继续转义 `&`、`<`、`>`、引号等 HTML 语法字符，但中文、日文、emoji 等 Unicode 正文直接以 UTF-8 输出，不膨胀为 `&#x...;` 数字实体。

## 理由

- 首屏直接包含正文，搜索引擎和禁用 JavaScript 的读者无需等待客户端组件块。
- 术语和查阅量不决定正文语义，继续动态加载可避免每篇文章携带完整词典、用户态指标和无关交互代码。
- 保留主题继承和局部回退，修复只触及公开主题组件解析路径，不把文章展示重新做成不可替换的单一页面。

## 影响与限制

- 静态主题注册和水合主题注册分开后，文章卡片、标题、正文及列表卡片不再因为水合注册表而整体进入客户端包。壳层、表单和确需交互的组件仍保留同步水合，以保证首屏结构和交互一致。
- 首次 HTML 的正文大小由文章本身决定；本次验证示例文章正文约 63 KiB，复杂文章仍应通过缓存、压缩和图片资源优化控制传输，而不是删减正文。
- 示例文章开发响应由约 363.7 KiB 降至约 314.3 KiB，gzip 估算由约 63.9 KiB 降至约 57.2 KiB；内联 RSC 数据约 222.9 KiB 降至 187.9 KiB，原始 Markdown 和 2,834 个数字实体不再重复传输。
- 真实阅读统计仍未接入。当前浏览量请求按需发生，接口不可用时指标保持隐藏并回退空占位，不影响正文和 SEO。
- 本次不迁移 WordPress 文章，不修改术语内容或站点业务数据，不改变后台编辑、发布、权限、快照一致性或评论边界。

## 验证

- 隔离生产构建的读者端首次响应包含文章标题、`article-card`、`article-content` 和语义标题，不包含扩展加载占位；回归断言位于 `tools/verify-reader-runtime.mjs`。
- JavaScript 开启与关闭时实际页面均显示相同标题“把新博客翻个遍：Everunfold 功能测试长文”和首个小标题“一、从一段普通文字开始”；无脚本时正文可见、占位数为 0。
- JavaScript 开启后，文章级术语接口请求 1 次并实际装饰 20 个词条；浏览量接口仅在指标进入视口后请求 1 次。页面脚本错误为 0。
- 首页、文章、搜索、术语目录和独立文章在桌面浏览器均无加载占位或脚本错误；主页四张卡片和文章正文在禁用 JavaScript 时仍可见。
- `npm run check` 351 项通过；读者端和管理端隔离生产验收均通过，覆盖主题切换、文章/说说/页面、SEO、离线和撤回快照、条件代码/公式资源、子主题多级组合及私有后台。
