# ADR0115：账号邮箱验证与用户管理确认边界

日期：2026-11-11。状态：已实施。

## 决定

1. 登录账号可在`/account`为自己的邮箱发送6位验证码，验证成功后持久化`email_verified_at`；未验证邮箱仍不能用于登录或密码找回。
2. 验证码通过现有SMTP配置发送，但外部发信只在Worker执行。请求记录在PostgreSQL，15分钟有效、同一时间只允许一个活动请求、60秒发送冷却、每账号每小时最多5次、最多5次验证码尝试。
3. Worker认领请求后读取一次性验证码发信，并在任何发送尝试后清除待发送明文；数据库只长期保留加盐摘要。发送租约中断、SMTP失败或配置改变均明确结束当前请求，用户重新发起而不是自动重复发送。
4. 确认时同时检查请求、邮箱、过期时间、账号修订和验证码。成功后原子写入邮箱、验证时间、账号修订与审计；修改邮箱会清除验证状态。
5. 按用户最新要求，管理员创建/编辑用户、角色、授权与启停不再要求操作人当前密码。仍保留登录Session、CSRF、`users:manage`、全局账号管理事务锁、期待修订和审计。其他敏感操作继续当前密码确认。

## 契约与迁移

- `accounts-v1`升至`1.6.0`，新增邮箱验证请求/确认类型和两个Session+CSRF接口。
- 迁移`0045_email_verification`增加`users.email_verified_at`与`email_verifications`；开发库和隔离测试库均已应用。
- `UserCreate`、`UserSave`移除`current_password`，旧客户端需按1.6.0更新。

## 安全边界

- 只有当前登录账号可请求和确认自己的邮箱；Bearer、撤销会话和错误CSRF均拒绝。
- API响应和日志不返回验证码；短期待发送明文只在Worker读取后立即清空。
- 移除用户管理当前密码确认降低了step-up验证强度，用户明确接受该取舍；这不允许撤销CSRF、权限或审计边界。
