# ADR0099：文章级术语匹配与按需 Tooltip

版本：ADR0099-2。状态：已实现并验证。日期：2026-11-10。来源：用户要求先实现 Tooltip/术语表，并明确“文章出现术语时后端才向对应缓存提供该术语；没有出现的文章不提供”；随后要求术语正文与文章地位等价、Tooltip 支持富文本。

## 背景

术语表既需要可搜索的公开目录，也需要在不修改文章正文的情况下解释特定词汇。若把整份术语索引随每篇文章下发，正文命中很少时仍会传输和解析全部词条；若只在浏览器对所有词条做匹配，又无法在服务端保证文章范围、发布状态和语言边界。文章正文已有独立缓存，术语补充不应破坏或频繁重写该缓存。

## 决定

1. 术语数据由后端插件 `everunfold.glossary` 独立维护，使用标题、别名、简短提示、带稳定块 ID 的 Markdown/HTML 正文、语言和草稿/发布/归档状态；不写入文章正文或文章快照。
2. 公开目录使用 `/glossary` 和 `/glossary/{slug}`。目录只列出已发布词条，详情按语言读取。
3. 文章级接口 `GET /v1/plugins/everunfold.glossary/for-content/{content_id}` 在后端读取对应已公开发布内容的可见正文，匹配该语言已发布词条的标题和别名，只返回实际命中的词条及 `matched_texts`。没有命中时返回 `terms: []`，不返回整份索引。
4. 匹配前排除代码围栏、行内代码、Markdown/HTML 链接、HTML 标签和注释；中文术语可在普通正文内连续出现，ASCII 术语不能命中更大英文单词的一部分。同一词条的多个匹配文字按较长者优先。
5. 前端继续使用原文章 HTML 缓存。页面空闲后才懒加载术语组件，再请求当前内容的文章级匹配；结果按“API 地址 + 内容 ID + 内容修订”在内存缓存 5 分钟，空结果也缓存。术语请求失败不阻塞正文，也不把失败当成空结果永久缓存。
6. 浏览器只在普通可见文本节点上添加提示，跳过链接、按钮、代码、公式、脚本、隐藏文字和已有术语节点；页面范围提示数受站点设置限制，默认 20，范围 1 至 100。重复出现时优先最长别名且不重叠。
7. 提示支持鼠标悬停、触屏点击、Enter/空格、Tab 和 Escape；关闭后恢复触发词焦点。完整正文只有在设置选择“完整词条说明”时显示，并复用文章的安全渲染、代码/公式增强、媒体地址解析与短代码上下文；正文为空时回退简短提示。
8. 站点设置只保存 `site.glossary.auto_match`、`max_matches_per_page` 和 `popup_source`，不保存文章正文的派生匹配结果。

## 理由

- 后端是文章发布状态、语言和可见正文的权威来源，能防止未发布或不匹配的词条进入文章级响应。
- 文章级响应显著小于整份术语索引，并允许正文缓存与术语缓存独立失效。
- 保留完整术语目录可支持主动搜索，同时不把目录当作 Tooltip 的默认载荷。

## 影响与限制

- 新增 `glossary_terms`、`glossary_operations` 数据表和显式迁移；迁移 `0037_glossary_rich_body` 把旧单段 Markdown 转换为正文块，文章表、正文块和公开内容快照不增加术语字段。
- 术语不会自动改写正文或生成永久链接；同一段落被拆成多个内联节点时，不跨节点拼接匹配。
- 术语修改后，已打开的页面最多等待当前文章级缓存到期；重新发布或内容修订会更换缓存键。
- 当前匹配是安全的可见文本近似，不等于完整 HTML 渲染树的逐像素判定；作者短代码参数等非渲染正文仍需后续按真实渲染器收紧。

## 验证

- 真实 PostgreSQL/API 测试覆盖命中与未命中文章、代码/链接/标记排除、ASCII 单词边界、标题/别名冲突和修订冲突。
- 前端测试覆盖中文命中、最长别名、不重叠、单词边界、页面上限、空文章结果缓存，以及富文本代码/公式/媒体、HTML 过滤和空白正文回退。
- 实际远程页验证命中文章装饰 20 个提示、无命中文章装饰 0 个；桌面与手机查看完整富文本、公式、代码、表格，确认弹层无横向溢出，Escape 关闭和焦点恢复通过。
