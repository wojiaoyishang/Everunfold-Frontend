# ADR0116：多邮件发信配置与提醒路由

日期：2026-11-11。状态：已实施。

## 背景

原邮件功能只有一套全局 SMTP 配置，通知平台页只能显示“邮件可用”，再跳转到独立配置页。业务需要系统通知、客服回复或备用发信身份并存，同时让每条提醒明确使用哪套发信配置。平台、发信身份和提醒规则是三个不同层级，不能继续合并为一个布尔开关。

## 决定

1. 通知平台表示发送能力，发信配置表示邮件平台下的一套 SMTP 与发件人身份，提醒规则表示业务事件、接收人、平台和可选发信配置的组合。
2. 邮件配置并入 `/admin/notifications/platforms`。原 `/admin/settings/mail` 作为隐藏的兼容路由跳转到发信配置锚点，不再出现在后台菜单。
3. 一个站点最多保存20套邮件发信配置。每套配置有稳定 UUID、名称、启用状态、默认状态、SMTP 参数、发件人资料和只写密码。非空配置必须恰有一套默认配置。
4. 旧 `_mail_private.value/password` 单配置在读取时归一化为固定的“默认邮件配置”，首次保存多配置后写入稳定配置列表。密码和 SMTP 参数继续只存在于私有设置段，不进入公开投影。
5. 提醒规则的 `mail_profile_id` 可为空；为空表示投递时使用默认配置，显式选择则固定该配置。非邮件平台不能携带发信配置。
6. 投递生成时快照配置 ID 与邮件配置修订。排队后配置被修改、删除或停用时不静默换用其他账号，结果标记为抑制并保留明确原因。
7. 不自动轮询发信配置，也不在结果未知时跨配置故障转移。SMTP 的 `unknown-no-retry` 语义继续优先避免重复发信。
8. 账号邮箱验证始终使用默认发信配置；测试发件必须指定具体配置并使用其保存后的参数。
9. 删除仍被提醒规则引用的配置返回422，要求先改绑；测试和投递记录保留已发生的配置 ID，密码不进入审计或任务载荷。

## 契约与迁移

- `settings-v1`升至`1.32.0`：邮件状态改为 revision 与 profiles 列表；保存请求接收完整配置列表，每项支持只写密码、保留密码和清除密码。
- `notifications-v1`升至`1.1.0`：提醒规则与投递视图增加可选 `mail_profile_id`。
- 迁移`0046_multiple_mail_profiles`为提醒、投递、测试邮件和邮箱验证增加配置身份或修订字段；不回写或删除既有业务数据。
- 兼容路由仍登记为 `menu: null`，使 Proxy 继续识别为后台私有页面，同时不显示侧栏入口。

## 失败与权限

- 读取需要`settings:read`，修改与测试需要`settings:write`；保存继续使用站点行锁、独立修订、409冲突保护和审计。
- 配置缺失返回`email_not_configured`，配置修订变化返回`mail_configuration_changed`，不自动替换收件人、SMTP 或发件身份。
- 密码目前仍位于后端私有数据库设置中，未新增字段级加密。
