# ADR 0143：后端公开查询缓存与前端快照复用

FastAPI 的站点信息、分类标签和常用公开内容列表以 PostgreSQL 为准，在专用 Redis 实例短期保存公开响应。查询缓存默认开启；未配置或不可用时直接查库。队列、验证码、协同与任务状态继续使用原有 Redis。给专用实例配置独立内存上限与淘汰策略，不以 Redis 逻辑库编号替代资源隔离。

缓存键包含项目与环境、契约版本、发布来源和影响响应的数据库版本及归一化参数。缓存未命中时先查库计算结果，写入 Redis 前复查数据库版本；版本变化时跳过写入。事务提交后发起的新请求不会再使用旧版本的结果，发布链路无需等待缓存回调；TTL 用于清理旧键。按时间开放也必须切换缓存边界；权限、草稿、用户态、搜索和任意高基数筛选不进入共享缓存。节点同步仍由原有可靠事件驱动。

业务查询监控按总计和业务区分命中、未命中、绕过、查询错误、实际 SQL 次数和延迟。在原 Redis 汇总短期时间桶，即使专用缓存暂时离线仍可计入回源。只保存聚合计数及延迟分布；不保存参数、SQL 文本和访客身份。管理员页面「节点状态」及独立认证的后端诊断入口各自维持原有授权。指标按批写入，P95 由延迟桶估算。

Next.js 继续用无时间 TTL 的本地公开快照，并在各 Node.js 进程以有界内存复用已解析数据及路径索引。每次读取仍检查最新磁盘意图和文件完整性；已知新版本无法读取时不回退旧正文。此层不依赖后端 Redis，后端断连时此前有效的本地快照仍可读。
