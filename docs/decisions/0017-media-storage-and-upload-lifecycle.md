# ADR 0017：媒体上传与可切换静态分发

日期：2026-10-31。状态：**用户要求已记录，工程方案待实施；不是已上线能力或冻结 API**。范围来自本轮“先不要修改代码”，详细设计见 [media-storage-1](../architecture/media-storage.md)。

## 来源与现状

用户明确要求：文章等业务媒体经后台媒体库上传到后端、入数据库；无 CDN 时后端提供文件；默认提供静态 Base URL 和支持相对/绝对路径的 Uploads Path；未来可复制 uploads 后切换 Base URL，也可由 CDN/云存储接管上传，须预留二次开发接口。

v2.11 Q28/Q30/Q55/Q62 已要求稳定虚拟引用、原媒体不可变、派生共用媒体 ID、本地优先及可恢复删除；v0.14 给出媒体/变体/位置模型与 staging/ready/failed 提案。本方案细化这些边界。当前前端 `public/uploads/wordpress/`、内容内媒体 URL 和绝对头图 URL 是试导入交付，不再作为正式媒体库目标；其现有数据本轮不迁移。

## 建议选择

- 媒体身份、文件位置和公开分发地址分离。数据库记录逻辑媒体、文件表示、可核验的存储位置及引用；URL 由后端生成，正文沿用稳定引用。
- 建议 `[media].base_url` 缺省派生于 `BACKEND_BASE_URL + /media`，`uploads_path` 默认 `./uploads` 并相对于实际配置文件目录解析；这是新配置设计，当前加载器尚不支持。
- 正式文件采用 `YYYY/MM/<media_id>/original.ext` 及版本化派生 key，临时/隔离区放同文件系统的 uploads 外；整个 uploads 可按相同 key 复制到云端。列表依赖数据库，不遍历文件夹/远程桶，每个逻辑媒体一行。
- 核心统一授权、分配 key、校验、入库与幂等完成；provider 替换传输与存储，支持后端接收或受限云端直传。正式原图不得被重复签名上传覆盖，文件未验证和持久完成不得进入 ready 映射。
- CDN 分发与上传 provider 可独立切换；混合存储期间保留真实位置，云端不要求伪造本地副本。Base URL 变更须联动媒体映射、头图、站点配置、SEO 和前端缓存代次，不能仅靠改配置或 TTL。

## 后果与范围

不增加前端存储配置或独立的媒体字段事实源，不创建通用插件平台，不把目录改名当 CDN 迁移，不扩展独立媒体 ACL。相对路径基准、目录布局和接口能力是建议，实施时在正式契约/迁移中落实，不把文档示例加入实际配置。

本轮仅同步规范/索引/交接；无代码、配置模板、契约、依赖、数据库或媒体文件修改。后续先完成正式权限与本地媒体闭环，再按上述设计接云端；必须执行媒体一致性及对应多进程/缓存验收。
