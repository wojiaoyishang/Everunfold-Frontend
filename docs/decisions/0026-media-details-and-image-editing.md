# ADR 0026：附件详情、元数据与不可覆盖的图片编辑

日期：2026-11-01。状态：**已实现并验证**。实现版本：settings 1.4.0、迁移 0006_media_details。

## 来源与边界

用户要求参考已登录 WordPress 媒体库的附件窗口和基本图片处理，并追加标题、替代文本、图片说明、描述；明确允许开发阶段修改数据库结构。本决定补充 ADR 0025 的基础媒体库，不修改 v2.11/v0.14 原件不可覆盖、稳定引用、事实源和权限边界。WordPress 页面只读参考，没有保存修改。

## 决定

1. 独立媒体库使用网格/紧凑列表，点击资源打开附件详情。桌面预览与资料分栏，手机纵向滚动，标题与操作区固定；支持当前查询页内上一/下一附件。已有设置字段选择器继续点击选取，不能被详情窗口截走交互。
2. PostgreSQL `media_assets` 增加 `title`、`alt_text`、`caption`、`description`、`revision`、`source_id`、`edit_recipe`。既有行以空字符串/版本 1 兼容；文件名和物理 key 不随标题变化。迁移必须显式执行，服务启动不自动改表。
3. 元数据是媒体库的默认资料。修改它不会重写已发布文章块或产生新的图片 URL；将来正文仍可保存上下文专属 alt/说明。当前详情展示 MIME、大小、位图尺寸、上传时间、上传者和公开地址；不伪造引用计数、视频时长或关联文章。
4. 保存全量元数据时提交 expected_revision，以行锁保证比较/更新/审计同一事务。冲突返回 409，当前输入保留；重新读取前明确放弃本地修改。相同内容的重试直接返回当前资料，不重复增加版本或审计。正文值不进入审计，仅记录字段名。
5. 图片编辑支持静态 PNG/JPEG/WebP 的顺时针 90° 旋转、水平/垂直翻转、矩形裁剪和等比缩小。预览由主题组件封装 SVG/指针行为，键盘可用像素输入；服务端使用已有 Pillow 再校验和处理。顺序固定为 EXIF 方向归一化 → 旋转 → 画面坐标轴翻转 → 裁剪 → 缩小；裁剪坐标相对旋转/翻转后的像素空间。
6. 编辑始终「另存为新图片」：新媒体 ID、新 original key，保留 source_id 和规范化配方，复制来源的四项资料。裁剪/旋转属于主动改变图像内容，不是同一媒体的纯格式派生；将来的 WebP 转码变体仍共用原媒体 ID。旧图片与现有引用不替换。
7. edit_id 与操作者共同确定新资源身份。丢失响应后使用同一 ID/配方重试，跨 API 进程仍返回同一结果；不同来源/配方复用标识返回 409。沿用 staging → 文件不可覆盖发布 → ready/审计同事务；失败期间不分发 staging 文件。CPU 与文件操作不持有业务数据库读事务。
8. 当前不放大图片，边长/像素/字节限额沿用上传约束；服务端拒绝越界裁剪和类型错误。新图保留来源格式及 PNG/WebP 透明通道，不复制 EXIF/GPS。原文件字节不变。SVG/视频允许预览、资料编辑，当前不做像素处理/转码。
9. 管理请求由生成客户端直接访问 FastAPI，使用已有管理员 Session、精确 Origin、CSRF 和 private/no-store。详情/元数据不进入公开共享缓存。改变媒体标题无需重发站点设置；把新图用于头像/背景仍走既有设置保存和版本化同步。

## 分层与扩展

- 后端 `media/management.py` 管理用例，`image_processing.py` 纯图片处理，`service.py`/`storage.py` 负责已有身份与不可覆盖发布。路由不承担转换逻辑。
- 前端 `core/media` 负责请求、版本/重试身份与几何计算；主题 `admin/media` 负责浏览/详情/编辑；原生指针交互只在 `components/ui/image-crop-surface.tsx` 封装。其余控件复用 Button/TextField/TextArea/Modal/Icon。
- 当前处理器读取本地存储原件，不从浏览器提交任意 URL 拉取图片。CDN 仅分发时保留本地原件即可；未来远程存储提供器需提供受控读取能力，不能把公开 URL 当存储事实源。
- 元数据、引用图、回收站、变体/转码、批量管理是不同用例。本次没有实现删除 UI、引用统计、CDN 直传或媒体整体迁移。

验证、已知限制和操作步骤见 [媒体指南](../development/media-library.md) 与 [本轮验收](../handoff/media-editor-verification.md)。
