# ADR 0132：账号通知与插件事件总线

固定管理员的规则已由 [ADR0133](0133-registration-verification-and-notice-recipients.md) 修订。

后台使用同一事件目录配置账号邮件、运营提醒和插件事件。普通事件的接收人仍可选；账号安全事件固定为执行目标主体；自行注册成功和后台新增用户固定为管理员，默认启用站内通知。两者分别记录，不为同一个新用户重复发送。涉及账号安全的策略和模板写入需要 `settings:write` 和 `access:manage`。

注册、邮箱验证和找回密码的发码规则始终启用，默认继承「访问与安全」的发信配置，可单独覆盖。验证码与目标邮箱仍由认证流程绑定并交给专用 Worker。密码重置完成提醒默认启用，未覆盖时沿用重置码的发信配置和修订，允许独立停用。账号验证码不进入通用事件载荷、投递记录、插件平台或通知 API。

邮箱验证成功及两步验证启用、停用、更新恢复码和用恢复码登录属于可选提醒。它们与业务变更同事务登记，邮件只投递到事件发生时已验证且仍然有效的邮箱。总线只持久化所需的模板变量，不保存密码、验证码或两步验证凭据。

可信后端插件经 `registry.notifications.register_event` 注册命名空间事件，并使用 SDK 在业务事务中发布。事件目录只显示已启用且部署一致的插件。插件停用、卸载或版本未同步时保留规则与模板；不再向旧构建派发未处理的事件。插件事件 ID 保持稳定，触发去重键在各事件内隔离，事件载荷仅保留声明的标量变量。

后端显式迁移 `0055_notification_subjects`，前端锁定通知契约 1.6.0。见[通知指南](../development/notifications.md)。
