# ADR 0021：后台工作台与主题展示边界

日期：2026-11-01。来源：用户要求调研现有后台设计，后台简洁专业、视觉不必贴合博客前台，样式仍归于前端主题并保持架构整洁。

状态：用户方向已确认；具体视觉、布局与目录为设计提案，尚未改动 `/admin` 的运行实现。规范版本为 admin-ui-1、admin-research-1，开发协议升级为 development-5。

## 决定

1. 后台继续属于 Next.js 前端主题，和 public/auth 分为独立展示区域；复用封装控件、图标与交互语义，同时拥有后台独立的语义配色、布局密度和轻量动效。
2. 后台权限、请求、数据与业务用例留在 core/后端，主题只渲染展示模型与回调。不复制公共阅读缓存链路，不从演示身份授予权限。
3. 建议采用浅色侧栏的内容工作台；文章/说说共用内容列表，媒体以网格和详情为主，未有真实接口不填造假统计或业务入口。调研不等于引入 shadcn/Ant Design 等依赖。
4. 公共、登录、后台的样式与浏览器副作用显式分区。共享控件的弹层也继承所属区域 token；后台个人外观与前台阅读偏好分开保存。
5. 分阶段从当前 `management` 拆出 auth/admin，只在真实功能落地时建立目录与抽象，不预建多套空模块。方案和验收见 [后台设计](../architecture/admin-ui.md)。

## 被更新的既有说明

ADR 0018 的“配色、字体、圆角、图标和交互全部沿用 Everunfold 主题”描述了当时空后台。按本轮最新要求，未来后台视觉允许独立，仍由主题代码管理；不是要求沿用公开页面所有色彩、背景与动效。

ADR 0012 的“封装控件与主题变量”继续有效，变量改为按 public/auth/admin 区域提供；前台已有配色一致性要求不被取消。ADR 0019/0020 的通用登录、成功反馈、默认管理员回跳和会话去重仍有效。

## 理由与影响

单独展示区域满足后台工作效率，又保留未来主题替换能力。统一控件行为减少前后端页面各自处理焦点、弹窗、字段错误的重复。CSS import 与 JS 初始化不能仅靠目录隔离，必须验证前后台软导航后样式仍正确。

本轮产出为研究、设计、开发规范和会话设计预览，不改变后端接口、数据库、认证、依赖或服务进程。原始 v2.11/v0.14 文件不改写；计划接口和示例枚举不能替代后端发布契约。

## 后续验证

按 admin-ui-1 第 8 节先完成壳与样式隔离，再接真实内容/媒体。设计预览的样例及成功交互不代表实际上传、编辑、发布、权限或数据缓存已验收。
