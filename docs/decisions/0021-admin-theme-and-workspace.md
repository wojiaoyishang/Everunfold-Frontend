# ADR 0021：后台工作台与主题展示边界

日期：2026-11-01。来源：用户要求调研现有后台设计，后台简洁专业、视觉不必贴合博客前台，样式仍归于前端主题并保持架构整洁。

状态：用户批准样例，第一期运行实现已完成。规范版本 admin-ui-2；官方调研仍为 admin-research-1，开发协议仍为 development-5。内容编辑/媒体上传及其契约仍后续交付。

## 决定

1. 后台继续属于 Next.js 前端主题，和 public/auth 分为独立展示区域；复用封装控件、图标与交互语义，同时拥有后台独立的语义配色、布局密度和轻量动效。
2. 后台权限、请求、数据与业务用例留在 core/后端，主题只渲染展示模型与回调。不复制公共阅读缓存链路，不从演示身份授予权限。
3. 建议采用浅色侧栏的内容工作台；文章/说说共用内容列表，媒体以网格和详情为主，未有真实接口不填造假统计或业务入口。调研不等于引入 shadcn/Ant Design 等依赖。
4. 公共、登录、后台的样式与浏览器副作用显式分区。共享控件的弹层也继承所属区域 token；后台个人外观与前台阅读偏好分开保存。
5. 分阶段从当前 `management` 拆出 auth/admin，只在真实功能落地时建立目录与抽象，不预建多套空模块。方案和验收见 [后台设计](../architecture/admin-ui.md)。

## 被更新的既有说明

ADR 0018 的“配色、字体、圆角、图标和交互全部沿用 Everunfold 主题”描述了当时空后台。按本轮最新要求，未来后台视觉允许独立，仍由主题代码管理；不是要求沿用公开页面所有色彩、背景与动效。

ADR 0012 的“封装控件与主题变量”继续有效，变量改为按 public/auth/admin 区域提供；前台已有配色一致性要求不被取消。ADR 0019/0020 的通用登录、成功反馈、默认管理员回跳和会话去重仍有效。

## 理由与影响

单独展示区域满足后台工作效率，又保留未来主题替换能力。统一控件行为减少前后端页面各自处理焦点、弹窗、字段错误的重复。CSS import 与 JS 初始化不能仅靠目录隔离，必须验证前后台软导航后样式仍正确。

最初产出为研究、设计与会话预览；用户批准后现已实现后台壳、外观、导航和结构页，不改变后端接口、数据库、认证契约或依赖。原始 v2.11/v0.14 文件不改写；计划接口和示例枚举不能替代后端发布契约。

## 后续验证

按 admin-ui-2 第 8 节推进；壳与样式隔离已完成，下一步接真实内容/媒体。设计预览的样例及成功交互不代表实际上传、编辑、发布、权限或数据缓存已验收。

## 第一阶段实施记录（2026-11-01）

- 共享 `admin/layout.tsx` 保持壳；适配器连接 `core/admin/use-admin-access` 与主题 `AdminShell`。导航登记同时供侧栏、移动抽屉、面包屑和安全返回地址白名单使用；注册路径为 `/admin`、`/admin/content`、`/admin/media`。
- 登录仍在 `themes/argon/auth`，管理员缺省回工作台；明确后台子页面登录后回原页面，普通账号不能借返回地址进入后台。子路由变化合并后台会话复核，首次挂载保留严格模式下的请求去重。
- CSS 按 public/auth/admin 分区且显式限制根级选择器；共用 Popover/Select/Dialog/RouteLink，原有公开 AppLink 管理公开阅读事务。后台原生滚动、独立配色/密度，个人外观存储不含身份或业务数据。
- 当前内容/媒体工具栏禁用且说明准备中；不发布虚构业务字段、没有样例数据冒充主库，也没有实际上传操作。
- 增加 `npm run verify:admin`：隔离生产构建与实际 HTTP 进程验证，无可用后端、无公开快照仍可获得匿名私有壳；不会改动正常 3000/8001 或用户缓存。完整验证边界见 [记录](../handoff/admin-workspace-verification.md)。
