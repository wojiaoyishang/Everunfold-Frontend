# ADR 0031：真实内容发布同步与独立编辑页

2026-11-01 用户要求接通前台、移除硬编码文章/说说、独立编辑页及垃圾桶图标。本期已实现并验证，替代 ADR 0030 的“仅草稿/弹窗编辑”阶段边界；实际结果见 [验收](../handoff/content-publication-verification.md)。不替代未完成的协同、完整缓存生命周期与历史迁移计划。

- 保留现有真实公开数据；移除前端 exampleMoments 和示例 URL。后台工作草稿需明确发布才进入公开投影，保存未发布改动不覆盖已发布版本。删除已发布内容同事务撤回，恢复只恢复草稿。
- 文章、说说仍通过类型注册；编辑改为 /admin/content/{type}/new 与 /admin/content/{type}/{id}/edit。编辑请求、冲突及未知结果重试复用已有 core，展示仍归主题。所有删除使用垃圾桶图标；归档保持独立含义。
- 发布用例按版本更新工作稿与公开 contents、搜索投影、修订审计、不可变完整 release、逐节点 Outbox，同一数据库事务。草稿 ID 即公开 ID；首发自动生成 posts/shuoshuo 下 UUID 地址，标题修改不改址。此次不提供 slug/分类标签等细设。
- SiteSettings 增加独立 content_generation，设置 generation 不再充当内容同步水位。完整内容 release 固定公开快照、epoch 和版本，重试不得重新生成同版本不同内容。继承现有设置投递表/Worker/Scheduler 的可靠租约与退避，按资源分发到 /internal/cache/v1/apply；历史表名 settings_delivery_events 保留，不复制另一套任务基础设施。
- 接收器扩展现有专用 Node 监听端口，沿用已配置 settings_receiver_url、真实 socket IP AND Token 与节点/epoch 绑定，凭据不经浏览器。公开内容与设置分别落盘，无时间 TTL。内容接受后先落版本意图，再原子发布完整文件；最高已知版本缺失或损坏时拒绝旧快照，首次受管内容到达后不再回退 current.json。失序、重复和同版本冲突必须验证。
- 前台按请求读取完整最高已应用版本；尚未使用受管版本时保留原显式导出兼容读取。public 快照 0.2 支持 shuoshuo，兼容 0.1 原数据；历史文件名 public-v0.1.schema.json 保留，生成来源记录 0.2.0。content-admin 1.1 增加发布/撤回、公开地址与同步状态。后端发布新契约后前端重新生成，旧前端需先升级再启用说说发布。
- 首期采用完整快照分发（8 MiB 上限），没有增量分片、全站浏览器推送、节点心跳或自动磁盘回收。后台“已同步”指最后一次持久接收确认，不是实时在线声明。管理员可以重试同步修复节点丢失。Y.Doc 和代码页面完整注册继续后置。

实现补充：显式迁移 0010_content_publication；权威契约提交 a86479b，前端锁定该版本。重新同步沿用完整版本，操作记录写入审计；不由浏览器直接访问内部接收器。旧公开 WordPress 数据不变，本机四份既有后台示例已通过正式发布接口用于联调。前端不再拼接硬编码说说。

验证要求及结果见本轮验收：真实双 API + PostgreSQL、Worker/Scheduler、Node 接收器，发布幂等/竞争/审计故障回滚、离线重试、节点应用、撤回后失序拒绝旧数据和快照损坏失败关闭；前台无硬编码内容、独立编辑/浏览器访问/窄屏、发布到公开阅读和撤回消失。
