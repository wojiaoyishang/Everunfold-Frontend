## SEO 建议补齐

- 站点：首页标题、标题模板、默认描述、规范公开域名、站点图标、社交分享默认图片、公开作者/发布者身份。
- 内容级：标题/描述/分享图片覆盖、明确 canonical；默认由正式公开修订生成。内容级编辑归文章/页面编辑器，不塞到主题设置大表中。
- 索引：公开文章/页面/分类/标签的索引策略；搜索、预览、登录、后台、受限和不列入索引的内容默认不索引。`noindex` 不代替业务鉴权。
- 输出：canonical、Open Graph/分享卡片、Sitemap、robots、文章/面包屑等结构化数据；与公开页面使用同一已激活配置和修订。后台只有一个编辑入口，主题和插件提交结构化贡献，核心合并校验后生成。
- 多语言：实际有翻译关系时生成 hreflang；不预造不存在语言的链接。
- 搜索平台站点验证使用受限验证字段；不让普通配置插入任意 head 脚本。
- Keywords 可作为迁移兼容字段候选，**不列为 SEO 首期重点**。Google 明确忽略 meta keywords 对索引和排名的影响；不承诺填写 SEO 设置即可保证排名。
- 已确认的 URL 规则保留：WordPress 迁移尽量直接保留原 URL；后续改址不自动生成历史别名/永久重定向。

## 官方补充依据

读取日期：2026-11-01。以下用于核验机制，不用于擅自改变原始产品基线。

- [Google 支持的 meta 标签](https://developers.google.com/search/docs/crawling-indexing/special-tags)：description/robots/验证标签与 keywords 的区别。
- [Google noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing)：robots.txt 阻断抓取会使抓取器无法读取页面 noindex；不能把两者视为同一种开关。
- [Google canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)：canonical 与 Sitemap 等信号保持一致，不从任意请求 Host 拼装。
- [Google Sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)：公开规范 URL 与真实修改时间；不随访问时间伪造 lastmod。
- [Google Article 结构化数据](https://developers.google.com/search/docs/appearance/structured-data/article)：只从真实公开内容生成标题、作者、时间和图片。
- [Next.js generateMetadata](https://nextjs.org/docs/app/api-reference/functions/generate-metadata)：服务端统一元数据出口；按项目锁定版本实施。
