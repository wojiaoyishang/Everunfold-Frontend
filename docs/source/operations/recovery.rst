备份、导入与恢复
================

按目标选择资料
--------------

.. list-table::
   :header-rows: 1
   :widths: 31 69

   * - 目标
     - 需要保留
   * - 恢复整个站点
     - 配套的 PostgreSQL 备份、媒体原文件、主密钥与实例凭据，以及对应的代码、迁移和配置。
   * - 将部分内容带入另一站点
     - 后台导出的 Everunfold 原生 JSON 内容包，再准备目标站点上的媒体与其他相关资源。
   * - 恢复前端读者服务
     - 当前绑定的节点配置。快照及公开设置可由正确的后端重新同步。

整站恢复点
----------

.. figure:: /_static/diagrams/ops-backup-restore.svg
   :width: 100%
   :class: flow-diagram
   :alt: 整站恢复依次记录恢复点、在隔离环境还原、核对后端、按来源绑定节点，然后确认同步并切换流量。

   整站恢复及流量切换。数据库、媒体、密钥和配套代码组成恢复点。前端副本在核对来源与版本后重新同步。

1. 记录同一批前后端发布提交、插件版本、数据库迁移头及 ``source_epoch``。
   将正在运行的目标环境和备份范围记录在部署侧。
2. 使用 PostgreSQL 运维工具与文件存储备份能力保留一致的数据恢复点。
   PostgreSQL 备份应覆盖业务表、设置、草稿、鉴权记录和持久投递信息。
   将数据库备份与媒体原文件对应起来。
3. 通过已使用的密钥管理或加密备份工具保存应用主密钥和 TOTP 主密钥。
   节点方向凭据和 SMTP 等部署配置按实际恢复方式留存。保存与恢复应由相同的站点授权控制。
4. 在隔离环境演练恢复。部署新实例时给 Redis 配置单独作用域和任务环境，
   使用隔离的节点副本目录，并在启用外部投递前核对队列、接收器绑定和站点地址。
5. 恢复数据库与媒体，启动匹配版本。按实际升级方案显式验证或迁移表结构，
   检查 API 就绪、管理员登录、内容和媒体读取，再启动正式 Worker 与 Scheduler
   执行待恢复工作。

恢复后的节点
------------

读者节点持久保存已应用版本。同一数据库较早的备份可能具有相同的来源 UUID、
较低的版本号。用单独存储空间或新绑定验证恢复库时，应避免让恢复库接管仍服务线上地址的旧节点。
如计划替换线上数据，维护窗口中核对来源代际和目标目录的对应关系，让节点按已确认的当前版本
重新同步。旧副本保留在隔离位置以供核查。

重新同步后，用一条可公开内容和匹配的站点设置验证后台回执及读者页，
并检查节点磁盘版本、媒体资源及此前撤回和受限的内容访问。通过后再切换读者流量。
前端快照表达公开读者状态。草稿、会话、完整媒体文件与运维凭据来自数据库、媒体或部署备份。

原生数据包
----------

用管理员账号打开「设置 → 节点状态与维护」，点击页面右上角的「站点维护」，
再在右侧快速导航选择「数据导出」或「数据导入」。

导出内容
~~~~~~~~

打开「数据导出」（``/admin/settings/nodes#maintenance-export``）。

.. figure:: /_static/screenshots/maintenance-export.webp
   :width: 100%
   :figclass: annotated-shot
   :alt: 数据导出的类型勾选项、内容状态及修改时间字段，以及导出 JSON 按钮。

   数据导出表单。

① 在「导出范围」勾选要导出的类型。若只需要特定时间段的文章，
只勾选「文章」并填写「修改时间起」「修改时间止」。也可以按「内容状态」缩小范围。

② 点击「导出 JSON」，在浏览器下载列表中找到导出的文件。

每份 ``everunfold-content`` 版本 1 的 JSON 最多 2,000 条记录或 16 MiB。
计划导入到另一套实例时，先核对目标语言、页面插件、引用及媒体。文件保留媒体引用，
媒体原文件和用户凭据分别处理。需要保护的正文还应在目标站点设置访问密码。
若勾选了「公开站点设置（仅导出）」，可从文件查阅设置，再到目标站点的设置页手动应用。

预览并导入
~~~~~~~~~~

在目标站点打开「数据导入」（``/admin/settings/nodes#maintenance-import``）。

.. figure:: /_static/screenshots/maintenance-import.webp
   :width: 100%
   :figclass: annotated-shot
   :alt: 数据导入的初始界面，显示说明和选择数据包按钮。

   数据导入的文件选择入口。

① 点击「选择数据包」选择一份原生 JSON 文件。

② 卡片说明提示先预览再导入。选择文件后系统会自动生成预览，存在可导入记录时才可确认。

1. 核对「可导入」「已存在」「有冲突」「无法导入」，可按状态筛选并查看具体原因。
   补齐缺少的语言、插件、媒体或关联记录后，重新选择数据包生成预览。
2. 存在可导入记录时，点击「确认导入」并核对确认窗中的结果摘要。
   导入以本次预览返回的摘要为准。若提示站点数据已变化，关闭窗口并重新选择数据包。
3. 完成后在「导入记录」核对回执。新增正文类记录保存为草稿，新增评论进入待审核。
   打开导入的内容检查关联资源，按需要发布或审核。

前端节点清理旧版副本的操作见 :doc:`diagnostics`。整站发布切换记录见
:doc:`../release/prerelease`。
