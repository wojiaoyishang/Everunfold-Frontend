备份、导入与恢复
================

按目标选择资料
--------------

.. list-table::
   :header-rows: 1
   :widths: 31 69

   * - 目标
     - 需要保留
   * - 恢复整个站点
     - 配套的 PostgreSQL 备份、媒体原文件、主密钥与实例凭据，以及对应的代码、迁移和配置。
   * - 将部分内容带入另一站点
     - 后台导出的 Everunfold 原生 JSON 内容包，再准备目标站点上的媒体与其他相关资源。
   * - 恢复前端读者服务
     - 当前绑定的节点配置。快照及公开设置可由正确的后端重新同步。

整站恢复点
----------

1. 记录同一批前后端发布提交、插件版本、数据库迁移头及 ``source_epoch``。
   将正在运行的目标环境和备份范围记录在部署侧。
2. 使用 PostgreSQL 运维工具与文件存储备份能力保留一致的数据恢复点。
   PostgreSQL 备份应覆盖业务表、设置、草稿、鉴权记录和持久投递信息。
   将数据库备份与媒体原文件对应起来。
3. 通过已使用的密钥管理或加密备份工具保存应用主密钥和 TOTP 主密钥。
   节点方向凭据和 SMTP 等部署配置按实际恢复方式留存。保存与恢复应由相同的站点授权控制。
4. 在隔离环境演练恢复。部署新实例时给 Redis 配置单独作用域和任务环境，
   并在启用外部投递前核对队列、接收器绑定和站点地址。
5. 恢复数据库与媒体，启动匹配版本。按实际升级方案显式验证或迁移表结构，
   检查 API 就绪、管理员登录、内容和媒体读取，再启动正式 Worker 与 Scheduler
   执行待恢复工作。

恢复后的节点
------------

读者节点持久保存已应用版本。同一数据库较早的备份可能具有相同的来源 UUID、
较低的版本号。用单独存储空间或新绑定验证恢复库时，应避免让恢复库接管仍服务线上地址的旧节点。
如计划替换线上数据，维护窗口中核对来源代际和目标目录的对应关系，让节点按已确认的当前版本
重新同步。旧副本保留在隔离位置以供核查。

重新同步后，用一条可公开内容和匹配的站点设置验证后台回执及读者页，
并检查此前撤回和受限的内容访问。前端快照表达公开读者状态。草稿、会话、
完整媒体文件与运维凭据来自数据库、媒体或部署备份。

原生数据包
----------

管理员浏览器会话可在「设置 → 节点状态与维护」展开「站点维护」。
一次导出生成 ``everunfold-content`` 版本 1 的 JSON。可按类型、状态和修改时间筛选，
单份最多 2,000 条或 16 MiB。内容包可包括文章、说说、页面、术语、分类、标签、评论、
模板及可选的公开站点设置。

1. 选择需要的记录并导出。准备与目标端匹配的语言、页面插件、引用及媒体资源。
   媒体原文件和用户凭据分别处理。需要保护的正文仍须在目标站点设置相应的访问密码。
2. 在目标站点打开「数据导入」，选择原生包并执行预检。核对新建、跳过、冲突和阻塞，
   按报告补齐引用或处理资源冲突。
3. 确认导入使用预检绑定的数据包摘要。目标情况发生变化时，重新预检。
   完成后在「导入记录」核对回执。新增正文类记录从草稿开始，新增评论进入待审核。
   导入后按内容编辑流程逐项检查并发布。

前端节点清理旧版副本的操作见 :doc:`diagnostics`。整站发布切换记录见
:doc:`../release/prerelease`。
