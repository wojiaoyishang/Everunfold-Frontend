架构与术语
==========

一次请求去哪一端
----------------

读者打开站点时，Next.js 根据主题、站点设置与公开内容副本渲染页面。
浏览器调用业务接口时使用公开 API 地址。登录、草稿、后台修改和实时统计
由 FastAPI 根据请求和账号权限处理。

.. list-table::
   :header-rows: 1
   :widths: 29 35 36

   * - 对象
     - 权威数据
     - 谁消费
   * - 草稿、用户、配置
     - PostgreSQL 中由后端维护的记录
     - 后台业务接口、Worker 与授权预览
   * - 公开内容与设置
     - 后端产生的公开投影
     - 各前端节点落盘后供读者请求使用
   * - 动态数据
     - 浏览量、评论等各自的业务接口
     - 浏览器或服务器按实际读者权限获取
   * - 查询缓存
     - 从后端公开读查询派生的短期缓存
     - FastAPI，用于减少重复查库

从编辑到浏览
------------

一次内容更改可能经过草稿、发布版本、投递记录和节点应用。后台保存草稿时，
读者仍看到已经发布的版本。发布后由后端安排节点投递，节点应用完成后读者才看到新内容。
运维可从页面同步状态和节点状态定位进度。Redis 中的队列和缓存可以帮助传递消息，
PostgreSQL 保存用于恢复的业务与任务记录。

常用术语
--------

.. glossary::

   前端节点
      一个有稳定 ID 的前端运行实例或逻辑部署目标。节点 ID 与后端清单对应，
      前端和后端各自维护其连接配置。

   来源 UUID
      后端的 ``source_epoch``，接收器用它识别快照属于哪个来源。
      更换数据库或恢复时核对这个值，再决定如何同步与绑定。

   内容快照
      已发布且允许公开的内容投影。授权预览、草稿和受限正文在各自的私有访问链路读取。

   页面类型
      一套页面实现和配置约定。多个实例可以共用同一类型，每个实例有自己的地址及参数。

   自定义页面模板
      可应用到多个页面的共享结构，具有草稿和已应用版本。模板的应用会影响引用页面。

   契约
      前后端共同遵守的接口、业务对象、同步事件及相关约定。前端按锁定的后端提交生成类型。

后台操作见 :doc:`../usage/index`。部署中的地址、代理和内网流量见
:doc:`../operations/topology`。
