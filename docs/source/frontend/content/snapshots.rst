公开快照、节点投递与缓存
========================

数据从哪里来
------------

后端提交发布事务后，由任务进程为目标节点投递公开内容版本。
前端的独立 Node.js 接收进程从 ``tools/settings-receiver.mts`` 启动，
路由处理在 ``src/server/settings/receiver.ts``。接收器校验部署身份、来源与数据结构，
确认内容已落盘后才应答。页面请求先在 ``src/core/content/snapshot.ts`` 读取
已应用的内容及设置副本，再从结果中查找路由和展示内容。

.. list-table::
   :header-rows: 1
   :widths: 42 58

   * - 位置
     - 用途
   * - ``[cache].directory``
     - 公开内容版本。使用独立后端连接配置时自动按来源 UUID 分隔。
   * - ``[settings].directory``
     - 已应用的站点公开设置与节点缓存策略，按节点和来源分隔。
   * - ``src/server/content/store.ts``
     - 校验来源和内容版本，写入版本意图和快照并验证摘要。
   * - ``src/server/settings/store.ts``
     - 读取和应用不同种类的公开设置副本。
   * - ``/health/ready``
     - 直接访问 Next.js 的就绪端点，检查可否读到有效公开快照。容器开发代理会把
       ``/health/*`` 转发给后端，响应中的 ``data.public_read`` 可用于辨认前端探针。

一次投递如何进入公开阅读
------------------------

.. figure:: /_static/diagrams/frontend-snapshot-apply.svg
   :width: 100%
   :class: flow-diagram
   :alt: 接收器校验公开版本，先记录版本意图再写入快照，成功后返回持久回执；读请求选择当前已知版本，缺失或损坏时返回服务不可用。

   接收器写入公开内容后，读取进程可在本地装载新版本。

1. Worker 将 ``public-content`` 投递到接收器的 ``POST /internal/cache/v1/apply``。
   接收器检查来源、节点、服务间凭据和消息结构。站点公开设置走独立的
   ``POST /internal/settings/apply``，由设置存储应用。
2. ``FileContentStore.apply()`` 第一次写入时建立来源与节点的管理标记，随后写入修订号对应的
   ``.intent.json`` 和 ``.snapshot.json``。意图文件保存快照摘要且先于快照写入。
   重发同一版本使用相同内容；同一修订号的不同内容会被拒绝。
3. 文件写入完成后，接收器回传节点、来源、资源、修订、请求摘要及 ``durable: true``。
   Worker 核对回执再更新投递记录。读取端可在快照完整落盘后直接使用新版本，无需等待 Worker 更新记录。
4. ``readPublicSnapshot()`` 读取当前已知的内容修订，装载已应用的站点设置，并按当前插件可用性过滤。
   ``src/proxy.ts`` 和阅读视图用这些数据查找路径。修订意图刚写入而快照尚未落盘时，最新修订可能暂时不可读。

版本与故障
----------

- 节点从已应用的修订读内容，没有按时间到期的快照 TTL。后端临时不可达时，
  已有的完整公开版本仍可用于公开阅读。
- 接收器一旦知道有更新的版本，若新快照写入失败或文件损坏，
  不能回退到可能已经撤回的旧正文。缺失或校验失败会触发服务不可用；
  在有效快照中确定无该路径时返回 404。
- Next.js 框架缓存属于派生状态。调整失效逻辑时保留来源、资源和修订，复用现存的
  缓存和同步路径。更新测试应覆盖后端完成、节点尚未确认以及节点已应用三个时点。

操作排查
--------

在后台「节点状态与维护」查看公开设置与内容的同步状态，确认关注的是目标节点。
部署切换时读实例配置中的当前后端地址和来源 UUID；检查运行进程使用相同目录，
再从节点界面发起重新同步。与 ``config.toml`` 及独立连接文件相关的说明见
:doc:`../architecture/requests`。

用开发实例验证发布链路时，可发布一篇含唯一识别文字的测试文章，记录后台显示的修订与节点状态。
待节点确认后，重新访问文章并直连 Next.js 的 ``/health/ready``，核对识别文字和就绪响应。随后撤回该文章，
等新修订应用后访问原地址，预期返回 404。测试修订冲突、意图已写入但快照缺失等故障时，
使用 ``tests/content-store.test.ts`` 的临时目录，避免改动运行实例的快照。
