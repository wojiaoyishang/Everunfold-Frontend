文章、说说与协作编辑
====================

定位源码
--------

工作台从 ``src/app/(management)/admin/content/[type]/`` 分派文章与说说。
``src/core/content-management/`` 提供表单、编辑操作、版本、私有预览与发布状态，
``src/themes/argon/admin/content/`` 负责界面。

区块模式保存带稳定 ID 的有序 Markdown 或 HTML 区块。``src/core/editor/``
维护文字位置、源码与可视编辑映射、区块操作和版本差异。拖动、撤销及变更类型
通过宿主命令使用稳定的区块 ID。媒体插入使用共享媒体选择器或上传队列。
源文中保留资源引用与插入调用；阅读时的 HTML、代码高亮、公式和媒体地址
由相应渲染器生成。

协作与本地恢复
--------------

.. figure:: /_static/diagrams/frontend-collaboration.svg
   :width: 100%
   :class: flow-diagram
   :alt: 工作草稿在浏览器中生成 Yjs 更新，经协作 WebSocket 提交后由服务端返回持久回执，断线后的输入保留到本地分支。

   协作草稿通过更新序号和回执逐步对齐服务端状态。

1. 先保存新稿以取得稳定资源 ID。每篇语言稿件的共享工作状态由一个 Y.Doc 保存，
   再通过受权限保护的协作票据接入 WebSocket。服务器下发 ``sync`` 帧时携带协作世代
   （``epoch``）和已提交序号（``committed_seq``），作为之后接收增量的基线。
2. ``src/core/collaboration/session.ts`` 维护当前文档、在线状态、待提交更新和确认基线。
   本地编辑生成带 ``update_id`` 的待提交更新。后端提交数据库事务后，发送 ``ack`` 帧；
   发送窗口据此清理对应的待发送记录。其他窗口按 ``update`` 帧中的提交序号合并更新。
   成员光标与选区属于临时在线状态。
3. ``local-store.ts`` 以 IndexedDB 在一笔事务合并本地状态、队列与已确认的更新编号，
   避免并行标签页覆盖彼此的进度。不要为单个编辑面创建另一份协作文档。
4. 离线后可在本地分支继续编辑。恢复连接时先确认账号权限，再比较并合并分支。
   若协作世代已切换，旧世代尚未确认的输入保留在恢复草稿中，由编辑者检查差异。
5. 编辑者可保存版本，再按需发布。发布后依照 :doc:`snapshots` 更新公开内容。
   同一语言组里的各篇稿件有独立的修订和发布时机。

组件模式与预览
--------------

组件模式使用 ``src/core/builder/`` 中的文档树和字段定义。文章和说说在此模式下
编辑组件树，当前不参加正文区块协作。预览使用当前主题和设备宽度，
可视化编辑通过宿主保存路径保存草稿；发布时仍遵循文章或说说的发布流程。

编辑页内的正文预览用于即时检查排版。正式主题的私有预览读取已保存草稿，
通过 ``/admin/content/<type>/<id>/preview`` 打开；无权访问时提示失败。
两者都不形成公开版本。

验证一次编辑器改动
------------------

1. 用两个窗口打开同一篇测试草稿。分别改动两个位置，检查两窗内容是否一致，再用其中一个窗口
   排序区块并执行撤销，确认本人操作能恢复。
2. 在一个窗口的 Network 面板切到 Offline，进入本地分支后加入一段便于识别的文字。
   用另一个在线窗口修改草稿。让离线窗口恢复连接并查看差异，确认合并后保留两边的预期内容。
3. 保存版本并查看版本差异和私有预览。若还要验证公开发布，发布后检查目标节点的应用回执与读者视图。

回归测试见 ``tests/collaboration.test.ts``、``tests/collaboration-receipts.test.ts``、
``tests/collaborative-recovery.test.ts`` 和 ``tests/content-preview.test.ts``。
