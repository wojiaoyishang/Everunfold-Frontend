内容编辑、发布和读取
====================

编辑与发布
----------

文章和说说的工作草稿与公开发布版本各自推进。编辑器在
``src/core/content-management/`` 处理表单、修订、预览和发布，在
``src/core/collaboration/`` 处理协作状态。编辑器展示位于 Argon 后台主题。

1. 正文是有序区块，每个区块有稳定的 ID、类型和源文。移动区块时保留区块 ID；
   Markdown 或 HTML 编辑沿用当前区块的内容表示。
2. 同语言的工作草稿使用一个 Yjs 文档。浏览器向后端协作 WebSocket 提交更新，
   持久回执代表后端已提交到 PostgreSQL。光标和选区属于临时在线状态。
3. 本机恢复数据及未确认更新保存到 IndexedDB。重新连接后先确认授权，再处理恢复或分支。
   离线分支通过版本比较和合并回到工作草稿。
4. 发布、撤回、回收和定时发布是独立的业务操作。发布时生成公开版本，
   后端通过可靠投递通知前端节点。后台可查看内容同步状态。
5. 草稿和历史版本的前台预览使用独立的管理路径和授权，不进入读者快照。

扩展编辑器时，复用宿主的区块、媒体选择和提交能力。表单字段增强使用
``formFields.register``，字段回填由宿主执行。组件模式文档走对应编辑器的
组件树和保存流程。

各语言版本有独立的内容 ID、修订和发布状态，并通过翻译组关联。读者路径决定页面语言；
只使用已发布的翻译版本。后台界面语言与内容语言可分别选择。

节点公开快照
------------

公开内容和已应用的站点设置写入节点的本地副本。内容存储处理位于
``src/server/content/store.ts``，设置保存和接收位于 ``src/server/settings/``。
``src/core/content/snapshot.ts`` 为公开渲染提供读者数据。Next.js 可从有效快照
渲染已有公开页面，减少日常访问对后端的依赖。

- 快照按修订应用，没有按时间失效的 TTL。后端暂时不可达时，仍可读取节点已有且允许公开的完整快照。
- 节点收到撤回或改为受限的更新后，较旧的公开内容停止使用；列表、搜索和索引也须遵循可见性。
- 无效或缺失的快照可返回 HTTP 503；在有效公开版本中确认不存在的内容返回 HTTP 404。
- Next.js 的框架缓存是从公开数据派生的状态。处理版本变化时，沿节点投递和现有缓存管理流程，保留修订保护。

受限内容与主题渲染
------------------

私有预览、需访问挑战的正文及受保护短代码使用各自的授权读取流程。公开列表和快照只保存
后端允许分发的数据。在公开阅读组件中增加导出、索引或社交卡片时，继续按公开资格过滤
正文、标题、摘要和链接。公开的媒体文件仍使用它自己的分发规则。

Markdown、HTML、短代码、公式和媒体统一进入正文渲染流程。需要在读者页面展示插件
生成的 HTML 时，使用宿主的清理及媒体处理规则。在 Markdown、HTML、协作编辑和历史比较
中保留源文，代码高亮和公式排版属于展示结果。涉及账户状态或权限的增强读取通过原有业务
接口完成。
