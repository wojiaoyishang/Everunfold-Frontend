开发检查与验证
==============

工具链
------

使用 Node.js 22 和 npm 10。支持范围在 ``package.json`` 中声明，
``.nvmrc`` 给出开发所用 Node.js 版本，``package-lock.json`` 锁定依赖。
在前端仓库根执行安装和检查，Windows PowerShell 可用 ``npm.cmd``。

.. code-block:: console

   $ npm ci --ignore-scripts
   $ npm run check

``npm run check`` 会准备锁定契约、主题资产和生成文件，检查扩展声明、错误页产物、
ESLint、宿主与插件类型、Prettier 格式，再运行自动测试。预发布验收还需要生产构建，
以及对涉及的运行链路做隔离验证。

.. list-table::
   :header-rows: 1
   :widths: 38 62

   * - 命令
     - 用途
   * - ``npm run typecheck``
     - 生成 Next.js 路由类型，并检查宿主 TypeScript。
   * - ``npm run plugins:typecheck``
     - 按独立插件配置检查公开 SDK 导入、组件与声明。
   * - ``npm run build``
     - 先构建独立插件包，再构建 Next.js 主应用。
   * - ``npm run verify:production``
     - 在临时副本构建并检查生产应用，可与正在运行的开发实例并行。
   * - ``npm run verify:reader``
     - 启动隔离的 Next.js 和 FastAPI，检查公开阅读、离线快照和管理入口隔离。
       需要已配置的测试快照和后端检出，通过 ``READER_BACKEND_ROOT`` 指定后端目录。
   * - ``npm run verify:admin``
     - 以生产配置验证后台生产运行路径，使用隔离测试环境。
   * - ``npm run verify:http -- <站点地址>``
     - 向已启动的前端检查 HTTP 响应。使用已准备好公开快照的测试站点。

验证一次改动
------------

1. 记录改动经过的路由、后端契约、权限、快照或扩展入口。调整数据结构时确认已有
   草稿、发布版本及插件设置仍可读取。
2. 运行相关测试及完整检查。浏览器界面按桌面和窄屏检查布局、键盘焦点、弹窗退出、
   加载与失败状态。对动效检查后台或前台各自的减少动态偏好。
3. 如果改动涉及发布、缓存、协作或授权，使用隔离的前后端、数据库、Redis
   和所需后台进程验证真实链路。按用例核对后端提交、节点应用及读者最终视图。
4. 把源码、适用的文档和构建配置放在同一变更中。使用示例配置说明参数，
   将实际配置、插件构建产物、快照和用户数据留在本地运行环境。

排查运行问题
------------

- 开发时，先检查应用和后端的 ``/health/ready``，再核对浏览器请求的 API 根地址
  与会话响应。已有公开页面可读时，后台仍可能因 API、浏览器来源或 Cookie 配置而失败。
- 已保存的公开内容未出现时，查看后台的节点状态和内容同步状态，确认目标节点
  使用对应的站点设置和已应用内容修订。
- 插件未出现时，检查独立构建输出、节点清单登记、插件是否启用，以及当前账号
  是否具有所需权限。修改宿主 SDK 或独立编译工具后，重启开发协调进程。
