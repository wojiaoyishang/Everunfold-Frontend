请求、实例配置与契约
====================

确认请求发起方
--------------

浏览器访问 ``PUBLIC_SITE_URL`` 下的 Next.js 页面和静态资源。业务读取与写入通常使用
``BACKEND_BASE_URL`` 下的 FastAPI ``/v1/*``。有独立服务器连接时，Next.js 的
``[backend].base_url`` 可以指向部署内的 API 地址。接收器是另一个 Node.js 进程，
供后端向稳定的前端节点投递公开版本。

受保护的浏览器请求带 HttpOnly 会话 Cookie。写操作使用后端确认的
``X-CSRF-Token`` 和配置允许的来源。后台宿主先通过会话读取确定用户和权限，
再传递给页面与插件。请求结果按 HTTP 状态和稳定业务码判断；``msg`` 用于展示。
SSR 的公开阅读内容、用户态请求和草稿预览分别走各自的数据入口。

实例配置
--------

``src/core/config/files.ts`` 由 Next.js、节点接收器和扩展清单上报器共用。
在项目根使用 ``config.toml``，或通过 ``CONFIG_FILE`` 指定文件。理解以下约束有助于排查多节点部署。

- ``FRONTEND_NODE_ID`` 须与后端登记的节点一致。来源 UUID 来自实际后端；
  节点绑定来源后才接收对应的公开版本。
- 内联连接设置写在主配置。使用 ``backend_node_file`` 时，公开 API 地址、
  服务器连接及来源写在当前连接配置，由 ``active`` 选中。
- ``[cache]`` 管理公开内容快照目录，``[settings]`` 管理已应用设置及接收器监听。
  令牌配置填写环境变量名，值由各服务继承。运行目录与实例文件保留在部署侧。
- 连接相关设置改变后重新启动节点接收器，并重新核对绑定和同步状态。
  部署步骤和同源开发代理配置见 :doc:`../../welcome/deployment`。

同步后端类型
------------

``contracts.lock.json`` 固定后端提交、契约文件与摘要。恢复时优先读取本地配对的后端
检出，可用 ``EVERUNFOLD_BACKEND_PATH`` 指定路径；锁定提交必须在该检出的 Git 历史里。
``npm run contracts:prepare`` 恢复 ``var/cache/contracts/`` 下的生成物。
提交后端契约变更时，应更新前端锁并复查请求、响应、默认值和错误处理。
运行时模块从 ``src/core/contracts/`` 使用稳定业务入口，供 UI 和节点共用。
