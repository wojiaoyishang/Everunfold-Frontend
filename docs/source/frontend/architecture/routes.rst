路由、布局与工作台
==================

从进程启动到首屏
----------------

.. figure:: /_static/diagrams/frontend-first-render.svg
   :width: 100%
   :class: flow-diagram
   :alt: Next.js 将打开页面的请求分为公开阅读和后台两路，前者读取公开快照，后者由浏览器确认账号会话。

   公开首屏和后台工作台从各自的数据源加载。

1. ``npm run dev`` 先准备宿主依赖的契约、主题和静态资源。``tools/plugins/run.mts``
   在开发模式下启动插件编译监听，再启动 Next.js 子进程。生产部署在构建后运行 ``npm start``，
   由同一脚本启动 ``next start``。页面进程与节点接收器间的分工见 :doc:`requests`。
2. 浏览器导航请求按 ``src/proxy.ts`` 的 ``matcher`` 分类。静态资源、就绪探针、站点地图
   和订阅响应等由各自路由直接处理。
3. 公开请求读取本地快照，确定路径对应代码路由、托管页面或已发布内容，再选择内容语言。
   默认语言启用路径前缀或术语路径需要规范化时，代理按对应条件返回 307。
4. 首页 ``src/app/(blog)/page.tsx`` 把已生效快照传给 ``CodePage``。首页绑定了自定义页面时，
   由阅读设置确定该语言下使用的页面。公开布局加载活动主题，组合导航、站点信息和正文；
   详情路径由 ``[...contentPath]/page.tsx`` 选择相应阅读视图。
5. 已登记的后台工作台路由从代理直接进入管理布局。工作台先展示加载状态，再由浏览器确认后台会话。
   确认后加载后台菜单和插件；收到未登录响应时通常跳往带返回地址的登录页，
   若有符合条件的本地恢复草稿则先提供恢复。页面可以依靠这条路径排查会话和代理配置。

公开路由
--------

``src/app/(blog)/`` 提供首页、文章和说说列表、分类、标签、归档、搜索、术语等
公开入口。括号中的路由组用于共用布局。带参数的路由使用 ``[slug]`` 等目录，
由 Next.js 将路径片段交给页面。任意已发布内容和托管页面的路径交给
``src/app/(blog)/[...contentPath]/page.tsx``，根据站点公开快照分派到相应主题视图。

``src/proxy.ts`` 在 App Router 之前处理路径与访问面的边界。新增公开固定路由时，
需要同时检查它在 ``src/core/content/routes.ts`` 中的登记与冲突规则。
分类或标签详情等动态公开页需要分别核对原始路径、语言前缀和不存在的资源。
可配置的页面用 :doc:`../extensions/public-components` 的页面类型登记实现。
阅读页返回 404 或 503 的判定见 :doc:`../content/snapshots`。

管理路由
--------

``src/app/(management)/`` 组织登录、账号中心、工作台、内容预览及后台工具。
``admin/layout.tsx`` 和 ``admin/workspace.tsx`` 负责进入工作台的会话边界。
应用在确认会话后显示后台壳与管理员插件，API 权限仍由后端逐请求检查。

内置菜单由 ``src/core/admin/`` 的注册器和各业务模块提供。后台主题负责菜单、
面包屑、窄屏抽屉和共享控件。新增宿主页面时更新相应注册声明及路由权限；
插件页面通过 :doc:`../extensions/admin-plugins` 注册。测试应同时覆盖从导航进入和
直接打开地址。

特殊路由
--------

.. list-table::
   :header-rows: 1
   :widths: 45 55

   * - 路径
     - 读取来源
   * - ``/admin/content/<type>/<id>/preview``、``/admin/pages/<id>/preview``
     - 授权读取保存后的草稿，展示时复用公开阅读主题。
   * - ``/admin/_nodes``
     - 前端节点诊断入口，对应 ``src/app/(node-console)/``。
   * - ``/health/ready``
     - 直连 Next.js 时检查当前前端配置和公开快照状态。
   * - ``/robots.txt``、``/sitemap.xml``、``/feed.xml``、``/atom.xml``
     - 按已应用设置及公开内容生成的索引或订阅响应。

验证首屏与请求分流
------------------

在已同步的开发实例上访问首页、一个已发布的详情页、一个不存在的地址和一个后台编辑地址。
在浏览器的 Network 面板查看文档响应和后续 API 请求。

- 首页和详情页检查服务端返回的正文与 ``Content-Language``。按站点设置启用语言前缀后，
  访问应重定向的基础路径，核对 307 和目标语言路径。
- 在有效快照上访问不存在的公开路径，预期 404。若 Next.js 的就绪探针与公开文档都返回 503，
  先检查 :doc:`../content/snapshots` 中的来源和快照状态。
- 用未登录窗口打开已登记的后台地址，检查文档的 ``Cache-Control`` 包含 ``no-store``，
  ``X-Robots-Tag`` 包含 ``noindex``。再观察后台会话请求与跳转，登录后重试同一地址。
