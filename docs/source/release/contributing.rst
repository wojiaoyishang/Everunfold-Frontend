维护手册
========

从哪里写
--------

每个仓库的可发布文档位于 ``docs/source/``。网站管理员需要的操作放在
``usage/``，安装与部署步骤放在 ``welcome/`` 和 ``operations/``。
编译、源码、接口和宿主扩展分别收在 ``frontend/`` 或 ``backend/``。
部署与使用两套共享章节改动应同步到两个仓库，以便读者从任一手册进入。

写一个专题页
------------

1. 标题使用实际模块或任务名。先交代用途、所需角色和前置条件。
2. 给出执行路径或最小示例。命令明确工作目录与环境，配置值用自己的
   占位域名、路径或环境变量名称。
3. 写清完成后能看到的结果。区分已保存、已发布、后台任务已执行和节点已应用。
4. 写出最常见的失败表现与检查入口。共用说明使用 ``:doc:`` 链接，
   代码入口用仓库相对路径标示。
5. 在上级 ``toctree`` 登记新页面。已有章节链接被引用时，保留原页面文件名，
   将细节拆到子页并在原地址提供导航。

文档用真实源码和测试核对。界面操作以当前控件命名为准，变更的截图用公开样例。
正式指南中避免使用部署侧实际配置、用户材料和秘密。历史记录继续留在仓库 Markdown
目录，发布站只构建 RST 手册。

提交前执行 :doc:`documentation` 中的严格构建，检查侧栏、章节链接、窄屏和搜索。
