预发布交付
==========

前端与后端是两个独立发布单元。为同一批预发布分别记录两个不可变的 Git 提交或标签，
同时记录数据库迁移版本和兼容的契约锁。预发布可供试用，是否切入正式站点由维护者
依据验收结果决定。

本批预发布范围
--------------

- 公开站点提供文章、说说、页面、术语、归档和站内搜索，以及 Sitemap、RSS 和分享元数据。
- 后台提供内容编辑、版本恢复、页面模板、媒体、评论和多语言维护。
  管理员也可配置账号访问、通知、插件和主题。
- 运行能力涵盖前端节点公开快照、后端查询缓存、任务状态和站点维护。
  原生数据导入前先做预检。可选的 AI 写作支持多个服务商及逐次选择。

发布前核对
----------

1. **配对版本。** 前端 ``contracts.lock.json`` 固定了后端契约来源提交和 SHA256。
   从干净检出恢复全部契约，再执行前端完整检查及生产构建。若后端源文件无法公开读取，
   为构建提供有读取权限且含锁定提交的后端检出，或先提供可校验的正式契约产物。
2. **验证数据库。** 在空库验证初始化，在预发布的独立数据库验证从上一版本升级。
   当前后端迁移头为 ``0065_ai_writing_providers``。本次迁移将原单服务商配置
   保留为默认项。通过后端就绪接口核对运行版本，运行隔离数据库和多进程测试。
3. **验证部署链路。** 保持 API、Worker、Scheduler、前端和接收器版本匹配。
   核对登录、协同编辑、保存与发布、撤回、媒体、站点设置和节点回执。
   核对 Sitemap、RSS、草稿访问及可选邮件或 AI 配置的真实反馈。
4. **验证恢复。** 在隔离环境用备份恢复 PostgreSQL、媒体与主密钥，
   检查节点绑定和公开快照重新投递。回滚按照上一版本支持的数据库状态执行。
   例如，若已配置多家 AI 服务商，迁移会拒绝会丢失该配置的降级。
5. **检查公开范围。** 检查发布附件、文档和二进制仅包含可分发内容，
   核对项目及附带资源的授权。实例配置、用户数据、媒体上传、备份和密钥保存在部署侧。

交付记录
--------

分别建立前端和后端的 GitHub Release，选择 **Set as a pre-release**，在说明中填写
配套项目的 Release 或提交链接以及验证状态。建议使用一致的预发布标识来关联两个仓库，
项目包版本和接口契约版本继续独立管理。

.. code-block:: text

   预发布标识
   前端标签或提交
   后端标签或提交
   后端数据库迁移头
   契约锁与兼容范围
   变更范围、已知限制与验证结果
   升级步骤、回滚方式、验证环境

已知发布限制
------------

- 后端完整 ``mypy`` 仍报告部分测试类型问题；应用包 ``mypy app`` 已通过。
- 后端 OpenAPI 全局错误封装的回归检查发现部分接口缺少 ``404`` 响应声明。
- GitHub 上的前端软件 CI 需要能取到后端锁定提交中的契约。现有本地构建能从同级后端
  检出读取。远程构建须另行核验其读取条件。
- 当前仓库没有项目级许可证文件。若拟作为开源项目分发，先由维护者确认源码和随附
  资源的授权及许可文本。
