通知、邮件与模板
================

以下用「评论待审核」演示。给审核人员添加站内通知和邮件规则，修改邮件模板，再用一条测试评论核对投递结果。

配置发信与接收规则
------------------

1. 打开「通知与消息 → 通知平台」，在「邮件发信配置」选择「添加发信配置」。
2. 填写 SMTP 服务器、端口、加密方式和发件邮箱。服务商要求登录时，填入其提供的账号及密码或授权码。
   启用这套配置，再点「保存发信配置」。
3. 在该配置的「测试发件」区输入自己能收信的测试邮箱，点「发送测试邮件」。等待结果，再检查测试收件箱。
   测试发件使用当前选中的已保存配置。

**添加接收规则**

.. figure:: /_static/screenshots/notification-policy.webp
   :width: 100%
   :figclass: annotated-shot
   :alt: 后台通知策略的评论待审核卡片。①添加接收规则，②选择通知平台。

   在「评论待审核」事件卡片管理该事件的接收规则。

1. 打开「通知与消息 → 通知策略」。找到「评论待审核」，点图中所示的「添加接收规则」①，也可以修改已有规则。
2. 将「接收人类型」选为「拥有权限的成员」，接收人选「审核与回复评论」，「通知平台」②选「站内通知」。
   如果只需通知测试账号，可以选「指定用户」。
3. 如还要发邮件，另加一条规则，将「通知平台」选为「邮件」，选择上一步准备好的发信配置。
   邮件接收账号需要有已验证的邮箱。
4. 确认需要的规则已启用，再点「保存策略」。

「注册成功」在用户自行注册后触发，「新增用户」在管理员创建账号后触发。两种通知都可选择接收人。

编辑和预览邮件模板
------------------

.. figure:: /_static/screenshots/notification-email-template.webp
   :width: 100%
   :figclass: annotated-shot
   :alt: 邮件通知模板。①编辑正文，②在安全预览中查看代入示例值后的邮件。

   左侧是编辑器，右侧是该模板的安全预览。两处控件在后台实际页面上纵向排列。

1. 打开「通知与消息 → 通知模板」，将「通知事件」选为「评论待审核」，选择「模板语言」和「邮件」页签。
2. 编辑「主题」与「正文」①。开启「启用 HTML」后，可以在「可视化」编辑排版，也可以切换到「HTML 源码」检查链接。
   要插入变量，先把光标放进主题或正文，再点击下方相应变量，例如 ``{{site.name}}`` 或 ``{{resource.title}}``。
3. 使用「安全预览」②核对主题、排版和按钮。右侧「变量填充」可临时替换示例值。
   审核链接变量是 ``{{comment.approve_url}}`` 和 ``{{comment.reject_url}}``。
   管理员从邮件打开链接后，在后台确认审核操作。站点公开地址、图标和帮助链接可在「邮件品牌」配置。
4. 点「保存模板」，确认显示「通知模板已保存」。已有自定义模板可通过「恢复默认」恢复为内置版本。

验证邮箱、注册与找回密码各有模板。编辑这些验证码邮件时，把 ``{{verification.code}}`` 保留在正文，
避开主题和 HTML 属性。其收件人为发起流程所验证的邮箱，发信配置可在对应通知策略中选择。

验证投递结果
------------

1. 在测试站点用读者身份提交一条会进入待审核队列的评论，再用接收规则对应的审核账号打开后台顶栏的通知。
2. 打开「通知与消息 → 投递记录」。用「通知平台」分别筛选「站内通知」和「邮件」，点「刷新记录」，
   按时间找到 ``comment.pending_review``，核对投递状态和模板语言。
3. 邮件标记为「已投递」表示 SMTP 服务已接受邮件，随后到测试收件箱检查主题、语言和审核链接。
   等待时间异常时，检查「运行与任务」中的 Scheduler 和 Worker。若为「投递失败」或「已抑制」，
   查看记录所列原因、规则和发信配置。若为「结果未知」，先核对邮件平台和收件箱，确认结果后再决定是否重试。

注册、验证邮箱和找回密码的验证码发送状态在各自的账号流程中查看。普通通知的投递记录显示最近 50 条逐接收人、逐平台的记录。
