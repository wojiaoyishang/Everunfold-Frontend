通知、邮件与模板
================

配置顺序
--------

1. 「通知平台」管理站内通知、邮件等投递渠道。维护邮件发信资料后先测试连接或投递，
   记录失败原因与投递状态。
2. 「通知策略」选择业务事件及接收规则。按事件配置接收对象和平台。
   注册成功、新增用户等事件适合配置通知维护者。账号验证码的某些事件只允许发送给执行目标。
3. 「通知模板」按事件、平台和语言维护主题、正文及展示形式。可从变量列表插入站点名称、图标、
   事件内容，或在支持的事件中插入审核链接。
4. 「投递记录」核对收件人策略的结果、失败原因及当前状态。
   邮件请求入队表示 Worker 将处理。实际送达以邮件服务器及收件结果核对。

维护认证邮件
------------

验证邮箱、注册和找回密码使用各自的事件。认证验证码留在正文中的验证码变量，
复查 HTML 可视化视图、源码视图和下方安全预览。主题、链接属性及样例数据按后台校验处理。
预览使用示例变量，实际邮件使用任务记录对应的收件人与配置。

评论邮件可加入「通过」「拒绝」的审核链接。管理员进入确认页后再提交审核。
请在邮件品牌中配置公开站点地址，使站内链接指向正确入口。

没有收到邮件时
--------------

1. 核对对应策略是否启用，账号事件当前选择了哪套发信配置。
2. 查看投递记录，确认等待、成功、失败或未知的状态。未知结果先检查收件箱和投递记录。
3. 确认 Worker、Scheduler 和 SMTP 连接可用。用测试账户重走流程，
   区分验证码请求已接受与邮件未能发送。
